# 1.1 public-links review — 2026-08-27

Independent adversarial review of the public-TTL-links + per-port-sharing code
(the part not covered by the pre-1.0.0 review). **No authorization hole** — a
link-holder is confined to exactly one {owner, project, port}, and the preview
host returns 401/404 (never the SPA or a 200) for anything that isn't a live
token. Verdict was REQUEST CHANGES on functional + hardening defects.

## Fixed (verified: go 8/8, integration 62/62, e2e 36/36, + live checks)

**Blocking**
- **B1** cold-attach redirect on a preview host doubled the `/link/<token>`
  prefix → 404. Now redirects to the stashed original path (`origPathKey`).
- **B2** `csrfGuard` 403'd every non-GET a previewed app made (sandbox →
  `Origin: null`) and capped its bodies at 1 MiB. Preview/link paths are now
  exempt from CSRF + the body cap (styrman only tunnels those bytes). Also: the
  `sandbox` CSP is applied ONLY to the same-origin `/p/` preview — the public
  link runs on its own token subdomain, so it isn't sandboxed and works fully.
- **B3** a failed revoke removed the link from memory but not disk → it
  resurrected on restart. `Delete` now rolls back on write failure.

**Should-fix**
- **S1** previewed-app `Set-Cookie` with a parent `Domain` (cookie tossing onto
  styrman hosts) — the `Domain` attribute is now stripped (host-only cookies).
- **S2** internal project UUID / run-state leaked in link error bodies → generic
  "preview is not available right now".
- **S3** no `Referrer-Policy` — the capability URL could leak via `Referer`. Now
  `Referrer-Policy: no-referrer` on all preview responses.
- **S4** unbounded link growth + prune-only-on-Create. Added a per-project cap
  (20, → 409) and pruning on `ListFor`.
- **S5** `links.Store` didn't fsync (unlike the other stores) → a power cut
  could resurrect a revoked link. Now atomic + durable (fsync temp, rename).
- **S6** `/api/health` was public on the `*.preview` wildcard (liveness oracle).
  A preview host with a non-token subdomain now 404s before the exemption.
- **S7** `/link/` skipped the ingress-token check → a project VM could reach it
  on :8080 and be proxied into another project (R12). It now still requires the
  ingress token when configured (verified live: 403 without, serves with).
- **S8** revocation didn't cascade — `deleteProject` now revokes the project's
  public links too.

**Nits fixed**: host lowercased/trailing-dot-trimmed in the rewrite; revoke logs
a token prefix not the full token; `ListFor` uses `sort.Slice`; the per-open-row
`listLinks` poll is hoisted to one project-wide poll in `PortsTab`.
