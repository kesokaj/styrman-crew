## Root cause

`.agents/docs/testing/styrman/integration.sh:137-138` asserts a previous-harness
absence including `~/.claude/settings.json`:
```
check "no previous-harness artifacts (shell gates, GEMINI.md, settings.json)" \
    "! docker exec ${CN} sh -c 'test -e ${GH}/.agents/bin || test -e ${GH}/.gemini/GEMINI.md || test -e ${GH}/.claude/settings.json'"
```
This assertion predates this range and was correct when written (the old
harness shipped no `settings.json` at all, ADR-062 D8). This range's harness
refresh to 4aa19be — carried in via `image/entrypoint.sh`'s changed lines and
the mirrored `image/harness/cmd/sh-agent/main.go`/`internal/harness/` —
implements ADR-072 (amending R5): `sh-agent install` now creates
`~/.claude/settings.json` with the `"attribution": {"commit": "", "pr": ""}`
key when the file is absent, confirmed directly above. `integration.sh` was
not updated in this range (`git diff v1.33.0..9dab61d --stat -- .agents/docs/testing/styrman/integration.sh`
shows no change to it) to reflect the new expected file, so the check now
fails against intended, reviewed behavior (per the harness-refresh commit's
own security review, cited in the 9dab61d ancestry) rather than against a
regression in the harness itself. This is a genuine coverage gap in the
integration suite for this release, not a code defect — reported, not
patched.
