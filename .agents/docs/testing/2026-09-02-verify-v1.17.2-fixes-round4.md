# Verification — v1.17.2 fix set, ROUND 4 (FINAL, uncommitted working tree)   (2026-09-02)

## Status: PASS

Scope: the same uncommitted working tree carried through rounds 1-3
(round 3: `.agents/docs/testing/2026-09-02-verify-v1.17.2-fixes-round3.md`, FAIL — the sole
gap was uncovered upload-eviction client logic), with four further changes made since round 3:

1. `internal/httpapi/explorer.go` `uploadFile` — `saved` is now initialised `[]string{}` (never
   nil) and reported on **every** exit path via a new local `uploadErr` closure (`writeErr`'s
   JSON shape plus `"saved"`), so a mid-stream failure tells the client exactly which earlier
   parts landed. New Go test `TestUploadReportsSavedPartsOnFailure`
   (`internal/httpapi/explorer_files_test.go`): a two-part upload where the first part
   (`a.txt`) saves and the second (`.ssh`, a managed name) is refused asserts a 400 with
   `saved:["a.txt"]`, confirms `a.txt` really landed on disk via a follow-up `GET`, and a
   separate fully-successful upload asserts a non-null `saved:["b.txt"]`.
2. `web/src/lib/api.ts` `uploadFiles` no longer throws on failure — it returns
   `{saved, error?: ApiError}`, always populating `saved` from the server body.
   `web/src/components/FileExplorer.tsx`'s `upload()` evicts panes
   (`evictFromPanes`, chip kept) for exactly the server-reported `saved` names joined under the
   current dir, then calls `load()`, then re-throws `r.error` if the server reported one — the
   old "evict by the locally-known dropped names" heuristic on the failure branch is gone
   entirely (it could evict files the server never touched).
3. New Playwright check `"upload over the open file evicts its pane, keeps its chip"` in
   `web/e2e/run.mjs`: uploads a file (`two.txt`) that collides with the file open in the pane via
   `setInputFiles` on the hidden `input[type=file]`, asserts the pane shows "No file open", the
   Recent chip for `two.txt` is still present, and reopening it shows the uploaded content.
4. Comment-only changes (no behavior change): `web/src/lib/editorPane.ts`'s `canonicalPath`
   docstring, the updater's EXIT-trap ownership note, `web/e2e/run.mjs`'s cap-check ordering
   note.
