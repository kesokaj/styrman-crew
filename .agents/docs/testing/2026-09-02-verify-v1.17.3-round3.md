## Scope

Re-verification of the delta since round 2 (`.agents/docs/testing/2026-09-02-verify-v1.17.3-round2.md`,
PASS) in `deploy/update/styrman-update` and `deploy/vulncheck.sh`, working tree still uncommitted on
top of `c83ddba` (v1.17.2):

1. **(security round-2 MEDIUM)** `self_install` no longer copies from the mutable worktree.
   `atomic_install(mode, git-path, dst)` writes `git show "HEAD:${gitpath}"` to `"${dst}.new.$$"`,
   then `chmod`/`chown root:root`, `mv -fT` (rename, not the swallow-into-directory `mv -f`
   round-2 flagged). A new `differs(git-path, dst)` gates each install on `! git show ... | cmp -s -
   dst`. Presence is probed with `git cat-file -e "HEAD:${src}/${f}"`. All three run through the
   script's own `git()` wrapper (`git() { command git -c safe.directory="${DEPLOY_DIR}"
   "${GIT_CRED_ARGS[@]}" "$@"; }`, `:198`), which relies on the script having already `cd
   "${DEPLOY_DIR}"` at `:145` (no `-C` in the wrapper — it is cwd-relative).
2. **(review round-2 findings)** `mv -fT` turns a directory-at-target from "swallowed, false
   success" into a real install failure; the orphan `.new.*` sweep for all three target names moved
   to the top of `self_install` (runs once, ahead of the presence probe and any `differs`/
   `atomic_install` call, not per-file inside `atomic_install` anymore); the "self-installed" log
   line is gated on `failed = 0`; `deploy/vulncheck.sh`'s exit is now worst-wins
   (`0` never overrides, `3` only sets `rc` from `0`, anything else always wins), `r` reset to `0`
   each loop iteration; the header comment re-wrapped.

No Go, web, or `web/dist` change in this diff.

All 7 scenarios (a–g) PASS exactly as specified. Case (c) is the load-bearing new assertion this
round: editing the scratch repo's **worktree** file directly, without committing, produces **zero**

release-content update, not tampering).
