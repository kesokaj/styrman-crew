## Why it stopped

**Sixteen findings across three review rounds, and in each round the previous
round's fixes introduced the next round's worst defect.** Round 1's
skip-the-reconcile fix created round 3's high finding; round 2's PATH fix
created round 3's other high finding. `AGENTS.md` caps review loops at three
for this exact situation, and the pattern — not the count — is the reason to
hand off rather than patch again.

The gate report has every finding with severity, confidence, file:line and
fix direction: `reviews/2026-09-08-preflight-v2.0.0.md`. Six are open.

## Open — start here

1. **[high] A failed revocation serves the SSH key to a project that still
   has LAN reach.** `Exposed` must consult `st.Errors[uuid]`, and the script
   needs a distinct status key for "the reconcile did not run" (a global
   `error=all:` line currently lands in `Warnings`, indistinguishable from
   anything else). This is the one that actually matters.
2. **[high] The sshd gate aborts silently as non-root** — `set -e` kills the
   script at the `pw="$(sshd -T …)"` assignment, so its own error branch is
   unreachable.
3. **[medium] The Match-block refusal does not refuse** — case-sensitive grep
   against case-insensitive keywords, and a probe address in no real Docker
   network. Demonstrated on OpenSSH_10.0p2.
4. **[medium] `WANT_COUNT` does not dedup** where `DESIRED` does — one
   repeated CIDR pins every project into a permanent error state.
5. **[medium] The R12 gate is bypassable** by a hand-edited conf or a
   re-install over an existing `LAN_ALLOW_HOST=1`; it should check the
   effective resulting state, not the flag.
6. **[low] The ordering test has blind spots** — `function name {`, indented
   or mixed-case definitions, and calls inside `$(…)`.

Also still open from before the gate: the live published-port proof needs
`LAN_ALLOW_PUBLISHED_PORTS=1` on a real host, and **no LAN allowance has ever
been applied by the v4 script on real hardware**.

## Corrections this session must carry forward

- **A claim in commit `dc5bad4`'s message is false.** It says
  "install.sh --dry-run reaches the end on both opt-in paths". That was
  verified only under `sudo -n`, where sshd is on PATH; as non-root the same
  command exits 1 with empty output. The commit is pushed and cannot be
  amended — the correction is in the gate report. The general lesson: a claim
  verified along one path was written as if it held for all of them.
- **The brokered SSH key does not open this host.** ADR-065 part (5) and R12
  both reasoned that it did. Neither `/home/kesokaj/.ssh/authorized_keys` nor
  `/root/.ssh/authorized_keys` exists. What `LAN_ALLOW_HOST=1` actually opens
  is sshd with `passwordauthentication yes` plus `%sudo NOPASSWD:ALL`.
  ADR-066 records this; the broker narrowing is justified by the transitive
  LAN path, not by host root.
- **`TODO.md` item (b)'s recorded rule shape was impossible.** iptables
  accepts one `--out-interface` per rule, so `! -o sdb-+ ! -o <ingress br>`
  can never be written. Replaced by a positive destination allowlist.
