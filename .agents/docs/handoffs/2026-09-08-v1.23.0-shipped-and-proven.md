## Key Decisions

- Root decides what "local network" means from a root-owned conf; the non-root server may only say on/off per project via a name-only marker file plus a spool kick, and reads root's status back. Rejected: a privileged helper container, a root daemon, Docker-native options, `PathModified` triggers (events measured lost while the oneshot runs).
- One head-of-chain RETURN per (project, prefix), pinned `-i bridge -o uplink -s bridge-subnet -d cidr`. RETURN not ACCEPT, so Docker's cross-bridge DROP still runs. Deletions by full spec, never by rule number.
- Fail-closed throughout: base rules first; an unreadable status with a record ON reads "cannot confirm", never "off"; an empty `STYRMAN_FIREWALL_DIR` removes every marker.
- `STYRMAN_FIREWALL_DIR` keeps a production default although BOTH release reviewers wanted it removed. Rationale in the field's doc comment and the gate report: ADR-052's no-default rule is about root-run programs, and removing it would let a lost compose env silently tear down live allowances.
- Two release findings rebutted rather than changed; one pre-existing accepted. All reasoning is in the gate report, not just asserted.
