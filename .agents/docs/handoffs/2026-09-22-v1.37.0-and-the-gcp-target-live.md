- **BUG-074 (open, diagnosed, not fixed):** the first sign-in in the operator's normal browser looped with `ERR_TOO_MANY_REDIRECTS`; incognito worked. Both hosts name the portal's session cookie `AUTHP_ACCESS_TOKEN` and scope it to their own `BASE_DOMAIN`; the NUC's scope `styrman.xyz` is a parent of `crew.gcp.styrman.xyz`, so a live production session shadows the new host's and the app bounces to the portal forever. Nothing is wrong with the GCP host's DNS, certificate, OAuth client or config — all four were verified. The fix (unique cookie name per deployment, via caddy-security's `cookie_name_prefix`) touches `deploy/caddy/ingress/{config.go,generator.go}` and reaches a host only through a release; it is NOT done. Until then: one styrman host per browser profile, or a private window for the second.
- **Operator decision on BUG-074 (2026-09-22):** "it worked in incognito. That is enough for me. I will not use the local and gcp with the same gmail account." The bug stays open and is not to be fixed unasked — see its Operator decision section, including the note that the collision follows the browser profile, not the Google account.
