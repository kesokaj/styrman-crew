## Key Decisions

- **`validBranchName` gates argv danger only** (leading `-`, control bytes, space, invalid UTF-8, >255 bytes) and DEFERS ref-format validity to git. A deliberate deviation from the plan, which said to use `check-ref-format`: reimplementing git's rules in Go means drifting from a spec we do not own. Pinned by `TestValidBranchNameDefersRefFormatToGit`.
- **Reads answer 200 with `state`/`repo` flags; mutations answer 4xx.** Matches `gitStatus`/`gitPush`. Documented so nobody "unifies" it.
- **`git fetch` omits `--prune` on purpose** — a guest-writable refspec makes a pruning fetch delete LOCAL branches — and keeps `--all`, which is what keeps guest-chosen remote names out of argv.
- **`checkout --end-of-options <name> --`** on the switch path. A TRAILING `--` terminates nothing: git parses left to right. The create path (`-b`) was already immune.
- **`git show --format= --patch`** for a commit diff, not `<hash>~1..<hash>`, which fails on a ROOT commit. Verified directly, not assumed.
- **The seam is narrow on purpose** — two methods; the orchestrator's other ~15 stay on the concrete `orch` field. It is a seam for the exec path, not an abstraction over the orchestrator.
- Rejected: the global UI density rework and `git commit --amend` (operator cut both).
