# Security review — v1.39.0-4dd51bf   (2026-10-02)

## Status: COMPLETE

## Verdict: FINDINGS (two low; no medium or high)

**Worst problem: a terminal pane can replay old keystrokes on wake.** The problem is in `web/src/components/TerminalPane.tsx` and arrived with 4460e1b (BUG-085, ADR-079).
- **What happens.** Keystrokes typed while a reconnect is pending go into the pane's outbox. When the 8 retries run out (about 90 s), the pane shows "Disconnected", but the outbox is never cleared. The new wake path then reconnects that same closure and flushes the old queue into the tmux session. The wake can come minutes or hours later, and the `online` event fires it even in a hidden tab.
- **Why low.** The input is the user's own and stays in their own session; nothing crosses to another user. It is still an integrity hazard: a queued `y` + Enter can land in whatever prompt is in front at the time, an agent CLI's permission prompt included.
- **Why it is new.** At v1.39.0 a "Disconnected" pane came back only through its Reconnect button. That button bumps the epoch, which re-runs the effect with an empty outbox, so the queue was dropped.

**The second finding is a carried one.** It is the pre-existing js-yaml advisory in the web build chain, which is outside the range.

**The fixes from earlier today are correct and complete** (details under Checked):
- Round 2 asked for a supersession marker on the ADR-077 heading, and for the agy check to cover the binary as well as the directory. Both are done.
- Round 1's `/opt/agy` 0777 finding (BUG-086, ADR-080) and the call-site test for "a ping is not activity" still hold on this read.
- The fixes introduced no new defect.

**The diff has no secret, no new injection surface, no authz change and no crypto.** `web/dist/client` is the build of the source beside it, as far as security-relevant content goes.

**For the gate, two things:**
1. **Production will not pick this release up by itself.** BUG-084 is open: the production NUC's auto-updater has been failing on a rejected `/etc/styrman/gh-token` since before v1.39.0, and the host runs 1.38.0. This release, ADR-080's hardening included, reaches the NUC only after the operator installs a fresh token.
2. **The working tree moved during this review.** Uncommitted changes outside the reviewed range appeared, among them `deploy/caddy/ingress/watcher.go` (+42), the security-critical ingress module (list under Not examined). This verdict covers `4dd51bf` only. A release commit that carries those changes needs its own security review.

## Findings
- **[low / confidence: high]** `web/src/components/TerminalPane.tsx:411-416` (the outbox push), with `:318-321`, `:341-351`, the `onWake` handler below them and `:262`: queued keystrokes survive "Disconnected" and are replayed on a later wake.
  - **The path:**
    - At `:411-416`, while the socket is not OPEN and the pane is not closed for good, `term.onData` pushes each chunk into `outbox`. There can be up to 256 chunks, and a paste is one chunk.
    - When the retries are exhausted, `:318-321` sets `disconnected`, `closedForGood = true` and `resumable = "wake"`, and leaves the outbox alone.
    - A later `visibilitychange` to visible, or an `online` event, reaches `onWake`, which calls `reconnectNow`. `reconnectNow` (`:341-351`) clears `closedForGood` and calls `connect()`.
    - On open, `connect()` runs `flushOutbox()` (`:262`), which sends the stale bytes.
    - The only place the outbox is ever emptied is `flushOutbox`'s `splice` (`:403`).
  - **Exposure:**
    - The bytes are delivered out of context, into whatever is in the foreground at reconnect time.
    - Through `online`, a hidden tab does this while it takes the terminal (close 4001) from the tab the user is typing in.
    - Same user and same session, so no cross-user effect.
  - **The code contradicts its own comment.** The comment at `:412-415` states the rule this path breaks: "a pane that is closed for good" must not replay. The reclaim path honours that rule only because typing is refused while the pane is closed. Nothing drops what was queued before it closed.
  - **Not covered by tests.** The three BUG-085 e2e checks and `termLiveness.test.ts` never type during a retry window.
  - **Remediation:**
    - Empty the queue when the pane closes for good: `outbox.length = 0` in the `:318-321` branch. The alternative is the start of `reconnectNow` when it leaves a closed-for-good state.
    - Add a check that fails without the fix. Example: type a marker while the server refuses the socket, let the pane reach "Disconnected", fire a wake, and assert the marker never echoes. A pure queue-policy module tested like `termLiveness.ts` would work too.
- **[low / confidence: high]** Carried, pre-existing, outside the range: GHSA-2883-xcg3-v3hh, a CPU denial of service in `js-yaml` 4.0.0-4.3.1.
  - **Where:** it enters the web build chain via `@tanstack/react-start -> @tanstack/start-plugin-core -> xmlbuilder2`.
  - **Still present:** neither `web/package.json` nor `web/package-lock.json` changes in the range, so the locked version is the one rounds 1 and 2 reported.
  - **Exposure:** the package is a build tool only.
  - **Remediation:** a separate dependency change (`npm audit fix`), already queued in the handoff's Next Steps.
  - **Not re-run:** `npm audit` was not run this round (see Checked).
