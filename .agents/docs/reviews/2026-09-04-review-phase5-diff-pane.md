## Verdict: APPROVE WITH NITS

Nothing here is broken at the level of the two flagged Go branches, the `PaneState`/`set()` guard, or the terminal visibility class — all three trace correctly end to end and `go build`/`go test`/`tsc -b` are clean. The one real problem is in `DiffPane.tsx`'s fetch effect: its stale-response guard only protects the automatic (effect-driven) fetch, not the identical fetch launched by the "Refresh diff" button, so a manual refresh in flight when the user switches files can silently leave the pane showing the wrong file's diff under the new file's header — for a feature whose whole job is showing the right diff, that is worth fixing before it ships.

## Findings

- **[medium / confidence: high]** `web/src/components/DiffPane.tsx:40-69,96` — the stale-response guard is bypassed by the manual refresh path. `load()` returns a closure (`() => { stale = true }`) that is only ever registered with React when `load()` is invoked *by the effect* (`useEffect(() => load(), [load])` — React stores and later calls that return value as the cleanup). The "Refresh diff" button does `onClick={load}`; that is a second, independent invocation of `load()` whose returned cleanup is discarded by the DOM event handler, so its own `stale` flag is never set to `true` by anyone.
  - Concretely: click Refresh on file A, then before it resolves click file B in the Git panel. The effect for the *new* target correctly cancels the effect-driven fetch for A (if any was still pending), but the manual refresh fetch for A has no way to be cancelled. When it lands, `setText(d.diff)` runs unconditionally and overwrites whatever B's fetch had just written — the pane is left showing A's diff under B's header, with no error and no way to tell without re-clicking B.
  - A related, always-reproducible symptom from the same root cause: `text` is never cleared synchronously when `key` changes (only `loading`/`error` are), so on every target switch the pane briefly renders the *previous* target's diff content under the *new* target's title until the new fetch resolves. The e2e check added in this diff ("clicking a SECOND file swaps the diff") only asserts the final, converged state via `mainContains`, so it does not catch either symptom.
  - Fix: give both the effect and the manual refresh a single source of truth for "is this still the latest request" — e.g. a ref holding the current request's key/counter (or an `AbortController` per `key`, per the `typescript` skill's async-and-errors checklist), and reset/blank `text` synchronously when `key` changes rather than only on fetch resolution.
