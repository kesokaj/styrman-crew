## Verdict: APPROVE WITH NITS

Nothing in this range is broken, and nothing in it blocks the tag. `go vet ./...`,
`go test ./internal/... ./cmd/...`, the ingress module's own `go vet`/`go test`, and
`npm test` (17 tests, 3 files) all pass on `d24fe40`. The worst problem is not a
regression but a **residual of the very class this release fixes**: the BUG-002/003
work confines *reads*, *opens*, and the *Docker bind source* below a guest-writable
home, but three raw `os.MkdirAll` **writes** on the same paths still follow a
guest-plantable symlink, giving a project guest a root-owned "create an empty
directory anywhere on the host" primitive (`orchestrator.go:270,284`,
`server.go:723`). Second: `internal/history` still opens the project home with
`os.OpenRoot(homeDir)` — the exact call `.agents/rules/guest-writable-paths.md`
forbids — because it does not go through `internal/files`, so `files.Trust` does not
cover it. Third, and the reason to act before the release run rather than after: a
`set -e` abort in the new `integration.sh` boot-latency block exits **0**, so a
truncated suite reports green.

The BUG-001 fix itself is sound end to end: `redirect: "manual"` is placed after the
`...init` spread so no caller can unset it, `res.type === "opaqueredirect"` replaces
the `res.redirected && res.url.includes("/oauth2/")` test that could never fire on a
cross-origin chain (no stale copies of the old predicate remain anywhere in `web/src`),
`uploadFiles` repeats both guards, the counter is shape-validated and a corrupt record
is overwritten rather than left to disable the cap, and the deferred clear is guarded
by `reAuthTriggered` so a page that also takes a same-origin 3xx cannot reset the cap
on every load. The session-lifetime change is a one-line, tested, correctly-named
caddy-security directive. The Phase 1 gates are real gates, not decoration: the
`SHA256SUMS` + unlisted-file + symlink triple check, the toolchain-pin equality
between the two Dockerfiles, and the runtime-image harness count all behave as
documented (verified by hand: list matches, pins both `golang:1.25.13-trixie`,
28 skills / 7 subagents consistent between `find`, `sh-agent list`'s inventory
loader, and `integration.sh`'s assertion).

## Findings

- **[medium / confidence: medium]** `internal/orchestrator/orchestrator.go:284` (also
  `:270` and `internal/httpapi/server.go:723`) — the BUG-003 guard proves `p` and
  `p/<uuid>` are not symlinks before handing the home to Docker, but the very next
  statements write *through* paths below that home with raw `os.MkdirAll`:
  `filepath.Join(phome, "projects", opts.Dir)` sits under `phome`, which is the
  guest's writable virtiofs mount. A guest that unmounts `~/projects/<dir>` inside its
  own microVM and replaces `~/projects` with a symlink (say to `/etc`, or to another
  tenant's home) leaves that link on the host; the next create-path boot — reachable
  without any user action via the stopped-container image-upgrade recreate at
  `orchestrator.go:206-219` — makes the server (root in production) create a directory
  at the attacker-chosen host path. `orchestrator.go:270` has the same shape one step
  earlier: `os.MkdirAll(phome)` runs *before* its `realBelow` re-check, so the mkdir
  has already followed a symlinked `p` by the time the boot is (correctly) refused;
  `server.go:723` is the same call on the create-project request path. Impact is
  bounded — `mkdir` never overwrites and never discloses, and the *mount* is refused —
  which is why this is medium and not high, but it is a tenant-boundary crossing that
  survives the fix. **Resolve:** create these three through an `os.Root` opened at
  `cfg.UserHome(user)` (`root.Mkdir` on each component, mirroring `pruneTranscripts`'s
  new `tenant.OpenRoot` pattern) instead of `os.MkdirAll` on a joined string, or
  extend `realBelow` to cover `phome/projects/<dir>` *before* the mkdir. Pre-existing
  code, not introduced by this range.

- **[medium / confidence: medium]** `internal/history/history.go:39`, `:125`, `:207` —
  all three entry points do `os.OpenRoot(homeDir)` where `homeDir` is
  `cfg.ProjectHome(...)` (`internal/httpapi/explorer.go:356,382,414`). That is
  literally the call BUG-002's prevention rule bans: "never `os.OpenRoot(path)` on a
  path below a mounted home". The new `files.Trust` confinement lives in
  `internal/files` and `history` does not use it, so `List`/`Search`/`Read` still
  follow a symlink planted at `p/<uuid>` and operate on whatever it points at.
  Exploitability is narrow — every read is `<target>/.styrman/logs/<own-project-uuid>/
  <id>.log`, and the attacker cannot make another tenant's tree contain a directory
  named after their own project UUID — so this is medium, not high, and I did not find
  a concrete cross-tenant read. **Resolve:** route `history` through `internal/files`
  (it already has `ListNames`/`ReadRaw`/`Exists`), or export the `openRoot` behaviour
  from `internal/files` and call it here. Pre-existing code, not introduced by this
  range; worth an entry under BUG-002's residuals either way.

- **[medium / confidence: high]** `.agents/docs/testing/styrman/integration.sh:104` —
  `READY_AT="$(docker logs -t "${CN}" 2>&1 | grep -m1 'project .* ready' | cut -d' ' -f1)"`
  runs under `set -euo pipefail`. When the ready line is absent (the exact case the
  block exists to catch), `grep` exits 1, `pipefail` propagates it to the assignment,
  and `set -e` aborts the whole script — mid-suite, roughly a third of the way in. The
  `EXIT` trap then prints `passed=N failed=0` and exits `0`, because it keys off the
  `FAIL` counter only: **a truncated run reports success**. Confirmed by reproducing
  the shell semantics directly. The same abort path exists for a `date -d` failure on
  a malformed timestamp in the `BOOT_GAP` line (`:105-106`). As a side effect the
  `${READY_AT:-1970-01-01T00:00:00Z}` fallback is unreachable dead code. **Resolve:**
  `READY_AT="$( … || true)"` (and likewise for the `awk`/`date` line), and make
  `cleanup` fail when `PASS+FAIL+SKIP` is below the README's expected check count so
  an abort can never read as green. This matters now because `integration.sh` is one
  of the release gates whose green result is the evidence for this tag.

- **[low / confidence: high]** `internal/httpapi/server.go:126` — `files.Trust(...)` is
  registered as a side effect of `httpapi.New`, but `cmd/styrman/main.go:66`
  (`migrateWorkspaces` → `files.ContainedPath` at `main.go:228`) calls into
  `internal/files` *before* `New` runs at `main.go:97`, so that call silently gets the
  unconfined `os.OpenRoot` path. No hole today — its root is the base home
  `HomesDir/<u>`, whose components are all server-controlled, so confined and
  unconfined resolve identically — but the ordering makes the new invariant depend on
  construction order rather than on startup. **Resolve:** call `files.Trust(cfg.HomesDir,
  filepath.Join(cfg.StateDir, "projects"))` in `main()` immediately after the config is
  loaded, and keep (or drop) the call in `New` as a harmless idempotent repeat.

- **[low / confidence: medium]** `image/entrypoint.sh:144-146` — two sequential
  `timeout 20` calls sit on the pre-`/run/styrman/ready` path, so the worst case adds
  40 s to boot. The comment says the cap "must stay inside R1's 15 s soft budget as far
  as possible", but 2 × 20 s cannot: a stall in either step breaches the stated 15 s
  hard limit for "new project → agent prompt visible" (REQUIREMENTS.md, Latency SLA)
  while still satisfying the server's 90 s ready wait. The new
  `integration.sh` boot-latency check would catch it as a failure rather than prevent
  it. **Resolve:** give the pair one shared budget (e.g. `timeout 10` each, or a single
  `timeout 12` around both), which still leaves ~100× headroom over the measured
  sub-second runtime.

- **[low / confidence: high]** `web/src/lib/api.ts:322` — with `redirect: "manual"`,
  *any* 3xx on an `/api/*` call becomes `opaqueredirect` and is therefore reported as
  "session expired", including a same-origin `http.ServeMux` path-cleaning 301. The
  server issues no 3xx on `/api/*` today (the only two, `server.go:479` and
  `proxy.go:86`, are on preview/link paths, which the SPA never fetches through
  `request()`), and the reload cap bounds the consequence at two reloads plus an error
  toast, so this is a deliberate and correctly-bounded trade — recorded here only
  because the failure mode is a self-inflicted double reload if an `/api` route ever
  gains a redirect. The behaviour is covered by `api.session.test.ts`'s second case.

No finding blocks the tag. Finding 3 should be fixed before the `integration.sh` run
is treated as release evidence; findings 1 and 2 are pre-existing residuals of the
BUG-002/003 class and belong in `TODO.md`/the bug records alongside the un-nesting
proposal, not in this release.

## Criteria

1. **Dead code — pass (one note).** The old expiry predicate (`res.redirected &&
   res.url.includes("/oauth2/")`) is gone from both call sites with no copies left in
   `web/src`; `internal/files`' old `openRoot` comment is replaced, not orphaned; the
   `p/<uuid>` raw-path open in `pruneTranscripts` is fully replaced by the tenant root.
   The only dead code found is the unreachable `${READY_AT:-…}` fallback in
   `integration.sh` (folded into finding 3). Delete it with the fix.
2. **Flow tracing — pass (two gaps, findings 1 and 2).** Traced: `request()`/`uploadFiles`
   → `reAuthOnce` → `sessionStorage` → toast/reload, including the cross-reload counter
   and the deferred clear, with the module-state reset modelled correctly in the tests;
   `httpapi.New` → `files.Trust` → `openRoot` → all 14 `files.*` entry points (every one
   goes through `openRoot`; no direct `os.*`-by-name remains in `files.go`);
   `EnsureRunning` → `projectHomeIsReal`/`realBelow` on every branch, including the
   `ContainerStart` at `:234`/`:239` and the create path, with the inner
   `if err := …` correctly *not* shadowing the outer `err` the switch reads; the setup-VM
   start at `:576` mounts the base home, which is not guest-replaceable, so it needs no
   guard; `pruneTranscripts` → `tenant.OpenRoot` → `fs.WalkDir` → `fs.Stat(home.FS(), rel)`
   → `home.Remove(rel)`, with `tenant.Close()`/`home.Close()` on every path including the
   `continue`s. `ListNames`'s new `err != nil && len(des) == 0` is correct against Go's
   `ReadDir(n>0)` contract (an empty directory returns `io.EOF`; a short directory returns
   its entries with a nil error). The two gaps found are the raw `os.MkdirAll` writes and
   `internal/history`'s own `os.OpenRoot`.
3. **Standards conformance — pass.** Go: errors wrapped with `%w` and context throughout
   the new code, no discarded errors, no new goroutines or contexts; `go vet` clean on
   both modules; `gofmt -l internal/ cmd/` clean. TypeScript: no floating promises, the
   `catch {}` blocks are narrow and commented with why, the `unknown`-then-narrow shape in
   the counter parse is exactly the `typescript` skill's idiom. Bash: `set -euo pipefail`
   and consistent quoting in `verify-commit.sh`; the one `set -e` interaction that bites
   is finding 3.
4. **Directory layout — pass.** `trust_test.go` beside `files.go`, `realbelow_test.go`
   beside `orchestrator.go`, `prune_test.go` beside `main.go` in `package main`,
   `api.session.test.ts` beside `api.ts`; `image/.dockerignore` at the root of the context
   it applies to, with a comment saying why the repo-root one does not; the harness builder
   stage lives in `image/Dockerfile` next to what it feeds. Nothing surprising.
5. **Simplicity (DIY-except-security) — pass.** No new dependency in any of the three
   modules (`image/harness/go.mod` has zero requires, and `GOPROXY=off` in the builder
   stage makes that a build failure rather than a silent fetch if it ever changes);
   `realBelow` is 15 lines of `filepath`/`os.Lstat`; the frontend fix is two property
   changes plus a shape check. No hand-rolled auth, crypto, hashing, session, or JWT code
   anywhere in the range — the session-lifetime change *configures* caddy-security rather
   than replacing it, which is the correct side of the inversion, and the styrman server
   still re-checks the userstore per request so the 900 s → 28800 s change does not become
   the revocation control.
6. **Decoupling — pass (one note).** `realBelow`/`projectHomeIsReal` are unexported and
   local to `orchestrator`; the `files.Trust` seam is a small, idempotent registration
   consumed only by `openRoot`. The one wrinkle is that `Trust` is package-global mutable
   state initialised from `httpapi.New` (finding 4) — it works, but it couples "the files
   package is safe" to "the HTTP server has been constructed", which is a seam two
   engineers could trip over. Registering it in `main()` decouples it.
