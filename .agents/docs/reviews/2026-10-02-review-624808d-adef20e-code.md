## Findings

- **[low / confidence: medium]** `deploy/update/styrman-update:147` (`[[ "${STATUS_FILE}" =~ ^/[A-Za-z0-9._/-]+$ ]]`), together with `.agents/docs/specs/styrman/deploy.md` / `versioning.md` ("plain characters only, `A-Z a-z 0-9 . _ / -`; any other character … is refused") and the WARN text at `:148`.
  - **What is wrong:** bash compiles `=~` with the current locale, so the bracket ranges depend on it.
  - **Probe** (bare, under `set -euo pipefail`):
    - `LC_ALL=en_US.UTF-8`: `/x/é` is **accepted**.
    - `C` and `C.UTF-8`: `/x/é` is refused.
    - Newline, tab and space are refused in all three locales.
    - `/etc/styrman/status/updater.json` is accepted in all three.
  - The script does not pin `LC_ALL`/`LANG` (grep of `deploy/update/` finds none), and systemd passes `/etc/locale.conf`'s `LANG` to services.
  - **Not a security hole:** UTF-8 multibyte sequences contain no `/` or newline bytes, so the `read` walk is not cut short. The newline fix (security round-3 finding 2) is complete.
  - **What is broken:** the documented, logged guarantee is false under a common host locale. That breaks the describing-text rule.
  - **Fix:** `local LC_ALL=C` at the top of `write_status` before the test, or spell the class out without ranges. Add one hook case with a non-ASCII letter run under `LC_ALL=en_US.UTF-8` (when that locale is present), which must WARN.

- **[low / confidence: high]** `internal/config/styrman_update_status_test.go:95-114` (`trustedTempDir`).
  - **What is missing:** the new ancestor walk checks for symlinks and for `022` without sticky. It does not check the owner (root or the caller's uid), and `status_ancestors_ok` (`styrman-update:113-114`) refuses an ancestor that fails that test. The round-3 finding's own remedy named the owner check ("owner 0 or `os.Getuid()`").
  - **Failure mode, if `TMPDIR` sits below a directory owned by another uid, mode 0755:**
    - The helper passes it.
    - Every "written" case fails with the writer's generic `WARN: status not written` (the round-3 symptom), not the named Fatal.
    - Worse, `TestStyrmanUpdateStatusWriteRefusesAPathOutsideThePlainSet` (`:535-563`) then passes even with the regex deleted, because the owner test refuses first. That breaks the global rule that a test which sets up an unusual condition first proves the condition holds.
  - **Production is unaffected.**
  - **Fix:** add `info.Sys().(*syscall.Stat_t).Uid` ∈ {0, `os.Getuid()`} to the walk's condition and to its Fatal message.
