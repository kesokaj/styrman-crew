## Verdict: FINDINGS — three low, nothing blocking

Nothing high, nothing medium introduced. The range's one new privileged-context
behaviour — `image/entrypoint.sh` keeping `sh-agent install`'s stdout and
copying selected lines into the microVM boot log — is correctly bounded: the
pattern is anchored (`^settings:` / `^note: ` matched on the hint's own
wording), non-printable bytes are stripped (`tr -cd '[:print:]\n'`), lines are
truncated at 200 columns, and the shell runs `set -uo pipefail` **without**
`-e`, so a no-match `grep` cannot abort a boot. The only variable text the
filter admits is a path built from `/home/${STYRMAN_USER}`, and that username is
constrained to `^[a-z][a-z0-9_-]{0,31}$` at both write
(`internal/httpapi/profile.go:77`) and load (`:53`), so no newline, quote or
control byte reaches a log line through it. The worst residual is that the boot
log is a diagnostic a guest could forge — which the shipped comment now states
and which Tier 2 backs with a `jq` read of the file itself.

Two **medium** findings raised against the earlier a81ef4b mirror
(`.agents/docs/reviews/2026-09-15-security-worktree.md`, both `left: styrman-harness`)
are **closed at 4aa19be and verified here, not taken on trust**:
`skills/preflight/SKILL.md:77` now blocks on "a security report … that is
missing, has no `## Not examined` section, or names a path from the release diff
under `## Not examined` (BUG-034)" **and** on "a project agent that shadows a
harness review agent (BUG-033)"; `skills/review/SKILL.md` Step 3 stops before
dispatching on the same clash. `.agents/agents/` in this repo holds only
`.gitkeep` and the range adds no `.claude/**` or `.agents/{agents,skills}/**`
path, so no shadow exists today.

## Findings

- **[low / confidence: medium]** `image/entrypoint.sh:174-181` — the lines
  copied into the boot log come from a process the project user can eventually
  control. `/styrman` is container-filesystem, not a bind mount, but it survives
  `docker stop`/`start`, and the guest holds `NOPASSWD: ALL` inside its own
  microVM (`image/entrypoint.sh:57`), so a guest that overwrites
  `/styrman/bin/sh-agent` in one session has it executed at the next boot and
  can emit any line matching the anchored pattern — including one whose *tail*
  contains `agent harness deployed (version …, styrman-harness …)`, the
  substring `integration.sh:136` greps for, since that check is a `grep -F`
  anywhere in the line. Impact is bounded and crosses **no tenant boundary**:
  `Orchestrator.Logs` (`internal/orchestrator/orchestrator.go:1543`) only
  *displays* the log — owner-scoped through `getProjectFor`
  (`internal/httpapi/stats.go:126`), capped at 256 KiB by `tailBuffer` — and
  never parses it for a decision; the deceived party is the project's own owner
  or the test suite. Raised independently by
  `reviews/2026-09-16-security-worktree-bug-061-062.md` finding 1 and answered
  there with the comment ("a DIAGNOSTIC, not an attestation"), which is the
  right disposition for the code. Remaining remediation (optional, defensive):
  anchor the Tier-2 boot-log greps at the start of the message
  (`grep -E '^\[styrman\] agent harness deployed'`) so a forged tail cannot
  satisfy them, and keep every security-relevant assertion on the file read
  (`jq -e` on `~/.claude/settings.json`), as `integration.sh:147`/`:461` already
  do.

- **[low / confidence: medium]** `image/harness/cmd/sh-agent/main.go`
  (`readSettings`, existing-file branch of `attributionSet`) — check-then-act on
  a path the caller owns. `os.Lstat` establishes "regular file, ≤ 1 MiB", then
  `readSettings` opens it with a plain `os.Open` (no `O_NOFOLLOW`) and the result
  is written back via temp + `os.Rename`. Between the Lstat and the Open the path
  can be swapped for a symlink, so another file's *content* could be read and
  copied into `settings.json`. The final `os.Rename` is safe (rename replaces a
  symlink at the destination rather than following it) and the create branch is
  already hardened with `O_EXCL` and an explicit comment, so this is the one
  unguarded window left in the function. Actor and victim are the same uid — the
  project user, root inside its own microVM — so **no privilege boundary is
  crossed on styrman**. Distinct from the prior report's symlinked-`.claude`-parent
  low (`MkdirAll`), which is about the create branch. Remediation (upstream,
  `styrman-harness`, the mirror being verbatim): open with
  `os.OpenFile(path, os.O_RDONLY|syscall.O_NOFOLLOW, 0)` and re-verify via
  `f.Stat()` on the open descriptor; no new dependency — `os`/`syscall` are
  already imported, and `os.OpenRoot(home)` is the broader stdlib alternative the
  prior report named for the whole installer.

- **[low / confidence: high]** `.agents/docs/architecture/DECISIONS.md` (ADR-072
  Consequences) — describing text narrower than the mechanism it describes: it
  states the entrypoint "logs each line matching `^settings:`", while the shipped
  filter (after BUG-062, `image/entrypoint.sh:180`) also keeps two `note:` shapes.
  `DECISIONS.md` is append-only and the amendment is recorded in
  `bugs/BUG-062-*.md` and `changes/2026-09-16-bug-061-062-fix.md`, so the trail is
  complete; the risk is only that a later reader treats the ADR sentence as the
  whole contract — the project's own describing-text rule, applied to an ADR.
  Remediation: **already applied in the working tree while this review ran** —
  `DECISIONS.md` now carries an `**Amendment (2026-09-16, BUG-062):**` paragraph
  under ADR-072 correcting exactly this sentence (uncommitted at the time of
  writing, `git diff` shows 2 added lines). The finding stands against the
  committed range `3743c29`, where the amendment is absent; it is closed by the
  commit that lands that paragraph.

  violation, not escalation.

  concatenation) guarded only by `json.Valid(result)`. Not the banned
  hand-rolled-crypto class — no primitive, MAC, KDF, RNG, token or session format,
  no auth flow is implemented or composed — but structure editing without a
  parse/serialize boundary; `json.Valid` proves the result parses, not that it
  means the same. Twelve probe shapes (prior report) and ten `TestAttributionSet`
  subtests left every other key byte for byte. Upstream remediation: assert the
  key set round-trips through `map[string]json.RawMessage`.
- **[low / medium]** `os.MkdirAll(filepath.Dir(path), 0o755)` succeeds *through* a
  symlinked `~/.claude`; `apply.go`'s `writeAtomic` already has the same shape, so
  no new surface. No test plants a symlinked `.claude` **directory**.
- **[low / medium]** `attributionHint` is `func(...) error` that can only return
  `nil`; the two callers read as if a settings.json problem could fail `install`,
  which its own doc comment forbids. Correctness, not security.
