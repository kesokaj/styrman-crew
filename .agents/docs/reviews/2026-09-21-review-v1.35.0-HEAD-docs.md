## Findings

- **[medium / confidence: high]** `.agents/docs/specs/styrman/deploy.md:188-213` (### Bring-up) and `.agents/docs/deploy/remote.md:20-29` (Prerequisites on the target) — both list `sudo bash deploy/host-setup.sh --user $USER` as literally the first command of a fresh host bring-up, with no mention that step 7 of that script (the runtime-image build) now needs a GitHub token as a docker build secret (`GH_TOKEN` env or `/etc/styrman/gh-token`, else FATAL — `deploy/host-setup.sh:255-266`). On a genuinely fresh host neither exists yet: `/etc/styrman/gh-token` is only created later, by the "auto-update INSTALLED but NOT enabled" instructions host-setup.sh itself prints at the *end* of the same run (`deploy/host-setup.sh:308-327`), and `.env`'s auto-update setup happens after bring-up too. So the very first invocation of the documented bring-up command will FATAL unless the operator independently thinks to export `GH_TOKEN=$(gh auth token)` first — a step neither doc names. `deploy.md`'s "Rebuilding a host" one-liner (`deploy.md:266-272`) has the identical gap. The changes entry itself half-acknowledges the token dependency ("the crew token ... must be granted read on kesokaj/styrman-harness before the next release deploy, or the deploy tick's image build fails") but only for the updater's deploy tick, not for a first-time or rebuild `host-setup.sh` run. Fix: add one line to Bring-up/remote.md's Prerequisites naming `GH_TOKEN=$(gh auth token)` (or a pre-staged `/etc/styrman/gh-token`) as a prerequisite before running `host-setup.sh`.

- **[low / confidence: medium]** `.agents/docs/testing/styrman/README.md:15` still opens the Tier 2 line with the harness-channel history ("2026-09-21, ADR-074: the harness channel's fifteen checks went with the channel ... twelve came in their place ... for 115 total") — this is accurate as a changelog of the check count and not wrong, but it is the only place living docs still narrate ADR-073 mechanics (channel, swap, commit-named boot line) at length; worth confirming in a future pass that the paragraph doesn't need trimming once the ADR-073 history is no longer load-bearing for anyone reading the current Tier 2 shape. Not a correctness defect — noting only because the brief asked to check every restatement.
