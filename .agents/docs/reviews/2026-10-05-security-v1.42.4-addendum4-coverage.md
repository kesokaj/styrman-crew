## Verdict: FINDINGS (low only; none blocks the release)

All three coverage gaps are closed, and nothing in them is a security defect. No secret, credential, token or private data appears in any file covered. No text addressed a reviewer or agent as an instruction. The range's production edits are comment-only (checked mechanically), and its one new test discriminates the fix it claims. `web/dist` is covered by the rebuild equivalence plus the grep.

The worst problem is in the release gate that the dist equivalence rests on, not in the release itself. `deploy/verify-commit.sh` skips the web/dist freshness step silently when `SKIP_WEB_FRESHNESS` is set or `npm` is not on PATH, and it still ends with "safe to tag". So the r4 verifier log's quote of that final line does not by itself prove the step ran. For d4356c9 the step did run and matched: the proof is in the gitignored `.agents/scratch/verify-r4/vc2.txt:28-30`. That file will not be committed with the trail.

## Findings
- **[low / confidence: high]** `deploy/verify-commit.sh:130` (block ends at `:183` with no `else`), `:223-226`, `:250`: the web/dist freshness rebuild-and-compare, the external-CSS check and the frontend check/lint/test all run only when `SKIP_WEB_FRESHNESS` is unset AND `npm` is on PATH. Otherwise they are skipped without a line of output, and `:250` prints "OK: commit … builds and tests clean in isolation — safe to tag." anyway. Compare the shellcheck and systemd-analyze skips, which print "not installed — skipped" (`:201`, `:216`). `versioning.md:136-140` documents `SKIP_WEB_FRESHNESS`, but the npm-missing branch is undocumented.
  - Why it matters: `//go:embed` ships the committed `web/dist/client` (`verify-commit.sh:132-133`, `versioning.md:127-128`), while reviewers read `web/src`. If the gate runs on a host without npm (another target, a different PATH), it certifies a bundle that may not be the build of the reviewed source, whether stale or hand-edited.
  - Impact: this weakens release integrity. It is not a remote exploit.
  - Scope: not part of `57de009..d4356c9`. Whether `v1.42.3..d4356c9` touched the file was not checked.
  - Remediation: print `SKIPPED: web/dist freshness (<reason>)` in an `else` branch. Then either fail when npm is missing unless `SKIP_WEB_FRESHNESS` is set explicitly, or make the final line say the web checks were skipped and the commit is not safe to tag if the release touched `web/`.
  - Test: one run with npm removed from PATH, which must name the skip (or exit non-zero), and one normal run, which must print "committed assets match a fresh build".
- **[low / confidence: high]** `.agents/docs/testing/2026-10-05-verify-v1.42.4-full-r4.md:25` (step 9b): the log records only "exit 0" and the final OK line for `verify-commit.sh d4356c9`. Because of the finding above, that line does not show that the freshness step ran.
  - The evidence that it did is `.agents/scratch/verify-r4/vc2.txt` (line 1 "verifying commit d4356c9f759a"; `:28` "==> web/dist freshness (rebuild and compare)"; `:29` "committed assets match a fresh build"; `:30` "built CSS references no external origin"; `:35` frontend check/lint/tests; `:40` OK). That path is gitignored scratch, and the log does not cite it, although step 2 cites `vc.txt`.
  - Remediation: the log's owner, or the main agent before committing this still-untracked log, quotes `vc2.txt:28-29` and names the path in step 9b.
