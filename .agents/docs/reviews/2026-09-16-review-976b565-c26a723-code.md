complete on both sides: `stopLocked` switches the restart policy off before
the in-guest TERM and `ensureRunningLocked` switches it back on for EVERY
existing container before any start, which is the only start path a project
container has (`ContainerStart` call sites: orchestrator.go:366 project,
:740 setup VM, :1092 create — the setup VM's `noRestart` is untouched, and
create already sets `unless-stopped`). Both late edits that no reviewer had
read — `TestStopProceedsWhenTheRestartPolicyUpdateFails` and the comment
above the Tier 2 stop check — are correct, and both can fail if the
behaviour they name is reverted (verified by reverting the fix in a scratch
copy, see "Verification performed"). The only findings are low-severity
inaccuracies in the committed `changes/` entry, which the project's
`changelog-brief.md` rule exists to catch.
