# Review — audit-fixes batch (v1.30.0)   (2026-09-13)

Range reviewed: 7066301..e18d62c (`git diff 7066301..e18d62c -- . ':!web/dist' ':!.agents'`; 50 files, +1200/-324). Blobs pinned by `e18d62c`; the working tree at review time is that commit plus uncommitted docs edits (`DECISIONS.md`, `api.md`, `runtime-image.md`, testing README, TODO, a new `changes/` entry) which are OUT of this range.

## Verdict: REQUEST CHANGES

Two defects, both in code the batch introduced, neither caught by the tests it shipped with. The worst is in `format.go`: the `.git/info/exclude` idempotence check is a BRE that can never match the line it writes, so every single Format click appends another `.styrman-fmt-*` line to the user's `.git/info/exclude` — proven by running the exact grep against the exact line. The second is an ordering fail-open in `recreateMissingNetwork`: the network is recreated BEFORE the container is removed, so a failed `ContainerRemove` leaves the project on a fresh subnet with the stale-env container still in place — the precise BUG-054 condition ADR-069 exists to close, and on the next start `recreateMissingNetwork` declines to act because the network now exists. Everything else in the batch traced clean: the credential snippet cannot fail a login shell, the recursion terminates, the updater's hoist is behaviour-preserving, the WebSocket Origin checks are genuinely first, the relay's pump join cannot deadlock, and `request()`'s signal ownership is complete across all five signal-passing callers.

## Findings

- **[medium / confidence: high]** `internal/httpapi/format.go:167` (the script emitted by `formatScript`) — `grep -qsx '.styrman-fmt-*' "$PWD/.git/info/exclude"` never matches the line the next statement appends. `-x` compares a whole line against a **BRE**, where `-*` is "zero or more `-`", so the pattern matches `<any char>styrman-fmt` + dashes and cannot match the literal trailing `*`. Verified: `printf '%s\n' '.styrman-fmt-*' > ex.txt; grep -qsx '.styrman-fmt-*' ex.txt` → exit 1. Consequence: every format request appends one more `.styrman-fmt-*` line to the project's `.git/info/exclude` — a tracked-adjacent file in the user's own repo growing without bound, and a visible oddity the moment anyone opens it. `format_test.go:151` only asserts the substring `.git/info/exclude` appears in the script, so nothing fails. Fix: `grep -qsxF '.styrman-fmt-*'` (fixed-string compare), and extend the test to append twice and assert one line.

- **[medium / confidence: medium]** `internal/orchestrator/orchestrator.go:1478-1491` — `recreateMissingNetwork` calls `createBridgeNetwork` first and `ContainerRemove` second. If the remove fails (the one error path it logs) it returns `false` with the network **already recreated**. The caller then returns the original start error, and on the next `EnsureRunning` the container is still the old one while `NetworkInspect` now succeeds, so this function returns `false` immediately and never acts again. Two outcomes, both bad: Docker reattaches the container to the same-named network and the project boots with `STYRMAN_CRED_BROKER` naming the OLD subnet's broadcast-1 (BUG-054 verbatim, now merely announced by the MOTD marker), or — if the stored endpoint's network ID is what start resolves — the container is permanently unstartable with "network not found" and no self-healing left. Fix, and it is shorter: remove the container first, then create the network; on remove failure return `false` having changed nothing.

- **[low / confidence: high]** `web/src/lib/api.timeout.test.ts:30-45` — the case that is supposed to pin BUG-055 asserts nothing. `api.startProject()` creates its `AbortSignal.timeout(150000)` (and, under the old code, the 20 s composite) **before** `vi.useFakeTimers()` is installed; sinon's fake clock only takes over timers scheduled after `install()`, and `AbortSignal.timeout` is in any case backed by an internal timer rather than `globalThis.setTimeout`. So `vi.advanceTimersByTime(25000); expect(s?.aborted).toBe(false)` passes identically for the composite the fix removed — the regression it names cannot fail this test. Fix: spy on `AbortSignal.any` and assert it was not called for `startProject` (and *was* for `checkFile`), or capture the signal the caller constructed and compare identity.

- **[low / confidence: medium]** `deploy/caddy/ingress/generator.go:277` — `trust login redirect uri domain suffix .<BaseDomain>` is asserted only as generated TEXT; nothing in this range shows go-authcrunch **parsing** a leading-dot domain. The plan records that the `caddy validate` run "stopped at the dummy Cloudflare token", which does not establish that the security app provisioned. If authcrunch validates that field as a hostname, the ingress fails to start on deploy and the whole platform is unreachable — a failure that lands only on the production host. Before the release, run an adapt+provision that reaches the `security` app (real-shaped TLS config, or the security block alone) and record the exit status in the testing log. The emitted Cookie-strip line parses as intended (Caddy's Caddyfile lexer keeps a backslash before anything but `"` and `\`, so `\s` survives into the Go regexp) — no finding there.

- **[low / confidence: high]** `internal/httpapi/credentials.go:45` — the `if err == nil {` → `if err != nil { … return }` rewrite left a bare `{ … }` block behind. It scopes nothing and reads as an editing artefact; delete the braces. (Simplicity only; behaviour is correct.)

## Notes on the surfaces the dispatch named (checked, no finding)

- `image/configs/styrman-credentials.sh` — a login shell cannot fail because of it: every early exit is `return 0 2>/dev/null || exit 0`, every write is `|| true`, the `if ! var="$(curl …)"` form is safe under `set -e` (the command is a condition) and needs no `set -u` (`__sc_fail` is initialised, every other read is `${x:-}`). Marker semantics match the plan: one flag, written once at the end, cleared only when both probes succeeded. Ordering is right — the entrypoint installs the snippet as `zz-` and the MOTD as `zzz-`, so the marker the MOTD prints is this shell's. `__sc_marker`/`__sc_fail` are left set in the interactive shell (the old code unset its temporaries); cosmetic, not reported. `TestCredentialSnippetMarker` actually sources the script against a dead broker — a real test, not a text pin.
- `internal/orchestrator` recursion — terminates: after `ContainerRemove` the recursive `ensureRunningLocked` inspects NotFound and takes the create arm; even in the "removal in progress" race the second pass finds the network present, so `recreateMissingNetwork` returns false and the error is returned. The lock is not re-taken (the `…Locked` variant recurses), and `invalidateSelfAttach` is kept before the `true`.
- `deploy/update/styrman-update` — the hoist is behaviour-preserving: `git()` expands `${DEPLOY_DIR}` at call time (set at line 29), `GIT_CRED_ARGS` is initialised once and only appended to later, and moving `ALLOWED_SIGNERS` above the `update.env` block changes nothing because that file is grepped, never sourced. The `__verify-tag` verb sits before the root and state guards but is fatal without `STYRMAN_UPDATE_TEST=1` and confers no privilege (the script is not setuid; anyone who can run it as root already is). `trap "rm -rf '${gh}'" RETURN` with the expanded path is correct for a `mktemp -d` name and fires on both outcomes; the four-marker regex plus `tail -1` matches git's own last-block dispatch, and the fixture test exercises all four. The owner check against `id -u` is equivalent to the old `= 0` on every path that reaches it (root check precedes the production call).
- `internal/terminal/origin.go` + `bridge.go` — `SameOriginOrAbsent` is genuinely the first statement of both `ServeHTTP` and `ServeSetup`, and `origin_test.go` proves it by serving a bridge whose store and orchestrator are nil. Host-only comparison (no scheme) is unchanged and previously accepted.
- `internal/httpapi/browser.go` — the pump join cannot deadlock: every arm of the select closes both the pane and the upstream before returning, so both pumps unblock; `defer pumps.Wait()` runs before `defer cancel()` (LIFO) but does not depend on the cancel, and it completes before the caller's `defer s.browserRelays.release`, which is the point of the change.
- `internal/httpapi/format.go` confinement — `formatDir` cleans relative and rejects `..`/absolute; the script's `case "$(realpath -m …)" in "$PWD"|"$PWD"/*` fails closed to `$PWD` (quoted patterns are literal), and the sweep is bounded by `-maxdepth 1 -name '.styrman-fmt-*'`. `--ignore-path /dev/null` is right for prettier.
- `web/src/lib/api.ts` — signal ownership is complete: the only callers passing a signal are the 210 s LAN toggle, two 150 s start/stops, the 120 s upload and `checkFile`, which now composes its own bound. `portUrl` through `u` is safe (`u` encodes each interpolation).
- `image/Dockerfile` — `--strip-components=1` into `/usr/local` lands node/npm on the default PATH; the three `--exclude` patterns are `*/NAME` and match under the stripped prefix; the `ARG` pairs sit immediately above the RUN that consumes them, so a bump invalidates only that layer. The published sums cannot be verified from here — the build is the gate.

## Criteria

1. **Dead code — pass.** `ContainedPath`, `sameOriginOrAbsent`, `ExternalLinkIcon`, the orphan JSDoc and the `attached` field are deleted outright with no remaining references (`git grep` at e18d62c finds only docs). `web/.claude/` untracked and gitignored. The one leftover is the empty block in `credentials.go` (above).
2. **Flow tracing — fail (one hop).** Callers and error paths agree everywhere else: `NewUUID`'s two callers both handle the error (500 / quarantine), `files.Read`'s new fault path propagates, `createProject` cleans the workdir on both failing arms, the credential handlers 500 rather than 404. The break is `recreateMissingNetwork`'s failure hop (finding 2), where a partial success is reported as "did nothing".
3. **Standards conformance — pass.** `go build ./...` and `go vet ./...` clean at this tree. Errors wrapped with context; no discarded `err`; no floating promises in the TSX (`try/finally` inside `run`).
4. **Directory layout — pass.** `origin.go` beside its consumer in `internal/terminal`, `diffReveal.ts` in `web/src/lib` with its test beside it, the updater's fixture test in `internal/config` next to the existing ctl harness, image scripts under `image/configs/`.
5. **Simplicity (DIY-except-security) — pass with one nit.** No new dependencies; stdlib and shell built-ins throughout. No hand-rolled auth/crypto — the signature gate delegates to `git verify-tag` with an SSH allowlist and an empty `GNUPGHOME`, which is the right shape. Two places could be shorter: the `credentials.go` block, and `recreateMissingNetwork` (removing the container first removes the need for the failure analysis entirely).
6. **Decoupling — pass.** Moving the Origin helper into `internal/terminal` and re-exporting `reveal` from `web/src/lib` both point the imports one way; `internal/config`'s test shelling out to `deploy/update/styrman-update` through a gated verb is a seam, not a reach-in.
