## Findings

- **[medium / confidence: high]** `.agents/docs/specs/styrman/deploy.md:51` — the
  `uninstall --level 1` table row reads "`systemctl disable --now` the four units". This
  is stale: `deploy/styrman-ctl`'s `UNITS` array (line 61) now holds six entries
  (`styrman-firewall.{service,timer}`, `styrman-update.{service,timer}`,
  `styrman-harness-update.{service,timer}`) added by this same range's Phase 1
  (518c5c0), and `uninstall --level 1` iterates `"${UNITS[@]}"` (styrman-ctl:889),
  so it now disables six units, not four. `deploy.md:364`, added later in this same
  commit, already gets this right ("`UNITS` (the uninstall list) is now six entries,
  the two harness units added") — the two statements contradict each other inside the
  same file. Fix: change "the four units" to "the six units" (or "every unit in
  `UNITS[]`").
- **[low / confidence: medium]** `.agents/docs/specs/styrman/runtime-image.md:255` —
  "`sh-agent status` inside a project is the drift check; `sh-agent update` is not
  used in VMs — the image is the delivery path". This sentence is not updated for
  ADR-073: the same file's own next paragraph (lines 269–277) correctly says a
  channel delivery, not only an image rebuild, re-seeds a project's home ("and so
  does a channel delivery — the server rebuilds a stopped VM to mount a newly
  delivered channel … its new commit is what makes the stamp differ (ADR-073)"). Line
  255's "the image is the delivery path" is the pre-ADR-073 framing this task's dispatch
  explicitly named as changed wording; it should read something like "the seed — image
  or channel — is the delivery path" to match the corrected paragraph nine lines below
  it and R5's own wording ("the base image's pinned mirror … remaining the fallback").
- **[low / confidence: high]** `deploy/styrman-ctl:980-982` (`cmd_help()`, the script's
  own live `help`/usage output) — still lists `install [--user U] [--version X.Y.Z]
  [--env-file F] [--gh-token-file F] [--allowed-signers-file F] [--skip-auto-update]`
  and `update [--redeploy] | --setup [--gh-token-file F] [--allowed-signers-file F]`,
  omitting `--harness-token-file`, even though this range added that flag to both
  `cmd_install` (styrman-ctl:458) and `cmd_update`'s setup path (styrman-ctl:678).
  `deploy/README.md`'s verb table was correctly updated to include
  `--harness-token-file` in both rows, but the script's own `help` text — what an
  operator actually reads on the host with `styrman-ctl help` — was not. This is the
