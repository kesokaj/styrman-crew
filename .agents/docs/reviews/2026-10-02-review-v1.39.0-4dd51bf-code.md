## Findings
- **[medium / confidence: medium]** `README.md:117` (a731950), with `.agents/docs/handoffs/2026-09-22-gcp-deploy-and-v1.39.0.md:46-48` and `.agents/docs/specs/styrman/versioning.md:279-281`
  - **What is wrong:** README's Status line says v1.39.0 is "deployed: … (GCP) and https://crew.styrman.xyz (NUC)". `git tag -v v1.39.0` reports `Good "git" signature with ED25519 key SHA256:XeeDl8Y8…`, and the tag does not verify against the original release key (verified here with a scratch allowed-signers file holding only `~/.ssh/id_ed25519.pub` = `5HpYQJjpG+…`: no principal matched, exit 1). The only record of an allowlist change is the handoff's "The GCP VM's `allowed_signers` trusts two ed25519 keys".
  - **Why it fails:** per ADR-051 / versioning.md:279-281, the NUC's updater refuses a tag whose signer is not in its root-owned allowlist. Unless that allowlist was changed off the record, the NUC never deployed v1.39.0, and it will refuse any later tag signed with the same key. A second trusted release signer is also a change to the trust root, and it is recorded nowhere but a handoff: no ADR, nothing in `versioning.md` or `deploy/gcp.md`.
  - **Fix:** on the NUC, check the deployed version (the updater journal, the `styrman-server` image tag). Correct the README line if the NUC is behind. Sign the gated release with a key both hosts trust. Record the second signer, or remove it, in `versioning.md`/`deploy/gcp.md` with an ADR.

- **[low / confidence: high]** `.agents/docs/specs/styrman/deploy.md:198-199`, `:151-156`, `:174-178` (a731950), and the same "optional" restatements at `AGENTS.md:170`, `.agents/docs/specs/styrman/guide.md:470-473,483`, `.agents/docs/deploy/remote.md:15`
  - **What is wrong:** these places now call `CLOUDFLARE_API_TOKEN` optional (HTTP-01 fallback) but leave out its one hard dependency. The preview and private-link wildcards (`*.STYRMAN_PUBLIC_DOMAIN`, `*.STYRMAN_PRIVATE_DOMAIN`) cannot get a certificate without DNS-01, and they get no DNS record without the token. `deploy/caddy/ingress/generator.go:29-30` and `deploy/.env.example:34-35` say so. The spec's preview sections still promise "a wildcard DNS A record (`EnsureDNS`), and an auto-issued wildcard TLS cert" without a condition.
  - **How it fails:** an operator following `deploy.md` on a host with no token (the GCP target is one) who sets `STYRMAN_PUBLIC_DOMAIN` gets preview links with no DNS record and no certificate, and no document they read warns them.
  - **Fix:** add "requires `CLOUDFLARE_API_TOKEN` (DNS-01)" to both preview sections and to the prerequisites sentence, and in AGENTS.md and guide.md add "(non-wildcard hostnames only)" where the token is called optional.

## Criteria
1. **Dead code — pass.**
   - `classifyControl`, `applyControl` and `pongFrame` are called from `serve` and from tests.
   - `cmd/wsprobe`'s `-control` flag is used by Tier 2's ping check.
   - Every export of `termLiveness.ts` is imported by `TerminalPane.tsx`.
   - `OPTIONAL_FILL` is read by `cmd_install`.
   - The range adds no commented-out code and no debug output.
2. **Flow tracing — pass.**
   - **Bridge:** the read loop → `applyControl` → touch/resize/bounded pong write. A write error ends the attachment, and `browserGone` is set only on a live context. Concurrent `conn.Write` from the pong path and the PTY pump is safe under coder/websocket.
   - **Web liveness:** one `Liveness` per socket. It is stopped on close, drop and unmount. `onDead` reconnects only when the socket is still current (`ws === sock`). The "reclaim" path fires only on hidden→visible or the button, never by itself after a 4001. A server without pong (`answers=false`) is never declared dead. Every listener and timer added in the effect is removed in its cleanup.
   - **Entrypoint:** `harness_finish &` runs after `ready` on the non-minimal path only. The minimal path neither seeds nor writes `harness-done`, as before. The stamp is the last write, so an interrupted install repeats on the next boot. The `/opt/agy` chown runs on every boot, before the minimal branch.
   - **styrman-ctl:** the optional key is validated and written only when `--env-file` carries it, and an invalid value stops the install.
   - **`integration.sh` (4dd51bf):** the added clause `test -x /opt/agy/agy && [ -z "$(find /opt/agy -perm /022)" ]` follows the same container's `stat` and `runuser` clauses. A `find` that cannot run would pass silently (the project's known R3-5 idiom). The positive clauses before it make that unlikely, and a must-fail run is recorded in `reviews/2026-10-02-review-1fe28a0-4460e1b-merged.md` (round 2, S5).
3. **Standards conformance — pass, with the two restatement findings above.**
   - Go and TS follow the language skills: table-driven tests beside the code; `unknown` narrowed in `isPong`.
   - The 4dd51bf describing text (DECISIONS.md ADR-077 heading, runtime-image.md step 4b) agrees with the code: `chown` at `entrypoint.sh:67`, before the minimal branch at `:353`.
   - Observation, not a finding: `handoffs/2026-09-22-gcp-deploy-and-v1.39.0.md:65-67` records that the GCP VM's Caddy and `styrman-ctl` were "patched inline" to unblock v1.38.0. That is the kind of hand-applied workaround `.agents/rules/no-live-workarounds.md` forbids. v1.39.0 replaced it, so it causes no failure today; it is listed here so the pattern stays visible.
4. **Directory layout — pass.** `control_test.go` sits beside `bridge.go`, `termLiveness.ts` beside its test in `web/src/lib/`, and the config tests in `internal/config/` with their siblings. The records are under `.agents/docs/`.
