# Review — v1.33.0-9dab61d-docs   (2026-09-16)

Range reviewed: v1.33.0..9dab61d

Docs lens only, per dispatch (no source, config, or test files were edited). The range's one substantive project change (non-vendored) is ADR-072: `sh-agent install` now writes one key, `attribution`, into `~/.claude/settings.json`, and `image/entrypoint.sh` now captures and logs the installer's `settings:` lines. `REQUIREMENTS.md` R5 and `image/entrypoint.sh`'s own comment were updated for this in-range (confirmed already reviewed and fixed by the 2026-09-16 worktree docs review). But `.agents/docs/testing/styrman/README.md` — the project's named testing source of truth — was not touched anywhere in this range and now contains two statements the shipped code contradicts, plus one living spec (`runtime-image.md`) still carries the pre-ADR-072 claim verbatim. ## Findings

- **[medium / confidence: high]** `.agents/docs/testing/styrman/README.md:402-403` — "install's own stdout is discarded, so that line is the in-guest proof install succeeded" no longer matches `image/entrypoint.sh`. Since this range, stdout is captured (`HI_OUT="$(... sh-agent install ...)"`) and its `^settings:` lines are logged line-by-line (`image/entrypoint.sh:159-170`). "discarded" is false; the sentence needs to say stdout is captured and its `settings:` lines are logged (auditability point from ADR-072's Consequences), while the "in-guest proof" claim about the `agent harness deployed` log line stands unchanged. `narrowed: image/entrypoint.sh:110-115 (old comment, pre-range) → image/entrypoint.sh:159-170 (new code, this range)`, docs at `.agents/docs/testing/styrman/README.md:402-403` never updated to match.

- **[medium / confidence: high]** `.agents/docs/testing/styrman/README.md:405-406` — lists `~/.claude/settings.json` among files a freshly-seeded home does NOT get ("none of `~/.agents/bin`, `~/.gemini/GEMINI.md`, `~/.claude/settings.json`"). Since ADR-072 (`sh-agent install` writing the `attribution` key when absent, wired into the boot path by `image/entrypoint.sh` in this range), every project home DOES receive `~/.claude/settings.json` on its next boot. This line describes exactly the negative-space claim ADR-072 reversed and was not touched by this range's diff (confirmed: `git diff v1.33.0...9dab61d -- .agents/docs/testing/styrman/README.md` is empty). `dropped: REQUIREMENTS.md:49 (old wording "no hooks, scripts, or settings files")` was fixed at its primary site; this restatement in the testing guide was not — same finding class as `REQUIREMENTS.md`'s pre-fix state, in a file the docs-lens review of the harness refresh explicitly said it had only grepped, not read, for `.agents/docs/specs/` (it did not cover `.agents/docs/testing/` at all).

- **[low / confidence: high]** `.agents/docs/specs/styrman/runtime-image.md:244-245` — "It ships NO hooks, NO scripts, and NO `settings.json` for either tool (operator directive 2026-09-03), so Claude Code runs in its default permission mode inside a project." This is the verbatim pre-ADR-072 claim (matches old `REQUIREMENTS.md` R5 and old `ADR-062` wording almost word for word) and was not updated when R5 and the entrypoint comment were fixed in this range. `narrowed: REQUIREMENTS.md:49-52 (fixed, this range) → .agents/docs/specs/styrman/runtime-image.md:244-245 (unfixed)`. The "default permission mode" consequence itself is still true (the attribution key only disables commit/PR trailers, not permissions), so this is a factual-precision gap rather than a behavior-safety one — hence low, not medium.

- **[low / confidence: high — already resolved, noted for completeness]** `README.md:174-175`'s v1.20.0 release-history bullet ("no hooks, scripts, or settings files") is a dated historical entry predating ADR-072 and was already flagged and explicitly left as-is (historical, append-only spirit) by the 2026-09-16 worktree docs review. Repeating only so this report's sweep for the same subject noun ("settings files") is shown complete; not a new finding.
