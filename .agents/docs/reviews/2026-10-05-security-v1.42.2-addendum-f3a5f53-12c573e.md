- **[medium / confidence: high that it is open and has no disposition at 12c573e; the weakness itself is medium confidence, computed by the earlier addendum and not measured]** `.agents/docs/reviews/2026-10-05-security-v1.42.2-addendum-ef22f5c-f3a5f53.md:15,21-31` (added by this range; none of its 146 lines is an `## Outcome`) against `.agents/docs/reviews/2026-10-05-security-v1.42.2-v1.42.1-ef22f5c.md:156` ("2. **Fixed.**", about `readHistory` only). The code is unchanged at `internal/httpapi/explorer.go:77` (12c573e). Carried, not introduced.
  - **Weakness:** `GET /api/projects/{p}/file` has no concurrency slot and no write deadline. A 2 MiB file of `<` becomes about 12 MiB of escaped JSON per request, so one tenant holding about 200-250 requests it never reads reaches the server's 4g cap. The restart drops every tenant's sessions. The 8 MiB request bodies on PUT `/file`, `/format` and `/check` are the same class (no read deadline).
  - **Why it is recorded here:** the range commits the addendum that raised this and changes no Go code, so v1.42.2's head ships the medium while the security trail calls it both "Fixed" (earlier Outcome) and "refuted" (addendum :87). The addendum's own remediation (:31) says to record an acceptance in the Outcome and not to record it as fixed.
  - **Remediation, stdlib only and no dependency:** before the v1.42.2 tag, do one of two things.
    - Fix it: put `readFile` behind the existing `acquireSlot` + `http.NewResponseController` write deadline, give the large-body handlers a `SetReadDeadline`, and add a must-fail test of stalled concurrent file reads getting 429.
    - Or accept it: write the operator's acceptance into a `## Outcome` in the addendum, and amend item 2 of the earlier Outcome to "fixed for transcript reads only; the file read is in the addendum".
