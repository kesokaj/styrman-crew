## Questions in the dispatch
- **Lock ordering.** There is one mutex (`searchMu`) and a non-blocking channel send under it. Nothing blocks while it is held, and the release takes `searchMu` and then does `<-searchSlots` (a receive that cannot block, since this goroutine holds a slot). No inversion.
- **Release on every path.** The `defer` is registered immediately after `searchBusy[...] = true` and Unlock, with no panicking code between them. It runs on a normal return, an error return, a client disconnect and a panic in `history.Search` (the defers run before net/http recovers). The busy flag is cleared and the slot is returned together.
- **429 takes no slot.** The per-user refusal happens before the channel send. The global refusal Unlocks before returning, and the flag is set only after the send succeeds. `TestHistorySearchIsOnePerUser` asserts `len(searchSlots) == 0` after the refusal.
- **Map growth.** `delete` on release means entries exist only while a search is in flight, bounded by `searchConcurrency` (4). `New` is the only constructor and initialises the map. A nil map write would panic, but none exists.
- **The test.** It fails without the feature: the second request would be 200. It checks that the busy flag is cleared after a real search, and `go test -race -run HistorySearch ./internal/httpapi` passes. Not covered: concurrent real searches by the same user (the busy state is planted directly) and the panic path.
- **Token wording.** `install -D -m 600 -o root -g root <file> /etc/styrman/gh-token` produces root:root 0600, which passes the owner check (`stat -c %u` = 0) and the `-perm /077` check at `host-setup.sh:304-305`. `-D` creates `/etc/styrman` and a later step resets it to 700. `test -s` refuses an empty file, and a missing file as well. No instruction now pipes `gh auth token` or any token value through sudo's argv, environment or stdin. The remaining `gh auth token` hits are the local `docker build` examples (no sudo), and `deploy/README.md:36` mentions it only as the form to avoid. `styrman-ctl --gh-token-file` exports the token in the environment of the process it spawns (`styrman-ctl:445`), not on sudo's command line. The `host-setup.sh:307` hint says the same.
