## Traced and found correct (dispatch questions)

- **`gitrepo.git()` with Start, then the adj write, then Wait:**
  - Output: `Stdout` and `Stderr` share one `bytes.Buffer`, which is what `CombinedOutput` does. The success and failure return values are unchanged.
  - Cancellation: `exec.CommandContext` kills the child on ctx cancel under Start/Wait exactly as before.
  - Start errors: now `git <arg>: <err>` instead of `git <arg>: <err>: ` with empty output. Every caller (`main.go:312,315`, `provision.go:92,155`, `server.go:934`) only tests `err != nil`, so callers see no change.
  - PID reuse: impossible. The write happens before `Wait`, so the PID cannot be reaped and reused, and an exited (zombie) child only makes the ignored write fail.
  - Race window: `Start` returns after exec. The write follows within microseconds, far less time than parsing a GB-scale config takes.
  - Privilege: runc sets `oom_score_adj_min` to -999. Raising the child to 0 is at or above that minimum, and the owner (same uid) may write the file.
  - Other host-side children: `gitrepo` is the only `exec.Command` outside the tests in `internal/` and `cmd/`.
- **Compose:** `docker compose config` (STYRMAN_VERSION=0.0.0, no `deploy/.env`) renders `oom_score_adj: -999` and `mem_limit` 1073741824 / 4294967296 for both services. `compose_oom_test.go` pins both values per service, and a different value fails it.
- **`deploy/lib/docker-oom.sh` and `host-setup.sh:116-129`:**
  - Placement: it runs after Docker CE (step 1) and before step 3's possible `systemctl restart docker`. That restart picks up the drop-in after the conditional `daemon-reload`, and step 8c's unconditional `daemon-reload` (`:329`) catches a missed one.
  - Unit syntax: `[Unit] StartLimitIntervalSec=0` is valid in a drop-in. It overrides the packaged unit's `StartLimitIntervalSec=60` / `StartLimitBurst=3`, which I read on this host.
  - Ordering against other drop-ins: the existing `limits.conf` sorts after `50-styrman-oom.conf` but sets neither key.
  - Writes: the drop-in is written atomically (temp file and `mv`), and a symlink in its place is replaced, not followed.
  - Error handling: `set -e` is safe around `[[ … ]] && daemon-reload` and the `pidof` loop.
