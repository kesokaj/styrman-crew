## The new test — `internal/terminal/ensure_before_upgrade_test.go`

Checked against `internal/terminal/bridge.go` `ServeHTTP` (unchanged in this
range), and it holds on all three questions the dispatch asked:

- **It really pins "boot callback before upgrade."** Revert the property —
  move `b.ensure(...)` below `b.serve(...)` — and `got` stays empty, so
  `t.Fatalf` at line 50 fires. There is a second, independent guard: with no
  handshake headers on the request, `websocket.Accept` fails inside
  `verifyClientRequest` (missing `Connection: Upgrade`) *after* setting
  `Connection: Upgrade` and `Upgrade: websocket` on the recorder, so the
  line-55 `Upgrade` assertion also fires. The test cannot silently pass a
  reordered handler.
- **Fakes and nil orchestrator mask nothing.** `oneRecordStore` returns a
  zero `conversation.Record{}, true`, so `paneCmd` stays `bash -l` and the
  record lookup cannot short-circuit the path before `ensure`; if
  `ValidateID("conv-1")` or the store ever rejected, the response would be
  400/404 with `got` empty — a loud failure, not a mask. The nil
  `*orchestrator.Orchestrator` is only reachable via `b.orch.Stopped(...)`,
  which Go's `&&`/`!=` short-circuit skips because `boot=1`; a future change
  that evaluates `Stopped` first would panic, which is a test failure, not a
  false pass. `SameOriginOrAbsent` passes because `httptest.NewRequest` sets
  no `Origin`.
- **Comments are true except one clause** — see finding 1. Everything else
  (the BUG-060 rationale, `httpapi.wsBoot` as the real symbol name, the
  `boot=1` short-circuit note) is accurate.

Placement is correct (beside `bridge.go` in `internal/terminal`, same package,
no collision with `origin_test.go`'s helpers), the file is plain text
(`git diff --numstat` = `58 0`, not binary — BUG-007 check), and it was added
as a new file, not written over an existing one (BUG-005 check: 0 deletions).

## Findings

- **[low / confidence: high]** `internal/terminal/ensure_before_upgrade_test.go:27-29`
  — the comment's stated mechanism is not the one that fires. "A recorder
  cannot be hijacked, so a handler that upgraded first would fail there and
  never call the callback" is true of `httptest.ResponseRecorder` in general,
  but this request carries no WebSocket handshake headers at all, so
  `websocket.Accept` refuses in `verifyClientRequest` long before any hijack
  attempt — and, usefully, sets the `Upgrade` header the test then asserts is
  absent. The test's protection is real either way; only the explanation of
  *why* is off, and the same sentence was copied verbatim into the prior
  review's `## Outcome`. Concrete fix (non-blocking, a future touch of this
  file): say "the request carries no handshake headers, so an upgrade
  attempted first fails in `websocket.Accept` and sets `Upgrade: websocket`
  — which is the header line 55 asserts is absent."

- **[medium / confidence: high]** Release gate, not a code defect —
  `.agents/docs/changes/2026-09-14-bug-060-terminal-ws-boot-attach.md`
  "Verification": the fix's only evidence is three fake-based unit tests. The
  real `EnsureSelfAttached` → `docker network connect` step was never
  exercised ("Live join … not executed (permission classifier blocked)"), and
  the automated e2e cannot cover it — the testing README correctly states the
  proof must start from a project left STOPPED across a server restart, which
  `web/e2e/run.sh` does not construct. The record is honest about this and
  ROADMAP.md carries the operator check, so nothing is being claimed falsely;
  the gate condition is that the release is not proven until that check is
  run on the deployed host (first terminal of a stopped project shows no
  "broker did not answer" MOTD line, `gh auth status` succeeds).

No other findings. The rule file, the AGENTS.md bullet, the two spec edits,
the testing README, the BUG-060 record and the change entry were each checked
