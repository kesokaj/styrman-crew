## Verdict: REQUEST CHANGES

One committed test now contradicts the behaviour this range ships: the Tier 2
integration check `no previous-harness artifacts (shell gates, GEMINI.md,
settings.json)` asserts `! test -e ~/.claude/settings.json` in the project home,
while `sh-agent install` at mirror commit 4aa19be creates exactly that file in
every project home on first boot. I reproduced the create against a scratch home
with the binary built from this tree. Tier 2 was not run this round (the
verifier's own log says so), and `deploy/verify-commit.sh` does not run it, so
nothing in the range caught it — the failure lands on the next
`integration.sh` run, i.e. during the release this handoff recommends. The
harness's own Go changes (attribution write, symlink path guards) are sound; the
attribution JSON insertion is careful and its edge cases hold up under reading.

## Criteria

1. **Dead code — pass with one low note.** No orphaned files, commented-out
   blocks, or leftover debug output in the range. `attributionHint`'s
   never-non-nil `error` return (finding 4) is the only unreferenced path, and it
   is upstream's. `go vet ./...` clean in the mirror module; `gofmt -l .` empty.
2. **Flow tracing — fail (finding 1).** The behaviour change was traced through
   `sh-agent install` → `image/entrypoint.sh` → the project home, but not to the
   caller that asserts on the result: `integration.sh`'s harness block. This is
   the BUG-035 / `.agents/rules/mechanism-reaches-every-caller.md` shape — the
   mechanism reached the installer and the requirement but not every step that
   must honour it. Positively traced and correct: `run()` gates `attributionSet`
   on `VendorAll`/`VendorClaude`; `attributionSet`'s create path uses
   `O_EXCL` so a planted link or FIFO fails rather than being written through;
   the modify path re-parses with `json.Valid` before `rename` and never writes
   through a symlink (`Lstat` first, and `rename` does not follow a link that
   appears afterwards); `abandonTemp` removes the temp file and reports when it
   cannot; every failure is advisory and cannot fail `install`, matching the
   entrypoint's "a harness hiccup must never block the project from booting".
   I read the textual JSON insertion against single-line, pretty-printed, empty
   (`{}`, `{ }`), CRLF, trailing-newline, brace-in-string and nested-object
   inputs and found no case that produces invalid JSON or drops an operator key.
   The `case err != nil, !info.Mode().IsRegular():` switch does not nil-deref:
   Go evaluates case expressions left to right and stops at the first match.
   `checkManagedTree` is called from both `LoadInventory` and `RenderContext`,
   so no reader of the repo's bytes is left unguarded, and `LoadSkills` now
   returns a symlinked `SKILL.md` as an error instead of skipping it.
   `image/entrypoint.sh` runs `set -uo pipefail` with no `-e`, so the new
   `printf | grep | … | while` pipeline returning 1 on no match cannot abort the
   boot — checked explicitly.
3. **Standards conformance — fail (findings 1-3).** `REQUIREMENTS.md` R5 was
   amended with recorded operator approval and an ADR (ADR-072), so the R5
   process is satisfied; what is not satisfied is the rule that every other
   restatement of a changed rule changes with it. Grepping the subject nouns
   (`settings.json`, `settings file`, `no hooks`) across the repo outside the
   mirror turns up three live restatements — `integration.sh:137-138`,
   `testing/styrman/README.md:406,448`, `entrypoint.sh:126-128` — plus
   `README.md:174` (dispositioned) and a set of dated `testing/` logs that are
   append-only records and correctly left alone. New tests in the range can all
   fail: `pathguard_test.go`'s symlink cases plant a real link and assert the
   refusal names it, `TestSkillDirWithoutSkillMdIsSkipped` pins the
   non-regression of the new error path, and `TestLoadStateDropsNonLocalManifestEntries`
   asserts on behaviour, not source text. No `t.Skip`, `//nolint` or lint
   exclusion added (the one `skip` in the suite is the pre-existing
   symlinks-unavailable guard).
4. **Directory layout — pass.** No new styrman-side files. Mirror files land
   under `image/harness/` exactly where `VENDORED.md` § Refresh puts them; the
   new test file sits beside the package it covers
   (`internal/harness/pathguard_test.go`). `sha256sum -c SHA256SUMS` → all OK,
   155 sums for 155 files, so the mirror is complete and text (no binary or
   partially staged file — the BUG-007 class).
5. **Simplicity, DIY-except-security — pass.** No new dependency in either
   module; the attribution work is `encoding/json` + `bytes` + `os` only. The
   textual insertion instead of `json.Marshal` is justified in the code comment
   (marshalling would reorder the operator's keys) and is guarded by a
   `json.Valid` re-parse, so the extra complexity buys a real property. No
   auth, crypto, hashing, session or token code is implemented or composed
   anywhere in the range — the only cryptographic surface is `sha256sum` over
   the mirror manifest, which is stdlib/coreutils use as designed, not
   hand-rolling.
6. **Decoupling — pass.** The attribution logic sits behind two small functions
   in `cmd/sh-agent` and touches no `internal/harness` state; `readSettings` is
   the single bounded reader both callers share. `checkManagedTree` puts the
   symlink refusal at one boundary rather than at each reader, which is the
   right seam. The styrman↔mirror seam is unchanged and one-directional: the
   entrypoint consumes `sh-agent`'s stdout by prefix and nothing else, so an
   upstream change to other output lines cannot break the boot.
