Range reviewed: v1.25.0..21ba6d9

`Name: rec.Name, Dir: rec.Dir` — judged against the committed file
(`git show HEAD:internal/httpapi/network.go`, HEAD = `29e05a1`); (b) commit

working tree in `2026-09-10-review-network-record-first{,-round2,-round3}.md`
(round 3: APPROVE) and its conclusions are inherited, not re-derived.

## Verdict: APPROVE WITH NITS

Nothing in this delta is broken. The worst item is a parsing gap in the new
frontend helper: `sshPublicKey`'s regex accepts a TWO-LINE value whose first
line is a comment-less public key, so a second, attacker-chosen line rides
along into the row's `title` and onto the clipboard — contradicting the
function's own stated contract ("only a line that LOOKS like a public key is
returned") and the server-side symlink refusal it is paired with. Low
severity: the file is the user's own base-home `.pub`, so the blast radius is
the same user pasting a second key into an `authorized_keys`. The Go delta is
correct on both branches: `gone` maps only `project.ErrNotFound` (the sole
error `Store.SetLanAccess` can return besides a save failure) to 404, writes
exactly one response, and every caller returns immediately after it — no
double write, no fallthrough. `RunOpts{Name: rec.Name, Dir: rec.Dir}` moves
the last two pre-lock values onto the record read under the lock, which is
what security round 4 asked for.

## Findings

- **[low / confidence: high]** `web/src/lib/sshKey.ts:14` — **the "is it a
  public key" regex admits a multi-line value, so the copy button can carry a
  second line the user never sees in full.** `(\s+\S.*)?$` lets `\s+` match a
  NEWLINE; with no `m` flag `$` is end-of-input, so
  `"ssh-ed25519 AAAAC3\nssh-ed25519 AAAAEVIL attacker@host"` and
  `"ssh-ed25519 AAAAC3\n-----BEGIN OPENSSH PRIVATE KEY-----"` both pass
  (verified in node against the exact literal). It only fails when the first
  line already has a comment, i.e. the check depends on a detail of the
  attacker's own input. Server side, `toolDetails` puts the WHOLE
  `.ssh/id_ed25519.pub` (up to `files.MaxReadBytes`) into
  `ssh.Details[0]` (`internal/httpapi/setup.go:238-243`), so a multi-line
  file reaches the browser intact. Failure: anything that can write the
  user's base home `.pub` (the setup VM's shell, an agent CLI run in it)
  appends its own key line to a comment-less pubkey; the Settings row shows
  `abbreviateKey`'s output truncated by `truncate`, the `title` shows both
  lines, and `copyKey` copies BOTH — pasted into `authorized_keys` or a git
  host's key box, the second key is authorized. This is precisely the class
  the server comment at `setup.go:234-237` says the symlink refusal exists to
  prevent, so the two guards should agree. **Fix:** test per LINE, not per
  detail — `for (const line of d.split("\n"))` before `PUBLIC_KEY.test` — or
  make the whitespace classes explicit: `[ \t]+` after the type and
  `([ \t]+\S[^\n]*)?$` for the comment. Add the two-line case above to
  `sshKey.test.ts`'s "returns nothing for details that are not a public key"
  block; it is the one discriminating case that list is missing.
- **[low / confidence: high]** `internal/httpapi/network.go:131-137`,
  `:180`, `:208` — **the new 404 branch has no test on either of its two
  call sites.** `git show HEAD:internal/httpapi/network_test.go` has 18
  `func Test`; none drives a `persist` that returns `project.ErrNotFound`
  (`TestNetworkPersistFailure*` inject a save failure, not a missing record),
  so deleting `gone` entirely leaves the suite green. The project's Definition
  of Done makes changed code without a covering test a FAIL. It also matters
  more than a usual coverage gap here, because the two sites are not
  symmetric in reachability: the `:180` site is reachable exactly as security
  round 4 describes (`deleteProject`'s `Remove` at `server.go:1016-1019`
  landing between the closure's `Get` and its `persist`), while the `:208`
  site — past a successful `Stop`, i.e. with the container RUNNING when the
  closure started — is not reachable through today's delete flow at all:
  `Destroy` takes the same project lock (`orchestrator.go:1326-1329`) and
  `Remove` runs only after it returns, so any interleaving that removes the
  record leaves `Status` reporting absent and the closure on the persist-only
  path; the other four `projects.Remove` sites (`server.go:796,809,814,822`)
  are create-failure cleanups where no container exists yet. **Fix:** one
  test per site using the existing `fakeMode.onLock` hook
  (`network_test.go:286-292`) that already removes/flips the record inside

  records which interleaving it is for.

## Verdict: REQUEST CHANGES

symlink fix broke the darwin build: `syscall.Openat` does not exist on
darwin, and `GOOS=darwin GOARCH=arm64 go build ./...` goes from exit 0 at

## Round-1 findings — both closed

  round-1 payloads now return `""`: run in node against the exact new literal
  plus the `MAX_KEY_LEN`/`[\r\n]` guard,
  `"ssh-ed25519 AAAAC3\nssh-ed25519 AAAAEVIL attacker@host"` and
  `"ssh-ed25519 AAAAC3\n-----BEGIN OPENSSH PRIVATE KEY-----"` both reject,
  while `"ssh-ed25519 AAAAC3 me@host"` and the tab-separated form with an
  inner-space comment still pass. Belt and braces, correctly: the explicit

  and 4096 caps the input anyway.
- **Finding 2 (404 branch untested) — CLOSED, and the test discriminates.**
  Verified by mutation on a throwaway `git archive` copy, not by reading:

  commit message is exactly right: `writeErr` (`server.go:1272-1277`) already
  promotes any error wrapping `project.ErrNotFound` to 404, the status alone

  Both sites are covered, and the `:208` site's test comment states in the

## Should `gone` be deleted? — no, but it should be inlined (not a finding)

Deleting the branch outright is the wrong trade even though it is shorter:
the mutation above shows what the user then gets — a 404 whose body says the
project "was stopped but the setting could not be saved ... start it to
continue in the previous mode", advice about a project that no longer exists,
plus a spurious `logger.Warn` for a benign race. The branch earns its keep on
the message, so keep the behaviour.

The *helper* is the part that fails the shorter-code rule. The closure is 7
lines plus two 3-line call sites (13); the same behaviour written out at both
sites is 8:

    if errors.Is(err, project.ErrNotFound) {
        writeErr(w, http.StatusNotFound, err)
        return
    }

That is −5 lines and, more to the point, removes a helper with an implicit
"returns true meaning I already wrote the response" contract that every
future reader has to re-derive from its body. Recommendation: inline it, keep
the two-line comment once above `persist`. Behaviour-identical, so the new
test stays green either way — hence a recommendation, not a finding.

  **Fix (either):** (a) `golang.org/x/sys/unix.Openat`, which exists on both

## `publicKeyLine` — the two questions asked, answered by probe

Twenty-one inputs run against the exact function body (`setup.go:297-311`)
in a scratch program.

**No false reject of a legitimate key.** Accepted: `ecdsa-sha2-nistp521 …=
simon@nuc laptop` (a comment with spaces — only the first token after the
type is body-checked, the rest is free text); `sk-ssh-ed25519@openssh.com …
yubikey 5c nano`; `sk-ecdsa-sha2-nistp256@openssh.com …` with no comment at
all; a body containing `+`, `/` and `=`; a double space between type and body
(the `strings.TrimLeft(rest, " ")` is what saves this one);
`ssh-ed25519-cert-v01@openssh.com`. `ssh-dss`/`ssh-rsa` follow from the
`ssh-` prefix. The one legitimate-ish form rejected is a TAB separator
(`ssh-ed25519\tAAAA` → false) — `ssh-keygen` writes a single space, so no
real `.pub` is affected, the direction is fail-closed (`Ready:false`, no
card), and it is only worth knowing because `web/src/lib/sshKey.ts` accepts
`[ \t]` and the two now disagree. Not a finding.

**False accepts exist, and one is more than cosmetic** — see finding 2. The
specific cases the question named behave correctly: a type prefix with an
empty body (`"ssh-ed25519 "`, `"ssh-ed25519  "`) is rejected via the `body ==
""` test after the `TrimLeft`, and a body with a space is not a body with a
space at all — the cut takes the first token and treats the remainder as the
comment, which is the OpenSSH format. The gap is the prefix test itself.
