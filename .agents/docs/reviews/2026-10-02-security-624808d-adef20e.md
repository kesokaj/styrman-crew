## Findings
- **[low / confidence: high]** `internal/orchestrator/ports.go:142-143,171` (the `GuestGoingAway` ceiling), against the Outcome claim at `.agents/docs/reviews/2026-10-02-security-57179a4-624808d.md:91`.
  - **What the fix does:**
    - `ctx, cancel := context.WithTimeout(ctx, lifecycleWaitMax)` reassigns the parameter itself, not a new variable. So the `gone` closure's `Status` calls share the deadline.
    - At 20 s the `select` returns false, and the caller reports the exec failure as it stands.
    - One request is now capped at about 200 inspects. Before, a toggle's 90 s `waitReady` allowed about 900.
    - Both callers get the ceiling: `ListeningPorts` (`ports.go:109`) and `browserExec` (`internal/httpapi/browser.go:95`).
  - **What it does not do:**
    - It does not limit the rate. A tenant who parks N requests still drives about 10·N inspects per second against the dockerd that all tenants share, for as long as the lock is held. A request parks after its exec fails while its own project's start or stop holds the lock and the container is still running.
    - A client that never gives up just sends each request again every 20 s.
    - N is still unbounded. There is no per-user in-flight cap for `/ports` or the browser REST endpoints (round 3's grep), and no coalescing around `gone()`.
    - For the page, nothing changes: it already aborts a poll at 20 s (`web/src/lib/api.ts:376`, cited from round 3 and the code review, not re-read). The ceiling only limits how long non-browser clients stay parked.
  - **Why it is only low:** this is unchanged from round 3. Only an authenticated, allowlisted tenant can do it, and it costs availability only. An inspect is cheap. The same tenant can already flood `/ports` with Kata execs, which cost more.
  - **Remediation, one of:**
    - **Accept it on the record.** Reword the Outcome and BUG-088's fourth step to say "bounds each request at ≈200 inspects; the aggregate rate stays ≈10/s per parked request".
    - **Close it with one of round 3's options.**
      - Option 1: a per-user in-flight cap for `/ports` and the browser REST endpoints. The relay's cap of 8 is the model.
      - Option 2: a singleflight or one-tick `Status` cache around `gone()`, keyed on `key(user, project)`.
      - Either way, add a test that N concurrent waiters cause about one inspect per tick.
- **[low / confidence: high]** `deploy/update/styrman-update:147` (`[[ "${STATUS_FILE}" =~ ^/[A-Za-z0-9._/-]+$ ]]`, comment `:144-146`). The same claim appears in `.agents/docs/specs/styrman/deploy.md:497-499`, `.agents/docs/specs/styrman/versioning.md:356-358` and the warning text at `:148`.
  - **What is wrong:**
    - Bash's `=~` uses the C library's regex in the current locale. In a UTF-8 locale, `A-Z` and `a-z` are collation ranges, not ASCII.
    - Measured on bash 5.2.37: `/x/é/updater.json` is accepted under `LC_ALL=en_US.UTF-8`, and refused under `C` and `C.UTF-8`.
    - On this host, `systemctl show-environment` reports `LANG=en_US.UTF-8`, and `styrman-update.service` sets no `LC_ALL` (`systemctl show -p Environment`). So a real tick here runs the check in exactly that locale.
  - **Impact:** none found.
    - The rule's purpose holds in every locale. UTF-8 never uses byte 0x0A inside another character, so no accepted character can cut `read`'s walk short. In the probe, case A (a newline in an ancestor) and case D (a trailing newline) were refused.
    - The path is pinned in root-owned config.
    - What fails is the written contract: "plain characters only, `A-Z a-z 0-9 . _ / -`; any other character … is refused". The next change that relies on that set inherits a check that depends on the locale.
  - **Remediation, one of** (both verified here, bash 5.2.37 under `LC_ALL=en_US.UTF-8`, `é` refused):
    - Make `local LC_ALL=C` the first line of `write_status`. Bash reapplies `setlocale` on the assignment and restores the locale when the function returns.
    - Or write the class without ranges: `[ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789._/-]`.
    - Then add a hook test with a non-ASCII component under a UTF-8 locale that must WARN, skipping when `locale -a` has none. The current test only plants a newline.
