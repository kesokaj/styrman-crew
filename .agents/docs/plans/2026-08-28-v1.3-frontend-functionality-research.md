## 1. Bugs root-caused this session (no decision needed — fix)

1. **Cannot write files created/opened in project scope** — `readFile`
   (`internal/httpapi/explorer.go:69-81`) returns the home-relative path
   (`projects/<dir>/foo`) without stripping the scope prefix; Save round-trips
   it through `scopedPath` which prefixes again → ENOENT → 400 "cannot write
   file". `listFiles` was already fixed for this exact bug (explorer.go:60-65);
   `readFile` was missed. Also poisons the viewer's Download link.
   Secondary: csrfGuard caps mutating bodies at 1 MB (server.go:409-413) while
   reads allow 2 MiB — files in between open editable but can never save.
2. **Cannot delete files** — not a bug: no DELETE endpoint, no UI. Rename and
   mkdir are missing too (server.go:243-252).
3. **Project deletion shows "Failed to fetch"** — client aborts all API calls
   at 20 s (`web/src/lib/api.ts:145`) while the server legitimately takes up to
   2 min tearing down a Kata VM on a detached context (server.go:626-633). The
   delete usually completes server-side; the UI lies. Same gap affects
   start/stop. Also: `Destroy` doesn't take the per-project lock that
   `EnsureRunning` holds → WS-reconnect race can recreate a container mid-delete.
4. **No .bashrc in terminals** — `ensureHome` (server.go:159-187) early-returns
   whenever the home dir already exists, so pre-existing/migrated homes never
   get dotfiles; and even when seeding runs, content is a fraction of the
   devbox predecessor's. Terminals ARE login shells (tmux `default-command
   "/bin/bash -l"`), so once `.profile`+`.bashrc` exist they get sourced.
5. **`?bytes=` on history read is unclamped** → multi-TB allocation attempt
   possible (explorer.go:181, history.go:115). Clamp it.
6. Native `alert/confirm/prompt` at 11 call sites (screenshot request: inline
   boxes instead) — `DeleteProjectDialog` is the in-repo pattern to generalize.

## 2. Facts established (answering the operator's questions)

- **conv-1/conv-3 in History** = tmux session names (`conversation.Prefix =
  "conv-"` + lowest-free-integer record ID). History = raw PTY transcripts
  piped via tmux pipe-pane to `~/.styrman/logs/<uuid>/conv-<n>.log`; agent
  activity is captured as terminal bytes (no structured capture). No search
  exists, server or client. Titles are never mapped back to friendly names.
- **Clips**: client-only, sessionStorage, max 30, 1-hour TTL — deliberately
  ephemeral because copy-on-select can capture OAuth tokens (ADR-023/R10).
- **Git checkpoints** trigger on: stop, terminal pause/delete/delete-all,
  pre-restore, manual. No timer, no watcher; idle-reaper stop takes NO
  checkpoint (known TODO).
- **Link lifetimes (item 17) already match the ask**: public = TTL enforced on
  every request; private = never expires, dies only when the share list empties
  or the project is deleted (verified in `internal/links/store.go:48-56`).
- **User-access allowlist (item 12) is load-bearing**: `authGuard` checks
  `IsAuthorized(email)` on every request in header mode — it is how family
  members get in. Removing it entirely would change R8/scale targets.
- **apt installs** survive stop/start (rootfs persists) but are lost on
  container REMOVE (project delete, guest-username change, image upgrade).
- **Storage**: one bind mount per VM (the user home). Projects are separated
  by convention only (`~/projects/<dir>`, `~/.dockerd/<uuid>.img`). Adding a
  second per-project bind is straightforward at the mount layer
  (orchestrator.go:384-386) but touches files-API scoping, checkpoints paths,
  wipe list, entrypoint, boot sweep.

## 3. Research digest

**Design (internet research):** Material 3 is fully token-driven; the 2026
Google look = surface-container tonal ladder instead of borders/shadows,
generous radii (8/12/16/28 + pills), state layers (hover 8%), 3-state theme
toggle (light/dark/system). **Google Sans Flex (UI) and Google Sans Code
(mono) are now OFL open source and on Fontsource** — the literal Google
pairing is self-hostable (no CDN). Terminal needs a PAIRED ANSI palette
(one per theme), background bound to the surface token. Reference UIs:
Google AI Studio (shell layout: icon rail → collapsible sidebar → main →
right panel), Warp (terminal blocks + theme architecture), Linear (density
and restraint to temper M3's playfulness).

**Competitors (internet research):** Coder, Ona (ex-Gitpod), Codespaces,
Daytona, DevPod, E2B, Replit, CodeSandbox SDK, Fly Sprites. Top adoptable
ideas for a single-user platform: idle auto-stop with activity bump driven by
terminal I/O; golden snapshots / warm VM pool of 1; checkpoints that include
`~/.claude` so rollback restores agent memory; dotfiles repo auto-apply;
devcontainer-style lifecycle hooks vocabulary (onCreate/postStart) = the
autostart feature; per-port sharing levels (already have); agent status
dashboard; asciinema-style session recording; platform API as MCP server;
three-stage lifecycle stop→archive→delete.

## 4. Decisions

### Decided by operator list (no further input needed)

- D1. Rebrand UI to **crew**: real SVG mark + wordmark, document title, real
  favicon link (current favicon.svg is an unreferenced TanStack template
  leftover; no <link rel=icon> exists at all).
- D2. Remove the permanent "run claude or agy here" header hint
  (p.$project.$term.tsx:58-60).
- D3. Terminal creation: generate a friendly name immediately; rename inline
  later (sidebar + header).
- D4. Remove the LINKS chip bar (TerminalPane.tsx:254-294) — superseded by
  drag-to-copy; it mostly harvests junk apt URLs.
- D5. History: map transcripts to friendly terminal titles; add search.
- D6. Files panel: bigger real buttons (SVG icon set), add delete/rename/
  new-folder end-to-end, fix the save bug, crumb shows friendly name; main
  header shows `<name> (uuid) / <terminal>`.
- D7. Rename Clips → Clipboard in the UI.
- D8. Replace all native popups with styled dialogs/toasts.
- D9. Seed rich dotfiles (devbox userprofile set) via image entrypoint
  write-once per file + fix ensureHome early-return (I15 direction).
- D10. Editor: markdown rendered preview + JSON/YAML viewers (within R4
  "lightweight viewer" ceiling).
- D11. Async project delete (202 + poll) so slow Kata teardowns don't fake-fail.
- D12. Item 17 needs no backend work (already behaves as requested); surface
  the lifetime rules in the share UI copy.

## 4b. Operator answers (2026-08-28) — decisions FINAL

- Q1 **M3 + Linear density approved**, PLUS new requirement: responsive design —
  desktop is primary, but the app must work as well as possible on phone and
  tablet (collapsible sidebar/drawer, touch-friendly terminal, adaptive panels).
- Q2 Google Sans Flex + Google Sans Code approved (self-hosted).
- Q3 "crew" alone + SVG mark/favicon approved.
- Q4 Operator confirmed the real model: ONE full platform user; family access
  happens via share links (private shares work for non-users — authGuard exempts
  shared paths). Decision: **remove the Admin "User access" UI section**; keep
  the auth-path enforcement + env-provided allowlist untouched (no REQUIREMENTS
  change — mechanism stays, runtime user-management UI goes).
- Q5 Per-project storage dir approved.
- Q6 Timer checkpoints approved — manual checkpoint MUST remain available
  (it already exists: POST /checkpoints + side-panel button; keep it).
- Q7 Manifest approach approved. Additionally: enrich the base image toward the
  old devbox toolset (gaps found: bash-completion, lsof, mtr, traceroute,
  net-tools, python-is-python3, gettext-base, openssl). The existing
  `/etc/styrman-base-packages` snapshot is the diff base for the manifest
  (devbox had the same concept). Per-project manifests replayed on boot.
- Q8 **Autostart is per TERMINAL, not per project** (operator call): a terminal
  record gets an optional command; it runs when the terminal's tmux session is
  created (first open, and after a VM restart when the session is recreated).
  Nuance accepted: it does not run headless at VM boot with no terminal open.
- Q9 Live tail preview cards approved.
- Q10 Clipboard stays ephemeral; rename only.
- Q11 Roadmap picks accepted: checkpoints incl. ~/.claude, platform API as MCP
  server, warm VM pool of 1 → record in TODO as post-v1.3.
