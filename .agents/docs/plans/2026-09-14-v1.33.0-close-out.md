## Interfaces

- `internal/config`: `func IPForwardOff(procPath string) (off bool, err error)`
  reads the file (default `/proc/sys/net/ipv4/ip_forward`), trims, returns
  `off = (content == "0")`; a read error is returned as-is. In
  `cmd/styrman/main.go`, right after `config.Load()` and only when
  `cfg.SelfContainer != ""` (a containerized server — host-mode dev runs in
  the host's netns where Docker itself needs forwarding on): if `!off` and
  `os.Getenv("STYRMAN_ALLOW_IP_FORWARD") != "1"` → `logger.Error("ip_forward
  is on inside the server container — it could route between project
  bridges (R12); fix the compose sysctl net.ipv4.ip_forward=0 or set
  STYRMAN_ALLOW_IP_FORWARD=1 to run without that guarantee")` and
  `os.Exit(1)`; with the override, one Warn line at boot (the
  `STYRMAN_ALLOW_UNSAFE_RUNTIME` shape). A read error is a Warn, not fatal
  (an exotic kernel must not take production down over a missing file).
  Config key added to the env table in `specs/styrman/deploy.md` and to
  `internal/config/config.go`'s comment block. Default compose already sets
  the sysctl; live pre-check before release:
  `docker exec styrman-server cat /proc/sys/net/ipv4/ip_forward` → `0`.
- Orchestrator fake: `fakeNetwork.subnet string`; `NetworkInspect` reports
  `IPAM.Config = [{Subnet: subnet, Gateway: gateway}]` when either is set;
  `NetworkConnect` records `NetworkConnect(<net>,<id>,ip=<IPv4Address>)`
  when `EndpointSettings.IPAMConfig` is non-nil, else the current two-field
  form (existing `callsTo("NetworkConnect")` counters keep working: `record`
  splits on the first `(`).

## Failure modes

- ip_forward on inside the container at boot: the server exits 1 with the
  Error above; the updater's health check then fails and rolls back to the
  previous version (versioning.md "If the deploy fails") — which is why the
  live pre-check runs BEFORE the tag. With the override: boots, one Warn.
- Static broker IP taken on attach: unchanged behaviour (dynamic fallback,
  Warn) — now pinned by a test.
- Docker Hub 429 during the gate: named as such; the tag is not pushed.
- e2e trap: unchanged behaviour; the format string is now parse-checked.
- Harness refresh: `deploy/verify-commit.sh` refuses a mirror whose
  `SHA256SUMS` or listed skill/agent counts disagree with the image.
