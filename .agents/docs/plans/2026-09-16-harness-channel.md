# Plan — Host-side, signature-gated harness channel   (2026-09-16)

## Why
Today a change in styrman-harness reaches a crew project only through a crew release: a hand refresh of the mirror `image/harness/` (VENDORED.md), a gate, a tag, a deploy, a re-seed (ADR-062: the image is the delivery path). The operator wants to develop in styrman-harness and argolis-devbox and have crew follow automatically ("It would be better if we could focus on the styrman-harness and argolis-devbox and styrman-crew gets updates automatically", 2026-09-16), with the VM still git-free and offline. styrman-harness now defines its side: annotated `vX.Y.Z` tags on `main`, SSH-signed with the operator's ed25519 key (its ADR-026, `deploy/remote.md` § Releases); its security review asks the consumer to walk the version sort downward to the newest tag that verifies, alarm on every refusal, and refuse a version below the installed one. Recon: `plans/2026-09-16-recon-harness-channel.md`.

## Scope
In: (1) a `harness` mode of `deploy/update/styrman-update` with its own timer unit — fetch the harness repo, walk `vX.Y.Z` downward to the newest tag that verifies (`verify_tag`), never below the installed version, alarm on every refusal, export a plain copy plus a built `sh-agent` under `/var/lib/styrman/harness/<commit>/`, smoke it inside the deployed runtime image, swap `current` atomically, latch a tag that fails; (2) `styrman-ctl` and `host-setup.sh` wiring: the content dir, the root clone `/opt/styrman-harness`, a second read-only GitHub token (the harness repo is private), the unit, a `status` line; (3) the server: `STYRMAN_HARNESS_DIR`, two read-only binds into every project VM when `current` exists, a trusted-dir check, the image copy as fallback with a WARN; (4) the entrypoint: the re-seed stamp keys on image version plus harness commit, the deployed line names the source and tag; (5) tests at every tier (shell tests for the channel unelevated against scratch dirs, Go unit tests, Tier 2 section against a scratch channel); (6) docs, R5 amendment, ADR-073, then `/preflight v1.35.0`.
Out: removing `image/harness/` and its refresh procedure (a follow-up after the first live delivery); `sh-agent update --release` for operator machines (the harness's own follow-up); a harness-version line in the Settings page; forcing running VMs to restart on a harness swap.
Follow-ups noted, not built: remove the mirror and `VENDORED.md` § Refresh once `styrman-ctl status` has shown a delivered harness on the production host; the Settings page line; `sh-agent update --release`.

## Interfaces
- **Invocation:** `styrman-update harness [--check] [--force]`, root, from `styrman-harness-update.service` (timer `OnBootSec=7min OnUnitActiveSec=5min RandomizedDelaySec=60`, offset from the crew updater's 5/5). Env pinned in the unit, none defaulted in the script (ADR-052): `STYRMAN_UPDATE_STATE_DIR=/etc/styrman/update` (shared with the crew updater; files `harness-version`, `harness-sha`, `harness-failed-version`, `harness-refused`), `STYRMAN_HARNESS_REPO_DIR=/opt/styrman-harness` (a root clone of `https://github.com/kesokaj/styrman-harness.git`), `STYRMAN_HARNESS_DIR=/var/lib/styrman/harness` (content root, root 0755; refused unless a dedicated nested path, never `/var/lib/styrman` itself), `STYRMAN_HARNESS_GH_TOKEN_FILE=/etc/styrman/gh-token-harness` (root 0600; read the way `STYRMAN_GH_TOKEN_FILE` is; absent means an anonymous fetch, which fails on the private repo with the same "mint a fine-grained token" message), `STYRMAN_DEPLOY_DIR=/opt/styrman` (the crew checkout at the deployed tag: the Go builder pin is read from its `image/Dockerfile` `harness-builder` FROM line, as `deploy/vulncheck.sh` reads `Dockerfile.server`'s), `DOCKER_CONFIG` as the crew unit sets it. `--check` reports the decision and changes nothing; `--force` re-exports the installed tag.
- **Selection (new function `harness_select`):** after `git fetch --tags --force --prune --prune-tags origin`, candidates are `git tag -l 'v*' | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | sort -Vr`; `INSTALLED` is `harness-version` (validated by the same shape regex, else ignored) or `none`. For each candidate, newest first: if its version is not greater than `INSTALLED` (`sort -V` order; equal counts as not greater), stop — and if it is the newest candidate and below `INSTALLED`, alarm `REFUSED: newest tag <t> is below the installed <i> (a deleted or moved tag?) — keeping <i>`; if it equals `harness-failed-version`, skip with a log line; `verify_tag <t>` — on refusal, alarm and continue to the next; on success it is the selected tag. No candidate selected: exit 0 with `harness: nothing newer than <i> verifies` (an alarm was already raised for each refusal) — or `harness: no vX.Y.Z tag yet — waiting for the first signed release` when there are no candidates at all (not an alarm).
- **Alarm (new function `harness_alarm <tag> <reason>`):** one `log "REFUSED: …"` line to the journal (the timer's stderr) and one line `<date -u> <tag> <reason>` appended to `harness-refused` (root 0644, capped at the newest 50 lines). `styrman-ctl status` prints the file's newest line as `harness    REFUSED <tag>: <reason>` and the verdict is DEGRADED while the file is newer than `harness-version`.
- **Export (new function `harness_export <tag>`):** commit `c=$(git rev-parse <tag>^{commit})`; into `${HARNESS_DIR}/.tmp-<c>/`: `repo/` from `git archive <tag> | tar -x`, minus `.agents/`, `.gitignore` and any `.git` (the mirror's own exclusions, VENDORED.md), then `repo/COMMIT` (full sha), `repo/TAG` (the tag), `repo/SHA256SUMS` (`find . -type f ! -name SHA256SUMS | sed 's#^\./##' | LC_ALL=C sort | xargs sha256sum`, the mirror's recipe); `bin/sh-agent` built by `docker run --rm --user 0 -v <tmp>/repo:/src:ro -v <tmp>/bin:/out <golang pin from image/Dockerfile> sh -c 'cd /src && CGO_ENABLED=0 GOTOOLCHAIN=local GOPROXY=off go build -trimpath -ldflags="-s -w" -o /out/sh-agent ./cmd/sh-agent'` (the harness has no dependencies, so the build is offline); every file root-owned, dirs 0755, files 0644, `bin/sh-agent` 0755; `find <tmp> -type l` must be empty and `<tmp>/repo/.git` absent.
- **Smoke (new function `harness_smoke <tmp>`):** `docker run --rm --user 1000:1000 -e HOME=/home/u -v <tmp>/repo:/styrman/harness:ro -v <tmp>/bin/sh-agent:/styrman/bin/sh-agent:ro -v <scratch home>:/home/u --entrypoint sh styrman-runtime:<deployed crew version, from deployed-version> -c '/styrman/bin/sh-agent list && /styrman/bin/sh-agent install --dry-run --repo /styrman/harness --home /home/u'` — both exit 0; the `list` output's `Skills (N)` / `Subagents (M)` lines are logged, never asserted against a number. A smoke failure: `harness_alarm <tag> "smoke failed: <last line>"`, latch `harness-failed-version=<tag>`, remove `<tmp>`, and continue the walk downward.
- **Swap:** `mv <tmp> ${HARNESS_DIR}/<c>`; `ln -s <c> ${HARNESS_DIR}/current.new && mv -T ${HARNESS_DIR}/current.new ${HARNESS_DIR}/current` (one rename); write `harness-version` and `harness-sha` (temp file + rename, as the crew state files); clear `harness-failed-version`; keep the previous `<commit>` dir, remove older ones. Log `harness: <tag> (<c7>) is current`.
- **Test mode:** `STYRMAN_UPDATE_TEST=1` lets `harness` run unelevated ONLY when every path is a scratch path — `STYRMAN_UPDATE_STATE_DIR`, `STYRMAN_HARNESS_DIR` and `STYRMAN_HARNESS_REPO_DIR` all outside `/etc`, `/var/lib/styrman`, `/opt` — and `STYRMAN_ALLOWED_SIGNERS` names a file the test user owns (the `__verify-tag` hook's existing relaxation); the docker steps run as the test user's docker access; the runtime image for the smoke is `STYRMAN_HARNESS_SMOKE_IMAGE` (test) instead of the deployed version (production ignores the variable unless `STYRMAN_UPDATE_TEST=1`).
- **Server:** `config.Config.HarnessDir string` from `STYRMAN_HARNESS_DIR` (default empty). In `createContainer` (before `ContainerCreate`): `src := filepath.Join(cfg.HarnessDir, "current")`; `harnessBinds(src) ([]string, error)`: `os.Stat(src)` — not exist → `nil, nil` (fallback, one WARN per server start: `harness channel absent at <src>; the image's baked harness seeds projects`); exists → resolve `filepath.EvalSymlinks(src)`, require it to be inside `cfg.HarnessDir`, a directory, uid 0, mode without group/world write, with `repo/COMMIT` and `bin/sh-agent` present — any failure → `nil, fmt.Errorf(...)` and the create logs a WARN and uses the fallback (availability over a refused boot; the dir is root-written); success → `[]string{src + "/repo:/styrman/harness:ro", src + "/bin/sh-agent:/styrman/bin/sh-agent:ro"}` appended to `Binds` (the unresolved `current` path, so Docker re-resolves it on every start — a stopped VM picks up a swapped harness on its next start, like an image upgrade). The setup VM (`MINIMAL`) gets no harness binds. At server start: `INFO harness channel: tag <TAG> commit <COMMIT> at <src>` or the WARN above. The image-upgrade recreate is unchanged.
- **Entrypoint:** `HARNESS_COMMIT="$(cut -c1-40 /styrman/harness/COMMIT 2>/dev/null || echo unknown)"`; `HARNESS_ID="${HARNESS_VER}+${HARNESS_COMMIT}"`; the stamp compares to `HARNESS_ID` and is written as `HARNESS_ID` (an old stamp holding only the version differs → one re-seed on the first boot after this release; idempotent). The pass line becomes `agent harness deployed (version ${HARNESS_VER}, styrman-harness <sha7>, source ${SRC}; browser MCP registered for claude and agy)` where `SRC` is `channel tag <TAG>` when `/styrman/harness/TAG` exists, else `image`. `sh-agent install`'s `--repo /styrman/harness` and the binary path are unchanged.
- **styrman-ctl:** `setup_auto_update` also asks for the harness token (`gh-token-harness`, root 0600), clones `/opt/styrman-harness` (https, the scoped helper), creates `/var/lib/styrman/harness` (root 0755), installs `styrman-harness-update.{service,timer}` and enables the timer; `status` gains one line: `harness    <harness-version> (<sha7>)    /var/lib/styrman/harness/current` or `harness    waiting for the first signed styrman-harness tag` or `harness    REFUSED <tag>: <reason>` (DEGRADED). `host-setup.sh` creates the content dir. The updater's `self_install` also installs the harness unit pair from the verified crew tree (so a crew release changing them converges), and `host_converge` enables the harness timer unconditionally (BUG-035).
- **Compose:** server env `STYRMAN_HARNESS_DIR=/var/lib/styrman/harness`.

## Failure modes
- Fetch fails (token missing/expired, network): `FATAL git fetch failed — root cannot reach /opt/styrman-harness's origin. For a private repo: mint a FINE-GRAINED GitHub token (this repo only, Contents: Read-only) and install it at /etc/styrman/gh-token-harness` (the crew updater's message shape); nothing changes; `status` shows the last good harness; the timer retries next tick.
- No tag yet: `harness: no vX.Y.Z tag yet — waiting for the first signed release`; exit 0; not an alarm; `status` says waiting; projects seed from the image.
- Newest tag lightweight / not SSH-signed / signed by an unlisted key: `REFUSED: <tag> …` (the `verify_tag` reasons), the next lower candidate is tried; the alarm marker is written; `status` DEGRADED until a newer tag is installed.
- Newest tag below the installed version: refused, alarm, installed kept.
- Verified tag whose export or smoke fails: alarm, `harness-failed-version` latched, the next lower verified candidate above the installed one is tried; a newer tag clears the latch; `--force` retries the installed tag only.
- `current` swapped while a VM runs: the running VM keeps its mounted dir (kept on disk as the previous dir) until its next stop/start; on that start Docker re-resolves `current` and the boot re-seeds.
- Channel dir absent or untrusted at container create: WARN, the image's copy seeds; the API and UI show nothing different.
- Runtime image for the smoke missing on the host (a fresh host before its first crew deploy): smoke fails → alarm; the next crew deploy fixes it; `status` shows why.

## Verification
Tiers: unit (Go: config, `harnessBinds` with a temp dir; shell: `deploy/update/harness-channel-test.sh` against scratch repos, keys and dirs, unelevated) / integration (Tier 2: a scratch channel built by the test helper before the server starts, the server started with `STYRMAN_HARNESS_DIR` pointing at it, a real Kata boot) / e2e (the deployed host: the timer's first tick logs the waiting line, `status` says waiting, a project boot logs `source image`; the first signed harness tag is the operator's and its delivery is observed after it).
E2E criteria: (golden) on a host with a harness `current`, a new project's boot log names the channel's tag and commit and `sh-agent status` in it reads 27 skills / 7 agents with no drift; (edge) with a lightweight `v9.9.9` pushed above a signed `v1.0.0`, the channel installs `v1.0.0`, the journal carries `REFUSED: v9.9.9 is a lightweight tag`, and `styrman-ctl status` is DEGRADED naming v9.9.9; (edge) with no `current`, a project boots and seeds from the image and the server log says the channel is absent.

## Risks
Assumptions: (a) `docker run` of `golang:1.25.13-trixie@sha256:…` builds `cmd/sh-agent` offline from a plain copy — checked by the Phase 1 test's export step (`GOPROXY=off`); (b) a bind whose source path contains a symlink component (`current`) is re-resolved by Docker on every container start — checked in Phase 3 by swapping the scratch `current` between a stop and a start and reading the guest's `COMMIT` (the recon cites Engine 29.7.2 re-resolving bind sources on start); (c) the `styrman-runtime` image runs `sh-agent list` as uid 1000 with the harness mounted read-only — checked by the Phase 1 smoke; (d) the harness tag's `git archive` minus `.agents/` and `.gitignore` equals what VENDORED.md's rsync produces — checked in Phase 1 by comparing the export of the mirror's own content with `image/harness/` (`diff -rq`, only `TAG` extra); (e) the crew updater's state dir may hold the harness files without confusing `styrman-update`'s own reads — checked by grepping its reads (`deployed-version`, `deployed-sha`, `failed-version` only).
