# v1.19.0 — security hardening, dead code removal, toolchain pinning, and coverage     (date: 2026-09-02)

## Summary

v1.19.0 is a composite release closing **security findings from the 2026-09-01 whole-project audit**, **operator directives**, and **standing coverage gaps**, shipped as three bundled commits.

**Cross-tenant deletion vulnerability (CRITICAL, fixed):** `sweepMaterializedFile` (`internal/httpapi/credentials.go:217`) validated the deletion path using `filepath.Rel`, which symlinks defeat — a symlinked `~/.config` to another tenant's home would cause a credential revoke to delete THEIR file instead. Project homes are bind-mounted into microVMs where the guest is root, so a compromised guest could mount a cross-tenant link and escalate. Now `files.Remove`, a new helper, confines the operation to `os.Root` — a verified safe boundary that `filepath.Join` + `os.RemoveAll` cannot cross. Regression test plants exactly that symlink and confirms it is rejected. Closes ADR-001's containment model assumption.

**Containment asserted, not assumed:** `STYRMAN_RUNTIME` was an unvalidated free string (defaulting to `mvm`) while every project container receives `CapAdd: SYS_ADMIN` + `apparmor=unconfined` (`internal/orchestrator/orchestrator.go:759`) — safe ONLY because Kata is the boundary. `config.Load` (line 211 onward) now allowlists VM runtimes (`mvm, kata, kata-runtime, kata-qemu, kata-clh, kata-fc`), refusing non-VM runtimes at startup unless `STYRMAN_ALLOW_UNSAFE_RUNTIME=1` is set (which logs a loud warning to stderr). Closes ADR-001: a microVM is a precondition, not a nice-to-have. (ADR-060)

**Egress filtering tightened:** `deploy/host-setup.sh` egress deny-list gains `100.64.0.0/10` (Tailscale/CGNAT) and `198.18.0.0/15` (TEST-NET-2). Closes a whole-project audit finding.

**Dead code removed:**
- `usernameFromEmail` (`internal/config/config.go:392`) duplicated `identity.DeriveUsername` on a false import-cycle justification, diverging auth paths into two state dirs. Deleted; auth paths now converge on the single `identity` function.
- `Project.Agent` and `Project.GitInit` fields dropped from the project API (the create request still accepts and ignores them for backward compat); `Orchestrator.LastActivity` (unused field) removed. The API drop is why v1.19.0 is a MINOR bump, not PATCH. Dead code sweep from the 2026-09-01 audit.

**Toolchain hardening — Helm removed, signatures verified:**
- **Helm install deleted entirely** (operator directive). It installed via `curl … get-helm-3 | bash` from a moving branch, as root, at image build time — a supply-chain risk no project uses. Operator decision (2026-09-02): remove it, pinning the remaining tools exactly instead.
- **OpenTofu, yq, Caddy now digest-pinned:** New `deploy/install-tools.sh` (sourced from `image/Dockerfile`) pins OpenTofu and yq to exact versions with sha256 cross-checked against the publishers' own release pages. Caddy base images (`caddy:2.11.4-builder`, `caddy:2.11.4`) gain digest pins (`sha256:...`) alongside tag pins, closing the "tag → image" non-determinism that breaks rollback. The go toolchain version inside `deploy/caddy/Dockerfile` is asserted via `go version -m` on startup.

**Unsaved editor edits no longer lost on terminal switch:** The draft buffer now lives in the per-terminal pane store (keyed by terminal ID) and is restored only for the file it belongs to. Opening another file or closing the editor still prompts to save; switching terminals now preserves the draft. Closes a 2026-09-01 review finding (`.agents/docs/reviews/2026-09-01-review-editor-ux.md`).

**`uploadFiles` gains OAuth and abort handling:** `web/src/lib/api.ts`'s `uploadFiles` was the only API call bypassing `request()`, so it got neither 401/OAuth-redirect handling nor the abort timeout. An expired session mid-upload redirected to the login portal; `res.ok` remained true but `res.json()` failed, and the `.catch(() => ({}))` fallback reported silent success. Now `uploadFiles` calls `request()` like every other API call, routing 401s through `reAuthOnce()` and respecting the 30s abort timeout.

**Frontend unit tests (vitest, 11 tests) + Go format/identity tests exist at all now:** The frontend had zero across 8,254 LOC; it now has 11 vitest tests in `web/src/lib/api.test.ts` (8 tests for `projectNameFromRepoURL`, `cloneURLError`, `projectNameError`) and `web/src/lib/editorPane.test.ts` (3 tests for `basename`). Note: `editorPane.test.ts` deliberately does NOT unit-test the pane store's draft buffer behavior (its state is a non-exported module-level Map), deferring to e2e coverage rather than asserting `true === true`. `internal/httpapi/format_test.go` adds Go tests for `TestFormatInPlace`, `TestFormatAndCheckAgreeOnGo`, `TestSafeSuffixStripsEverythingButAlnum`, and `TestFormatScriptReadsAnExactByteCount`. `internal/identity` — which owns the tenancy key — was untested; it now has tests confirming `DeriveUsername` determinism and the drift-fix (deleted `usernameFromEmail` divergence). Closes a 2026-09-01 whole-project audit coverage gap (🟢 priority).

**PUT .../file?create=true for create-only (O_EXCL) atomicity:** A raw API caller could truncate an existing file via `PUT .../file` with the same `name=` parameter used for reading. New `?create=true` query param maps to O_EXCL; the endpoint now refuses to overwrite, making file creation explicit and safe from TOCTOU.

**Updater state-dir guard (ADR-052 tightened):** `STYRMAN_UPDATE_STATE_DIR` validation now refuses `/` and common top-level dirs (`/etc`, `/var`, `/tmp`, `/opt`, `/home`), requiring at least two path components. A typo like `STYRMAN_UPDATE_STATE_DIR=/etc` instead of `/etc/styrman/update` would otherwise silently write deploy-state into a shared system dir, making the host "never deployed." Closes a 2026-09-01 round-3 re-review finding.

**Non-wipe delete no longer strands credentials:** `projectHome.Delete` without `wipe=true` now cleans up materialized SSH keys from provisioning (the readiness probe and repo clone both run login shells inside the guest, materializing the user's key into the project home before any terminal opens). Closes a 2026-09-02 security review finding.

**`deploy/vulncheck.sh` now runs standalone:** It used to exit 125 in runc if `deploy/.env` was missing (a build artifact in this repo, not shipped). Now it exits with 3 (govulncheck CALLED findings) or 0 (clean), with no gitignore-dependent files required. Baseline today: two docker/docker CALLED vulnerabilities, both unfixed upstream (`GO-2026-4887`, `GO-2026-4883`), accepted per ADR-055 TODO.

**Small fixes:**
- `chipLabel` walks up directory hierarchy until the basename becomes unique, not just one level.
- The open explorer row gained its missing `hover:` class (v1.17.2 contrast fix left this one out).
- E2E recents check restores the real `styrman.recentFiles` localStorage key instead of leaving 20 junk entries.
- No more duplicate tmux resize frames on Editor↔Terminal toggle (the 120ms debounce now takes effect).

## Verification

**Security/containment:**
- Cross-tenant symlink test plants a symlinked `~/.config` to another home and confirms `files.Remove` rejects it (symlink not followed).
- Runtime validation test confirms config.Load refuses non-VM runtimes at startup.
- Egress deny-list confirmed in `deploy/host-setup.sh` output (two new CIDR blocks).

**Dead code:**
- `usernameFromEmail` grep finds zero references; auth paths use `identity.DeriveUsername` exclusively.
- No references to `Project.Agent`, `Project.GitInit`, or `Orchestrator.LastActivity` in working tree.

**Toolchain:**
- `deploy/install-tools.sh` sourced by Dockerfile; sha256 sums verified against OpenTofu/yq release pages.
- Caddy digest pins extracted from image manifest (`docker inspect caddy:2.11.4` confirms digest).
- `go version -m` assertion in Caddy build logs confirms Go toolchain version.

**Frontend/UX:**
- Vitest suite runs and passes all 11 tests; `nyc coverage` reports >80% on tested modules.
- Draft buffer keyed by terminal ID survives switch; opening a different file still prompts.
- `uploadFiles` calls `request()` directly; expired session triggers OAuth re-auth (manual test).
- Open explorer row has `hover:` class in HTML output; `chipLabel` uniqueness test passes.

**E2E:**
- Recents check passes; localStorage restored post-test.
- File creation with `?create=true` returns 409 on existing file name; 201 on new.
- Deletion without `wipe=true` cleans materialized SSH keys (manual verification: `ls ~/.ssh` in project home post-delete shows key gone).
