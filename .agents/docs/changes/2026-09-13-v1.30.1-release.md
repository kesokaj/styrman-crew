# v1.30.1 — Firewall degraded state and entrypoint stamp fixes (2026-09-13)

**PATCH.** Base `v1.30.0` (5393ef5). Range `v1.30.0..HEAD` (the release commit carries this entry) includes two fixes to
released behaviour (the firewall script's missing-`xt_physdev` state reaches its exit
path and `styrman-ctl status` reports it as DEGRADED; the guest entrypoint writes the
harness stamp without interpolating the version) and a developer-side helper
(`image/bump-pins.sh`) that adds nothing for a user of the released artifact. The rest
of the range is the operator's close-out: TODO and ROADMAP emptied, ADR-070 with the
reason for each struck item. Requested by the operator: "I approve all your
recommendations. If we pin stuff make it easy to upgrade. Do not overcommit, it
works."

## What changes for a user

- **Firewall degraded state:** when the host kernel lacks `xt_physdev`, the firewall
  script reports degraded via `warn()` (reaching the exit code instead of silently
  passing); `styrman-ctl status` now reads `enabled/failed` as DEGRADED (rather than
  OK). Because the oneshot now exits 1 on such a host, `deploy/firewall/install.sh`
  tolerates that exit and still enables the units (the auto-updater's host-converge
  already did), and the firewall suite (`deploy/firewall/test.sh`) keeps the exit
  status observable and asserts it both ways. Tests:
  `TestStyrmanCtlStatusFailedFirewallIsDegraded`, `TestFirewallScriptMatchesBridgePrefixes`,
  the firewall suite `PASS=26 FAIL=0`.

- **Guest entrypoint harness stamp:** the version and stamp path are now passed as
  arguments to `sh -c` (never interpolated into the shell code), blocking an injection
  vector if future code paths supply untrusted values. Test: integration check "harness
  stamp equals the image version after boot", `passed=92 failed=0`.

- **Bump helper** (`image/bump-pins.sh`): standalone script to refresh ADR-069 pins
  from publishers' sources and rewrite ARG lines and base-image digests in both
  Dockerfiles when run with `--apply` (developer-only).
