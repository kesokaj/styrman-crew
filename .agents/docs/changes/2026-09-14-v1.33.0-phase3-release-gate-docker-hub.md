# Phase 3: release gate and deploy guide — Docker Hub rate limit   (date: 2026-09-14)

## Summary

Phase 3 of the v1.33.0 close-out plan (item 2: BUG-056) detects Docker Hub anonymous pull 429 errors in the release gate and documents the `docker login` remedy. `deploy/verify-commit.sh` now wraps both image builds (server and runtime) in a `build_image` helper that captures full build output (stderr included) to a worktree log; on failure, if the output matches the 429 pattern (`429|toomanyrequests|Too Many Requests`, case-insensitive), it prints a dedicated message naming the rate limit and the remedy instead of a generic build failure, then exits 1. The tag is never pushed on a failed gate. `.agents/docs/deploy/remote.md` gained a new "Docker Hub (pull budget)" section documenting the anonymous budget (100 per 6 h per IP), which steps spend it (verify-commit's two builds, ensure-test-image, bump-pins manifest inspects, updater deploys), the gate's 429 detection, and the operator `docker login` option the updater already honours. BUG-056 status updated to fixed; login remains the operator's responsibility (recorded in the docs with the date once done).
