## Release notes
## New features
- The harness reaches every project as the sh-agent release binary carried by the runtime image (ADR-074) — `image/Dockerfile` downloads the styrman-harness release named by `ARG HARNESS_VERSION` (v1.6.0) from GitHub Releases at build with a docker build secret and verifies its signed checksums; the entrypoint installs it into each project home and never downgrades a home the user moved forward with `sh-agent update`, which is now the per-project update path; the image mirror (ADR-062) and the host harness channel (ADR-073) are deleted, and the updater sheds the channel's units and state from a host on every tick.
## Fixes
- The test suite's image builder had no build secret (BUG-066); the entrypoint's never-downgrade guard let an unreadable image release win and logged "deployed" after a skipped install (BUG-067); the release gate's shellcheck failed on unquoted `--secret` array elements (BUG-068) — all fixed before the tag.
## Other updates
- R5 rewritten (operator approval 2026-09-21), ADR-074; the harness channel's docs replaced by "Agent harness in the image (ADR-074)" in `specs/styrman/deploy.md`; Tier 2 now 115 checks.
## Install / update
The auto-updater deploys the signed tag within one tick; the host's crew token at `/etc/styrman/gh-token` must read `kesokaj/styrman-harness` (it does on this host). Running projects pick the new runtime image up on their next stop/start; a project updates its harness with `sh-agent update` in its terminal.

## Accepted, named here
- The token-selection branches at the four host/dev build sites have no live test beyond `bash -n`, shellcheck and the `styrman-ctl install --dry-run` plan; the Dockerfile path they feed is live-tested.
- The sh-agent binary shipped in the image is not vulnerability-scanned in this repository (the harness repository's gate scans it); follow-up: scan the downloaded binary.
