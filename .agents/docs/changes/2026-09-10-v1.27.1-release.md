# v1.27.1 — updater firewall idempotence   (2026-09-10)

A PATCH: one fix to the updater's `host_converge` script. Shipped in v1.27.0,
the boot-time firewall unit was enabled by the operator's `install.sh`; on
hosts that skipped that step or use a rolling auto-updater, the new script's
tick runs `systemctl enable styrman-firewall.service` on EVERY convergence
instead of only when the unit file changed. This release corrects the
convergence to check file mtime before re-enabling, restoring idempotence
(BUG-035 recurrence; rule `.agents/rules/mechanism-reaches-every-caller.md`).

Gated commit: `63aceb1`; the release commit carries this entry and gate artifacts.
Gate report: `reviews/2026-09-10-preflight-v1.27.1.md` (VERDICT: SHIP).

## What changed

**Updater firewall idempotence.** The `host_converge` script now records the
firewall unit file's mtime and re-enables the service only when mtime changes.
On every tick (default 5 minutes), the script runs to convergence; before this
fix, it re-enabled the already-enabled unit on each tick (no-op at the kernel
level but a sign of a mechanism reaching every caller when it should reach
once). The fix moves `systemctl enable` behind an mtime check, as other
deployment mechanisms in the script already do.
