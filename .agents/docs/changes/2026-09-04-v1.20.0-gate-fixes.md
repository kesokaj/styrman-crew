# v1.20.0 gate fixes: file listing, path confinement, test suite hardening     (date: 2026-09-04)

Date: 2026-09-04. Release gate browser e2e (round 1) failed 21 of 63 checks with every project listing coming back empty. Root cause: BUG-004, a regression in file enumeration below trust boundaries surfaced by Go 1.25's stricter `DirEntry.Info()` behavior on symlink targets — a quirk BUG-002's confinement model first encountered in the transcript janitor (fixed in isolation a day earlier). Pre-tag security and release review passes identified path confinement escapes in directory creation and test suite robustness gaps. All nits fixed before tag.

## 1. File listing below trusted roots (BUG-004 root cause)

`files.List` and `history.List` both enumerate entries below a trusted base using `DirEntry.Info()`, which fails on certain symlink-target mismatches under Go 1.25 — returning `os.ErrPermission` that both functions skipped silently, leaving callers with empty results. The fix: both now use `rt.Lstat(name)` through the root, bypassing `DirEntry` entirely. The transcript janitor (`internal/history`) had already been patched in isolation; `files.List` was missed.

**Tests added:**
- `internal/files/trust_test.go` — new `TestListWorksBelowATrustedBase` plants a real `.git` tree below a confined root and confirms listing succeeds and finds entries.
- `internal/history/search_test.go` — new `TestListBelowATrustedBase` verifies listing below a project-home root (`.styrman` metadata) works after Lstat fix.

**Integration suite updated:** `bash .agents/docs/testing/styrman/integration.sh` listing checks now assert a concrete entry (`.git` or `.styrman`) exists in the output, not just `grep -q entries` (which passed silently on an empty list). New count: 63 checks, same as before but tightened assertions.

## 2. Path confinement in directory creation (release review nits, 3 medium)

Two raw `os.MkdirAll` calls on guest-plantable paths escaped the confinement model:

- **Project-home creation (`internal/orchestrator`):** Now goes through `os.Root` at the base home, guarded by `files.MkdirAllPerm`. Guest cannot plant a symlink in an unconfined base.
- **HTTP API `createProject` path (`internal/httpapi`):** Workspace mount target inside project home now created via `files.MkdirAllPerm` at the confined root.
- **Workspace mount target:** Already bound by project-home confinement; now explicitly guarded.

Helper `mkdirAllConfined` introduced in `internal/files` to encapsulate the pattern: take an `os.Root` and guard all intermediate directory creation.

## 3. Raw `os.OpenRoot` in history replaced by `files.Trust` wrapper

`internal/history` opened project-home roots directly via `os.OpenRoot`, bypassing the confinement model. Now routes through `files.OpenRoot`, which enforces trust boundaries identically to the files package — consistency across all root-based access.

## 4. Integration test suite robustness (test harness fix)

`bash .agents/docs/testing/styrman/integration.sh` ran under `set -e`; a missing ready line (microVM boot race) could abort mid-suite and the EXIT trap exited 0. Now:
- Missing ready is tolerated (`|| true`), so latency check fails properly (as intended).
- An `aborted=1` flag is set on any abort; the summary line checks it and exits 1 if set.
- This prevents silent masking of transient boot races in CI environments.

## 5. Shell.html rebuild drift (informational)

`web/dist/client/_shell.html` drifts byte-for-byte on every rebuild while the file list remains equal (a build ID stamp in the HTML comments). Not a code change; reverted with `git checkout` and documented.
