# v1.42.3 — editor endpoints bounded, slot deadlines tested, harness made safe   (2026-10-05)

Gate: `.agents/docs/reviews/2026-10-05-preflight-v1.42.3.md` (SHIP, range
v1.42.2..2829e51). This release commit carries only records.

- **Editor file endpoints** (read, save, format, check) share 8 server-wide
  slots, taken before the body is read. A holder has 30 s to send its body and
  30 s to receive its response; both deadlines are tested on a real server.
- **History panel:** aborts its previous search.
- **host-setup.sh:** refuses an empty token file; `deploy/.env` is created
  600 and renamed into place.
- **Token docs:** a step-by-step snippet that names each outcome, and a token
  scope that names both repositories.
- **e2e harness:** requires `--base`, refuses a foreign status file, uses a
  private screenshot dir, and cleans up only its own networks.
- Entries: `changes/2026-10-05-1637-…`, `-1643-…`.

**Corrections to those entries:**
- "Every memory-heavy endpoint bounded" (1637) is false. The git endpoints,
  the file and transcript listings, and uploads are still unbounded (gate row
  1).
- "A trickled body no longer holds an editor slot" (1643) holds per request;
  a user can still keep the 8 slots busy by re-sending every 30 s (gate row
  2).

**Carried to v1.42.4:**
- a central byte budget for building JSON responses and decoding bodies, in
  place of more one-by-one slots;
- per-tenant slot accounting;
- the read deadline only on requests with a body;
- 408 for a body timeout;
- token-tooling and e2e lows.

No host step in this release.
