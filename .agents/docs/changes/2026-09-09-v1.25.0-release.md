# v1.25.0 — the network switch ships   (2026-09-09)

A MINOR: the per-project network switch now works and is two states (Sandbox
and LAN). The feature replaces ~3,500 lines of root-mediated machinery (ADR-065
and ADR-066, v1.23.0–v1.24.0) that was never applied on real hardware. ADR-067
ships its implementation, with three amendments and one correction, all
append-only. Net +1,800/−4,500 source lines.

Release commit: `b142106`. Gate report: `reviews/2026-09-09-preflight-v1.25.0.md`
(VERDICT: SHIP).

## What a user gets

Two states, toggled in Settings → Network.

**Sandbox** (default): internet only. The project's container is on a
user-isolated bridge with DROP rules for all private ranges.

**LAN**: the project is an ordinary machine on the host's network. It reaches
the LAN, the host itself (including sshd), host-published Docker ports; still
NAT-only outbound; other projects stay unreachable. Toggling REBUILDS the
container (home and workspace survive; ephemeral container state does not). The
UI states this clearly before and during the rebuild.

Admin-only to toggle; the owner may disable it at any time (rebuilds again).

## How it works

ADR-067 makes the network mode the **bridge interface name** the server picks at
`docker network create`. Sandbox projects get `sdb-<hash>`; LAN projects get
`lan-<hash>`. The host firewall matches interface names: Sandbox bridges
trigger DROP rules for private ranges, LAN bridges do not. Cross-project
isolation remains Docker's own per-bridge DROP. The server never touches
iptables.

The credential broker withholds the SSH key from LAN-mode projects (they would
pivot off sshd otherwise). The server enforces a 3-minute timeout on mode
toggles; if a rebuild hangs or fails, the operator stops and restarts the
project.

## Proven on hardware

`testing/2026-09-09-lan-mode-live.md`: two projects, all five verification
steps, R12 (cross-project isolation) held under the `cap_net_admin`
manual-route attack. `iptables -S` identical before and after the test run.

## Operator changes

From `deploy/remote.md`:

1. **Cleanup (optional):** an auto-updated host keeps the retired
   `styrman-firewall.path` unit and spool mount enabled but inert.
   `sudo bash deploy/firewall/install.sh` from `/opt/styrman` at the deployed
   tag removes them — cleanup, not a requirement. `/etc/styrman/firewall.conf`
   is left in place and no longer read.

2. **sshd hardening is now advice, not an enforced gate.** A LAN-mode project
   reaches the host's sshd with whatever auth it allows. This host currently
   accepts passwords — that is a choice the operator made earlier, and toggling
   LAN mode does not change the sshd config.

3. **Timeouts:** mode toggles are bounded server-side at 3 minutes. If a
   rebuild hangs, stop and restart the project from Settings.
