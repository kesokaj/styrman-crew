## What ships

An admin can allow ONE project at a time — each toggled separately, running
or stopped — to reach the operator's local network. The switch is at the top
of the Ports tab, off by default, and a danger dialog names the blast radius
before it flips. Root applies it in about 0.2 s. Still blocked for a
LAN-enabled project: the host itself, every other project, the ingress
bridge and the credential broker, host-published Docker ports, cloud
metadata and the tailnet; LAN hosts still cannot initiate connections in.
Access is by IP (guest resolvers stay 8.8.8.8/1.1.1.1), and the traffic is
masqueraded, so it reaches the LAN as this host's own address — a device
whose access list trusts this machine by IP admits every LAN-enabled
project.

The mechanism, in one line: the non-root server records intent and mirrors
it as an empty marker file named by the project uuid, then kicks a
root-owned spool; the root firewall script reconciles one head-of-chain
RETURN per (project, prefix) and writes a status file the UI derives its
honest state from. The server never touches iptables.

## Release gate

Two whole-range reviews on top of the per-phase ones, because the v1.22.0
gate had shown that per-phase reviews pass while a range review still finds
real defects. **0 high, 2 medium, 6 low. No blocking finding.** Five fixed
in the release commit, two rebutted in writing, one accepted:

1. FIXED (medium) — the allowance is masqueraded and that was never
   disclosed. Now stated in the confirm dialog, the guide and `deploy.md`.
   Deliberately NOT added to `REQUIREMENTS.md` R12, which needs the
   operator's explicit approval; the exact sentence is offered in the gate
   report.
2. FIXED (medium) — the testing README contradicted itself on the Tier 4
   count (86 in one place, the stale 82 in another; both wrong). Measured:
   85 check call sites, a green run on a firewall-hardened host prints 83
   passes plus the client-error gate and 2 auto-SKIP.
3. FIXED (low) — `install.sh` created and chowned a directory inside the
   server uid's own tree as root, which could only be narrowed, never
   closed. Root removed from that path entirely; the server makes the
   directory itself.
4. FIXED (low) — the one-time migration deleted the pre-chain rules before
   installing the replacement chains, contradicting the script's own
   never-delete-then-insert promise. Reordered.
5. FIXED (low) — a dead accessor in `internal/netpolicy`.
6. REBUTTED (low, raised by BOTH agents) — `STYRMAN_FIREWALL_DIR` defaults
   to the production path. ADR-052's no-default rule is about root-run
   programs; removing the default would invert a failure mode, since an
   empty value now means "remove every marker". Reasoning recorded in the
   field's doc comment.
7. REBUTTED (low) — `host_converge` skips silently when HEAD is not the
   deployed SHA. Already escalated by the version handshake into a red
   Settings row and a 503; the uncovered case is a script change without a
   version bump, now a TODO discipline item.
8. ACCEPTED (low) — `web/dist/client/_shell.html` carries a raw NUL and
   diffs as binary. Pre-existing generated build output, not BUG-007.
   Recorded in TODO.

## Operator action still required after this release

The updater verifies the signed tag, deploys the containers, and
`host_converge` then installs the firewall script and units. It deliberately
does not write the LAN definition. Once per host:

```bash
sudo bash /opt/styrman/deploy/firewall/install.sh
```

That discovers the LAN prefix, writes `/etc/styrman/firewall.conf` only if
absent, and mounts the bounded spool tmpfs. Until it runs, local-network
access reports as unavailable and every enable is refused with 503 — the
feature is inert, not half-open.

**The same run converges a pre-existing drift, which is NOT a finding of
this release and is NOT yet fixed:** the live host has carried a
2026-08-30 firewall script with four private-range DROPs since before this
work, while the repo has had six since 2026-09-02 (100.64/10 and 198.18/15
were added but never delivered, because nothing delivered host-setup
changes). Closing that delivery gap for good is what `host_converge` is for.

## Requirements

R12 as amended 2026-09-08 (ADR-065): the exception is admin-only, per
project, off by default, and fails closed; the cross-project guarantee,
`ip_forward=0` and the host-networking clause stay unconditional. The
enforcement clause now names the six dropped ranges (10/8, 172.16/12,
192.168/16, 169.254/16, 100.64/10, 198.18/15) where it previously said
"RFC1918 + metadata". No other requirement changed.
