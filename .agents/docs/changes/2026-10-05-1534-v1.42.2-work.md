# v1.42.2 work: v1.42.1 gate follow-ups   (2026-10-05)

Operator: "go v1.42.2". Answers rows 1–4, 6, 8 and 9 of
`reviews/2026-10-05-preflight-v1.42.1.md`.

- **History search is bounded server-wide** (row 1, medium). Past
  `searchConcurrency` = 4 searches in flight, `GET …/history/search` answers
  429 instead of queueing. Each search holds several MiB per transcript, and
  hundreds at once could OOM-kill the server under its 4g cap. Compose sets
  `GOMEMLIMIT=3GiB` for the server, so the GC works hard below the cap.
  - Tests: `history_search_limit_test.go`, red before the semaphore;
    `compose_oom_test.go` pins `GOMEMLIMIT`.
- **The git child's OOM reset is tested through `git()`** (rows 2 and 9).
  `TestGitResetsItsChildsOOMScore` raises the test's own score to 300 and runs
  a fake `git` on PATH that records its score; it reads 0. With the reset line
  removed it read 300 and failed. A failed reset is now logged (`slog.Warn`),
  not dropped.
- **The token never goes through sudo** (row 3). Checked on dave:
  `sudo --preserve-env=VAR` logs `ENV=VAR=<value>` in the journal, so
  v1.42.1's docs still leaked it. The deploy guides and `host-setup.sh`'s hint
  now write the token through stdin,
  `gh auth token | sudo install -D -m 600 /dev/stdin /etc/styrman/gh-token`,
  or use `styrman-ctl install --gh-token-file`.
- **The reaper's out-of-time return is tested** (row 4).
  `TestReapSetupVMsStopsWhenThePassIsOutOfTime` asserts the second stuck VM is
  not inspected; without the check it was, and the test failed.
- **ADRs** (rows 6, 8): ADR-084 is marked "Superseded by ADR-085". ADR-085
  amendment 1 corrects its rejected-alternative premise: the host shim wrapper
  could raise the VMs' score. That is not adopted, but noted as the cleaner
  later option.
- **e2e:** the alert printer labels its line "shown on the main page" (row 6).
- The testing README's Tier 1 line names the new tests.

Diff read by me; the release gate reviews it. `go test -race ./...` exit 0.
