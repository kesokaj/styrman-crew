# v1.3 Phase 4 — platform: per-project storage, autostart, apt persistence, checkpoint timer

Date: 2026-08-28. Last of four v1.3 phases (plan §4b). Phases 1-3 =
74e40c8, 64054bb, 1f93063.

## Summary

- **Per-project workspace storage (Q5, ADR-027)**: every working tree now
  lives in its own host dir `StateDir/projects/<user>/<uuid>`, bind-mounted
  into the microVM at `~/projects/<dir>` (in-guest paths unchanged; home
  stays shared per R3). One boot sweep migrates existing workspaces by
  same-filesystem rename (idempotent; a both-exist conflict is skipped
  loudly). The files API's project scope roots its os.Root at the workspace
  itself — strictly better confinement (project scope can no longer reach
  the home at all); the managed-path guard keys on scope, not prefix. Git,
  checkpoints, diff, wipe, and the R13 sweep all address workspaces via the
  one `cfg.ProjectWorkspace` helper. The orchestrator creates the dir
  before binding (Docker would auto-create it root-owned).
- **Per-terminal autostart (Q8, operator call)**: a terminal record carries
  an optional `command` (PATCH `{"command"}`, one line ≤500 chars, `""`
  clears). It runs when the tmux SESSION is created — first open, and
  re-opens after pause/VM restart; `tmux new -A` reattach never re-runs it
  — then drops to the login shell. UI: the sidebar pencil opens a
  name+autostart dialog; a bolt icon marks terminals with one.
- **apt persistence (Q7, ADR-028)**: at graceful shutdown the entrypoint
  records the dpkg delta vs the image's base snapshot to
  `~/.styrman/apt/<uuid>.list`; on boot a non-empty manifest replays in the
  BACKGROUND after the ready marker (boot SLA unaffected), logged to
  `~/.styrman/apt/<uuid>.log`. Wiped with the project.
- **Periodic checkpoints (Q6)**: `RunCheckpointLoop` snapshots every
  RUNNING project every 10 minutes (label "periodic"; tree-dedup makes
  unchanged trees no-ops). This also closes the idle-reaper gap — worst
  case loss is now one interval. Manual + event checkpoints unchanged.
- Unit tests no longer touch the host's real Docker daemon: the background
  project boot is skipped when no runtime image is configured (only true in
  handler tests; config.Load always sets one).

## Review fixes (reviewer subagent, same session)

Three blockers found and fixed:

1. **Failed migration silently became a permanent empty workspace**: after
   a rename failure, ensureRepos (and EnsureRunning) would create the new
   location empty, shadowing the real tree in the home forever. Now a
   `LegacyWorkspaceExists` guard makes BOTH refuse to create the new
   location while the old one still holds a tree (error + boot retry);
   migration failures are loudly logged, and a both-exist conflict warns
   with both paths instead of silently skipping.
2. **Migration under live microVMs**: project containers survive server
   upgrades (restart unless-stopped), so the sweep could rename a workspace
   out from under a running VM. It now runs AFTER the orchestrator exists
   and gracefully STOPS a running project before migrating it (skipping,
   loudly, if the stop fails).
3. **Pre-ADR-027 recreate used force-remove**, skipping the entrypoint's
   SIGTERM trap and tearing the loop-mounted ext4 down dirty. Now
   ContainerStop (30s grace) precedes the removal.

Should-fixes addressed: apt replay sets a `/run/styrman/apt-replaying`
marker so a shutdown during (or after a failed) replay keeps the existing
manifest instead of capturing a SHRUNKEN delta; autostart joins the command
and `exec bash -l` with a NEWLINE (a trailing `&` or `# comment` made `;` a
syntax error that killed the pane) — extracted to `autostartPaneCmd` with
unit tests; the checkpoint loop skips users with no state on disk (a stale
container label no longer fabricates a home) and gates on terminal activity
since the last snapshot (git add -A per idle tree every 10 min wasn't
free); the dead `prefix` plumbing in explorer.go is gone (scopeFor returns
just the root; logs carry the project id); stale comments/doc rows updated
(guide.md's backup table now names `/var/lib/styrman/projects/` — source
code no longer lives in the home!); integration.sh's workspace-path and
restore assertions fixed (one could no longer fail); per-user projects dirs
are 0700; apt-get gets `--`, per-boot log truncation, and tmp cleanup;
`renameTerminal` → `updateTerminal`; `hasWorkspaceBind` unit-tested (incl.
the uuid-prefix collision); the Image=="" boot-skip warns. Deferred, noted:
non-wipe deletes orphan the workspace dir invisibly (guide note; candidate
for a boot sweep), R3's wording now lags ADR-027 (REQUIREMENTS.md is
operator-approval-only — flagged to the operator instead of edited).

## Notes

- Home-scope file browsing shows `~/projects/<dir>` as empty mount points —
  workspaces are browsed via Project scope (documented in ADR-027).
- Production rollout: deploy the new server + image together. The workspace
  migration runs on first boot, and `EnsureRunning` auto-recreates any
  pre-ADR-027 container (detected by its missing workspace bind) on next
  open — without this, an old container would see an EMPTY ~/projects/<dir>
  after the migration. One-time cost: those containers' rootfs apt state is
  lost (the old entrypoint never captured a manifest).
