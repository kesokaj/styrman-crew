# v1.29.0 — Browser view review fixes (2026-09-13)

**MINOR.** Base `v1.28.0` (`eb7b883`). Range `v1.28.0..b6a287d` plus the
release commit (this entry, the gate report, the tier logs). Requested by
the operator: "make sure the code is excellent and works super optimized.
When done if you need changes do a minor and execute a /preflight and then
git commit push".

## What changes for a user

- **Browser pane, hidden:** switching to the terminal/editor/diff stops the
  screencast and pushes NO viewport onto the browser the agents share (v1.28.0
  forced a 320×200 floor on it every time); switching back resumes it. A
  terminal that never opened the browser holds no relay (v1.28.0 mounted a
  hidden pane — one relay, one launcher exec — on every terminal visited
  after the first browser use).
- **Browser pane, failures:** Retry after a failed launch calls the REST
  start first and shows the launcher's full 2 KiB log tail; the close frame
  itself now carries the END of that log (rune- and UTF-8-safe). An owner
  removed from the allowlist loses an open browser relay within 60 s (close
  4003, "Access revoked", no Reconnect). A guest frame over 16 MiB closes
  1009 "frame too large" (the branch existed in v1.28.0 but could never
  fire).
- **Browser pane, input:** AltGr characters type into the page (Ctrl+Alt is
  not a chord); a drag released outside the canvas no longer leaves the
  button stuck; mouse moves are coalesced to one per animation frame and a
  frame no longer re-renders the pane.
- **Relay:** frames are streamed 32 KiB at a time instead of materialized
  (up to 16 MiB each); one launcher exec per connect instead of two; the
  discovery request sends `Connection: close` so it never parks one of the
  guest forwarder's bounded children.
- **Launcher (`styrman-browser`):** the `mcp` verb no longer inherits the
  start lock, so a pane's start no longer waits 20 s and fails while an
  agent's MCP session is open; a server-run start whose server cannot
  learn its own bridge address fails closed (502 / 4004 with the reason)
  instead of starting a browser the pane can never reach; pid files that
  survive a VM restart are trusted only when the process is ours (comm and
  group predicate) and the forwarder counts as up only when the recorded
  socat holds the `:9222` listening socket itself (inode from
  `/proc/net/tcp{,6}`, matched in `/proc/<pid>/fd`); socat admits 16
  forwards, pinned to the server's per-user relay cap by a test.
- **Ports panel:** one guest exec per 7 s poll instead of two; the
  inner-docker half is bounded by `timeout 3` so a wedged dockerd cannot take
  the socket listing down.
- **`styrman-ctl`:** the global flags may precede the verb
  (`styrman-ctl --dry-run status`); `--confirm` without a value says so
  instead of exiting silently; an interrupted `update --setup` removes its
  root-only token temp dir and exits.
- **Integration runner:** refuses to start without `ss` instead of passing
  the port guard silently.
