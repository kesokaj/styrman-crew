# Harness v2.4.1 in the runtime image, its binary pinned by SHA-256 (ADR-090)   (2026-10-06)

Image change, unreleased: it reaches projects with the next crew release.

- **Why the bump needed a decision:** styrman-harness stopped signing releases
  (its ADR-053); v2.4.1 has no `SHA256SUMS.sig`, and `image/Dockerfile`
  required one (`ssh-keygen -Y verify` against `ARG HARNESS_SIGNER`). The
  operator chose to pin the binary's SHA-256 in crew ("Pin SHA-256
  (Recommended)"), recorded as ADR-090 (amends ADR-074).
- **`image/Dockerfile`:** `ARG HARNESS_VERSION=v2.4.1`, new
  `ARG HARNESS_SHA256=3031e27e…`; `HARNESS_SIGNER` and the signature download
  removed. The RUN step refuses a pin that is not 64 lowercase hex characters,
  then checks the `SHA256SUMS` version marker, that `SHA256SUMS` lists the
  pinned hash for `sh-agent-linux-amd64`, the bytes against the pin, and
  `sh-agent version`. `--repo` names the host (`github.com/…`).
- **Pin provenance:** the hash was confirmed by rebuilding the tag, not only
  read from GitHub: `v2.4.1` → `7ea90689ccb5`, clean clone, `golang:1.27.1`,
  `CGO_ENABLED=0 go build -trimpath -ldflags "-X main.version=v2.4.1"` gives
  `3031e27e…` bit for bit. The bump procedure (deploy.md, image/README.md,
  the Dockerfile comment) now edits both ARGs and repeats that rebuild.
- **R5 amended** (operator approved the exact text, 2026-10-06): the binary is
  verified against the pinned SHA-256, no longer "signed checksums … against
  the harness's signer".
- **Harness content:** 36 skills, 8 subagents, and the first rule
  (`critical-thinking.md`, installed to `~/.claude/rules/` and
  `~/.gemini/config/rules/`); `~/.claude/settings.json` still holds only the
  `attribution` key. Homes on v2.3.2 cannot `sh-agent update` to an unsigned
  release; the release carrying this image reinstalls v2.4.1 at each home's
  next boot.
- **Docs:** README.md, image/README.md, specs/styrman/deploy.md,
  specs/styrman/runtime-image.md, testing/styrman/README.md (Tier 5 intro,
  guard controls now the hash-pin controls, the roster line).

## Verification
- `verifier` (`testing/2026-10-06-verify-harness-v2.4.1.md`): PASS — Tier 2
  `integration.sh` `passed=146 failed=0 skipped=3` (matches the README count
  line) against `styrman-runtime:test` rebuilt from the tree, which printed
  `sh-agent v2.4.1`; `go build/vet/test ./...` green. That run predates the
  last RUN-step edit (the shape check and `github.com/` host), which adds
  preconditions only: the rebuilt `styrman-runtime:test` carries the same
  `/styrman/bin/sh-agent` bytes (`3031e27e…`), so Tier 2 was not re-run.
- Author's build controls (`.agents/scratch/harness-build*.out`): must-pass
  rc=0; must-fail rc=1 for an all-zero pin, an uppercase pin, an 8-character
  pin, and `HARNESS_VERSION=v2.4.0` without its hash.
