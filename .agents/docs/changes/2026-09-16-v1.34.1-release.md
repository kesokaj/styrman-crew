# v1.34.1 — Stop no longer lets Docker restart the guest's clean exit (BUG-063) (2026-09-16)

**PATCH**. Base `v1.34.0` (release commit `c1f7e31`, 2026-09-16). Range `v1.34.0..c26a723` plus the release commit: BUG-063 fix. No new endpoints, command-line flags, image or deploy-step changes. Web changes: none.

## What changes for a user

Stopping a project (the sidebar Stop button or the idle reaper) switches its container's Docker restart policy to `no` before the entrypoint is told to shut the guest down, so Docker no longer restarts the guest's clean exit. The next Start or terminal attach switches the policy back to `unless-stopped`, so a running project still restarts with the host. Before this, every Stop made the VM boot a second time one second after its shutdown and the real `docker stop` twelve seconds later hard-killed that second boot (exit 255, a dirty shutdown of the project's dockerd), while the server's docker inspects timed out — observed on the operator's project right after the v1.34.0 deploy. While stopped, `docker inspect` on the container shows exit code 0, `RestartCount` 0 and policy `no`. The integration suite asserts both halves (106 checks; green run: `passed=103 failed=0 skipped=3`).
