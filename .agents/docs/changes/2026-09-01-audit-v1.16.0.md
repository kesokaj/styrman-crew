## Why a whole-project audit, the same day as a diff-scoped release gate

Both 🔴s are in code **nobody touched today**. Today's release ran four
review rounds, three security passes and a preflight gate, and none of them
could have caught these — every one of them was scoped to the diff. That is
the justification for running a whole-project sweep in addition to a
release gate, not instead of one.

## The central finding: a recurring comment/code mismatch

Both 🔴s, and the 🟡 cross-tenant symlink deletion in `credentials.go`, are
the **same shape**: a comment asserting a safety property the code does not
actually have. That class was deliberately weighted into every scanner's
brief and produced 9 further instances beyond the three flagship cases.
This pattern, not any single finding, is the most useful result of the
audit for a future reader — it is worth grepping for the next time a
comment reads like a safety claim rather than a description.

## 🔴 High (both boundary-crossing, both untouched today)

1. **Unauthenticated Caddy admin API on host loopback**
   (`deploy/caddy/ingress/cmd.go`, `config.go`, `deploy/docker-compose.yml`).
   The generated global options emit no `admin` directive, so no origin
   restriction is applied; `CADDY_ADMIN` gets no loopback validation (unlike
   `STYRMAN_DEV_ADDR`, which `config.go:180` already refuses when
   non-loopback). The declared Caddy floor `v2.9.1` predates two CALLED
   admin-API CVEs — GO-2026-4537 (cross-origin `/load`, fixed 2.11.1) and
   GO-2026-5743 (`/config` authz bypass, fixed 2.11.3). This runs inside a
   `network_mode: host` container that also holds the Docker socket: one
   HTTP request to that port replaces the whole ingress config — and the
   ingress is the sole authority for `X-Caddy-Email` — so that one request
   forges any identity including admin, plus host root via the socket.
2. **Unbounded buffering of guest-controlled container logs**
   (`internal/orchestrator/orchestrator.go:1229-1234`). Logs are buffered
   into a `strings.Builder` under a comment claiming `Tail` bounds it —
   `Tail` bounds lines, not bytes, and the guest is root and picks the line
   length (2000 lines × 10 MiB ≈ 20 GiB). `exec.go:26-31` defends the
   identical threat with `cappedBuffer` and rates it H4/H7 ("without a cap
   one project could OOM the whole shared server") — the file next door
   already has the fix this file needs.

## What held up

Stated plainly, because an audit that only lists failures misleads: the
`authGuard` chain fails closed on unknown modes; `config.Load` refuses to
start in header mode without an ingress token; the ingress strips
client-supplied identity headers before injecting authentic ones;
`internal/files` is genuinely `os.Root`-confined at every entry point; link
tokens are 128-bit `crypto/rand`; nothing hand-rolls auth, crypto, or
sessions anywhere in the codebase; the tenant-merging username-slug
collision that would collapse two tenants is refused at both load and
`Add`; no secrets are committed; the API spec matches the code **in both
directions** across all 78 registered routes; and a test-theatre hunt
across ~20 sampled test functions across seven packages found no further
instances of the "passes while broken" shape beyond the two already fixed
earlier the same day.

## A finding surfaced by the audit's own activity

Production boots the mutable tag `styrman-runtime:dev`, and the testing
guide's own prereq step rebuilds that same tag. Following the documented
verification procedure re-stamped what production boots — it happened
during this audit (marker read `dev-1788269597` instead of `1.16.0`).
Restored to `1.16.0`, and an immutable `styrman-runtime:1.16.0` tag now
also exists. Documentation is being corrected in a parallel pass.

## Gap: an ungated module

`deploy/caddy/ingress` is a separate Go module **scanned by no existing
gate**. Running `govulncheck` there — done specifically for this audit — is
what produced the Caddy 🔴 and revealed the stale dependency floor.
Recommended: add that module to `/preflight`'s verification (also carried
into `TODO.md`).
