# v1.24.1 — the audit fixes reach production   (2026-09-08)

A PATCH, not a minor: everything in it fixes released behaviour, and nothing
adds a user-facing capability. That reading is the rule added to the harness
the same day, applied to its first release.

Audit and dispositions: `reviews/2026-09-08-audit-project.md`. Commits
`05db066`, `271a7e8`, `00dd134`, `80765ca`, `6e6c909`.

## Why this ships now rather than waiting

v1.24.0 shipped hours earlier and production did not have these. The one that
justifies the release on its own: **a cross-tenant denial of service.**
`internal/files` sets `O_NONBLOCK` on its opens and its comment says exactly
why — a guest-planted FIFO or device would otherwise wedge the goroutine
forever. Six sibling opens on the same guest-writable trees did not have it,
and `history.searchOne`'s `IsRegular` check sat *after* the blocking open, so
it never ran. Any project owner could plant a FIFO in their own home and pin
a goroutine **and an OS thread** per request, walking the runtime toward its
10k-thread limit — where process death takes every tenant with it.

Not remotely exploitable: it needs an authenticated project owner. But it is
a fix to live isolation code, and leaving it on `main` while production runs
without it is a choice nobody made deliberately.

## Also fixed

- The ingress wrote label- and env-supplied emails **verbatim** into the
  generated Caddyfile, in an internet-facing process running
  `network_mode: host` with the docker socket mounted. `sanitizeHostname` has
  stripped Caddyfile-significant bytes from the hostname since it was written;
  the email path had no equivalent.
- `styrman-update` asserted `.git` and `deploy/.env` ownership but never the
  worktree root it then builds as root — its own comment names that threat.
- `git diff --no-index` took git out of repository mode, so `?path=` was not
  confined to the work tree.
- The firewall scan's prefilter was a hard-coded literal rather than derived
  from `FAMILY_TAGS`: a fourth rule family named otherwise would have been
  inserted and never revoked, while the status still reported it applied.
- `install.sh` failed *after* every step succeeded on any host with more than
  12 firewall rules — which is exactly a host with LAN allowances.
- The two Go modules pinned different `docker/docker` versions with the older
  one in the internet-facing ingress. Converged, and `verify-commit.sh` now
  blocks on a recurrence.
- `files.openRoot`'s unconfined fallback now warns instead of being silent;
  the `LanChecker` contract comment no longer describes the superseded rule.

## What did NOT go in

Nine audit findings are recorded as not-now with reasons in the report —
refactors and design decisions rather than fixes, including splitting
`internal/httpapi` (10,288 lines, 7 subsystems), the credential-harvest
import flow, and unifying the four symlink-guard implementations. Doing any
of them inside a fix pass is how the ADR-066 gate produced sixteen defects.

## Verification

`deploy/verify-commit.sh` green on the release commit — the full gate in a
detached worktree, including the new shared-dependency check. Firewall
`test.sh` **128/0** (was 125), both Go modules clean, web 85/85,
`integration.sh` 79/0/4. Every fix was mutation-checked: the defect
re-introduced, the suite watched to go red, the fix restored.

## Still true, and unchanged by this release

**No LAN allowance has ever been applied by the v4 script on real hardware.**
The feature ADR-066 built has never been used. It is blocked behind
`install.sh --lan-allow-host 1`, which correctly refuses until this host stops
accepting sshd password authentication — and hardening that needs the
operator's own client public key, since the key on this host is the host's
own and hardening without theirs would lock them out.
