## 1. Workspace migration test coverage gap (BUG-005)

`cmd/styrman/migrate_test.go` was rewritten in Phase 1 (`f3882ac`) to test the new harness migration path (`harnessPlan` → user home conversion), but the rewrite replaced the entire file without preserving `TestMigrateWorkspaces` and `TestEnsureReposRefusesUnmigrated`:

- `TestMigrateWorkspaces`: validates ADR-027 workspace-tree migration (`/projects/<u>/<uuid>` creation + file move).
- `TestEnsureReposRefusesUnmigrated`: guards R13 (unmigrated projects are rejected at startup).

Both functions restored verbatim from v1.20.0 below the new harness-path test. All seven tests pass.

**Prevention rule:** File rewrites that alter existing test coverage must be reviewed for dropped test cases; a pre-commit hook or a linter can catch this by diffing test counts.

## 2. Stale setup-VM cleanup timeout

`internal/orchestrator` cleans up stale setup VMs (crashed `mvm:setup` containers) on startup with a 60 s Docker API budget. On slow hardware or under load, individual operations (list, inspect, remove) can exceed 60 s total, causing startup to timeout before the listener binds. Reduced to 10 s; the sweep is a nice-to-have cleanup, not a blocker.

## 3. Silent error in base-home migration

`cmd/styrman` migration path (`migrateBaseHomes`) renames the setup-VM home to its final location but dropped the error on failure. Now logs `firstError` (the renamed path, never a secret) under a distinct "base home migration incomplete" line for observability. Errors on individual homes are already logged per-home; this catches cascade failures.
