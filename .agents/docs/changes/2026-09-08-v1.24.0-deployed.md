# v1.24.0 deployed and verified live   (2026-09-08)

Tag `v1.24.0` on commit `7cbced7`, SSH-signed and verified against
`/etc/styrman/allowed_signers` **before** pushing — the same check the
updater performs, so the tag could not be rejected at deploy time.
`deploy/verify-commit.sh` passed on that exact commit (ADR-061).

`styrman-server:1.24.0` healthy, `styrman-caddy:1.24.0` up, deploy clone at
the tag. `host_converge` installed the v4 firewall script from the tagged
object with no root command from a human — the second release to prove that
path.

## It shipped inert, which was the design

| Check | Result |
|---|---|
| `lan_allow_host` / `lan_allow_published_ports` | `0` / `0` — the conf has neither key |
| `STYRMAN-IN` | `-j DROP` only |
| `STYRMAN-FWD` | 6 DROPs, **0** allowance rules |
| Script / status version | 4 |

The host behaves exactly as it did on v1.23.0. Opting in is
`install.sh --lan-allow-host 1`, which **refuses on this host** because sshd
accepts password authentication — R12, now enforced in code rather than
documented and hoped for.

## Signing note

The tag was signed with `git -c gpg.format=ssh -c user.signingkey=…` rather
than by setting those keys with `git config`. `versioning.md`'s procedure
says to set them; `AGENTS.md` says never to change git config. The `-c` form
satisfies both, and `gpg.format` was confirmed still unset afterwards.
Worth folding into `versioning.md`'s step 3.

## A correction about my own instrumentation

I armed a `Monitor` on `styrman-update.service` to watch the deploy. It ran
15 minutes and emitted **nothing** — across a deploy that had already
succeeded. The filter was wrong, so it would have been equally silent on a
failure. The live state above was established by looking directly, not from
that monitor. Recorded because "the watcher said nothing" is not evidence,
and this session already had one claim (in `dc5bad4`'s message) that came
from trusting a single observation.

## Still unproven

Named in the gate report and unchanged by shipping: **no LAN allowance has
ever been applied by the v4 script on real hardware**, and the published-port
path has never been exercised live. Both need an operator opt-in — and that
opt-in is blocked, correctly, until sshd is hardened.
