# Project repo provisioning order fix — v1.18.0     (date: 2026-09-02)

## Summary

**The bug:** In `createProject`'s background goroutine, `EnsureSelfAttached` (which joins the styrman-server container to the project's bridge, the ONLY route to the credential broker per ADR-030/032) ran AFTER repo provisioning. So every `cloneUrl` clone and every `github: private|public` create ran against an unreachable broker: no ssh key materialized, no git-credential-helper answer, no GH_TOKEN, no git author identity. The failure was logged at `logger.Warn` only, silently degrading to an empty repo with nothing shown in the UI. Live server confirmed: clone attempts followed by broker serves 30–35ms later.

**The fix:** Provisioning extracted into `internal/httpapi/provision.go` (`provisionSpec`/`provisionRepo`, with `attach` and `run` injected so the step ORDER is unit-testable). Order is now: pause → attach → wait for the broker to answer from inside the guest via a plain `sh -c curl` of `$STYRMAN_CRED_BROKER/healthz` → provision in a LOGIN shell (`bash -lc`) so `/etc/profile.d/zz-styrman-credentials.sh` materializes credentials first.

**UX improvements:** New `provisionError` field on the project API (`GET /api/projects`, `GET /api/projects/{id}`), plus a red "repo setup failed" sidebar badge. A failed clone now says WHY instead of presenting as an empty project (message is redacted, control-stripped, length-capped — all guest-controlled text). Cloning a repo now names the project after the repo (new `projectNameFromRepoURL` in `web/src/lib/api.ts`); the name field auto-fills until the user types their own.

**Project hostname:** The microVM hostname lost its `styrman-` prefix (operator: "all projects have styrman- as prefix. We dont want that" — old prompts read `ostling-simon@styrman-styrman-harness`). New `guestHostname()` in `internal/orchestrator/orchestrator.go`. Existing containers keep the old hostname until recreated, which happens on the next stop→start after image upgrade.

**Security remediation:** `redactURL` deleted (it mangled `https://host/o/r@v1.git`) and replaced by `redactSecrets`, which redacts every scheme-bearing URL and splits userinfo at the LAST `@` of the authority like git/curl/net/url. `stripControls` now also drops C1 and Unicode bidi/invisible controls. `clampBytes` truncates rune-safely (both shared with `clampTitle`). `waitForBroker` short-circuits in host-mode dev; the readiness probe is no longer a login shell (it was materializing the user's ssh key into a project home up to 10 times just to check reachability). `setProvisionError` no longer resurrects an entry for a deleted or vanished project (ADR-058 security analysis).

## Verification
- `TestProvisionRepoAttachesBeforeAnyCredentialedCommand` pins the attach-before-provision order regression.
- `TestProvisionRepoClonesThroughALoginShell` ensures login-shell provision (credentials available).
- `TestWaitForBroker` exercises the broker reachability wait.
- `TestProvisionErrorLifecycle` and `TestProvisionErrorSurfacesInTheProjectAPI` confirm the error surface.
- E2E: clone with reachable broker succeeds; clone with unreachable broker records error and falls back to empty repo; project-name auto-fill works; error badge renders; deleting a project drops the error.
- Manual: verify hostname in project shell is now `user@project-name`, not `user@styrman-project-name`.

## Requirements
- R13 (empty repo fallback on clone failure) satisfied — `provisionRepo` still runs `gitrepo.EnsureRepo` if clone fails.
- ADR-030/032 (credential broker reach) satisfied — provisioning now waits for broker readiness before any credentialed command.
