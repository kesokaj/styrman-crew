# What the round's reviews found, and what was done   (2026-10-02)

Phase 3 of `plans/2026-10-02-stale-keys-browser-liveness-updater-status.md`:
the code, security and docs reviews of v1.40.0..5571b57. The operator, during
this pass: "Include in the version go".

## Code review (`reviews/2026-10-02-review-v1.40.0-5571b57-code.md`, REQUEST CHANGES)
- **Medium: BUG-088's first fix gave a held lock a meaning it does not have.**
  `GuestGoingAway` answered "the guest is going away" whenever the project's
  lock was held. That lock is also held by an attach's no-op `EnsureRunning`
  and by the idle reaper's busy check, so a real failure in that window would
  have been hidden. The function now waits for the lock to come free, checking
  every 100 ms and bounded by the request, then asks Docker again. A stop or a
  toggle reads stopped or replaced; a no-op holder leaves the failure
  reported. `internal/orchestrator/ports_lifecycle_test.go` now has five
  tests, one of them the review's case. With the old logic put back, four of
  the five fail. All pass with `-race`. BUG-088's record carries the revised
  fix, a `Diagnosis missed:` line and a tightened prevention rule.
- **Low: a missing token read as a rejected one, at a hard-coded path.**
  Fixed by wording: "GitHub did not accept this host's token (missing,
  expired or revoked)", with no path (`web/src/lib/updaterNotice.ts`, its test,
  the e2e check, `versioning.md`, `guide.md`). git gives one signal for both
  cases, so no new code was added.

## Security review (`reviews/2026-10-02-security-v1.40.0-5571b57.md`, two lows)
- **The second release signer.** ADR-082 gains both full fingerprints (read
  from the v1.39.0 and v1.40.0 tag signatures), where each key lives, and the
  revocation step. Left to the operator: how the Mac key is protected, and
  whether the NUC's `allowed_signers` lists it (root on the NUC).
- **The status path.** `write_status` now refuses a relative path, or one with
  a symlink, `..` or `//` on it (`realpath -m` must equal the path), as the
  state dir does. New test `TestStyrmanUpdateStatusWriteRefusesANonCanonicalPath`
  fails with the check disabled.

## Docs review (`reviews/2026-10-02-review-v1.40.0-5571b57-docs.md`, one low)
- `api.md`'s server environment table gains `STYRMAN_UPDATE_STATUS_FILE`, and
  the older missing `STYRMAN_INGRESS_NETWORK`. The `documentation` agent wrote
  these edits and the wording and path-rule changes above; they were read
  against the code before staging.
