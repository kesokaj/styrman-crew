# v1.42.2: transcript reads bounded too   (2026-10-05)

Security review of v1.42.1..ef22f5c, finding 2
(`reviews/2026-10-05-security-v1.42.2-v1.42.1-ef22f5c.md`).

- `GET …/history/{session}` takes one of 8 server-wide slots
  (`readConcurrency`), else 429. One read holds up to 4 MiB, about 30 MiB
  JSON-escaped. Under v1.42.1's 4g cap, about 150 reads that are never
  consumed would crash-loop the server; 8 stay far below it.
- Search and read share `acquireSlot`, which also sets a 30 s write deadline
  (`http.ResponseController`), so a client that never reads its response
  releases the slot.
- `TestHistoryReadIsLimitedServerWide` was red first. `api.md` documents the
  read 429 and the deadline.

`go test -race ./...` exit 0. Diff read by me.
