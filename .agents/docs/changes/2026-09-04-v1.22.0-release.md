## What ships in v1.22.0

**Phase 1: GOPATH to `$HOME/.go`.** Guest shell skel files rewritten to place `GOPATH` at `$HOME/.go` instead of `$HOME/go`, keeping the home's top level clean. **Scope is new project homes only** — existing homes keep their `$HOME/go` directory due to the write-once-per-file guard in `entrypoint.sh` (`[ ! -e "$dst" ]`); anything already `go install`-ed there stays on the old path. This is the **single operator-visible behaviour change** that is not purely additive. Runtime image rebuilt AMD64 and confirmed to carry the new skel. `REQUIREMENTS.md:31` uses `~/go` as prose example but was deliberately NOT edited — immutable without explicit operator approval per AGENTS.md hard rules.

**Phase 2: Settings → Appearance.** Terminal and editor font size + family controls arrive in `/settings`, defaulting exactly today's per-surface values so nothing changes until a control is touched. **Honest limitation:** `/settings` is a separate route and unmounts the panes, so the preference applies on next mount — there is no live update. The plan records that the compartment and live-apply effect are defensive only; appearance is not claimed as a shipped "live update" feature.

**Phase 3: File explorer real back/forward/up.** Explorer gained true Back/Forward/Up buttons (`Alt+←` / `Alt+→` / click breadcrumb); breadcrumb bar renders with middle-path elision for readability. Replaces read-only ..-parent-folder fallback.

**Phase 4: Recent-files grid is collapsible and resizable.** The recent-files strip became a wrapping grid with cap of 8 → 16 entries, togglable collapsed/expanded and draggable height via a resize handle. Addresses explorer UX complaints on files with many recent items.

**Phase 5: Git diffs open full-width in main pane.** Git diffs (`git diff` on tracked file, `git show <commit>`) now open in a dedicated `DiffView` occupying the main pane (Terminal, Editor, or Diff), replacing side-panel read-only diffs. A Fast Commit button stages everything and commits with a generated UUID behind a confirm showing the file count. Cleanup prevents tree-rewriting verbs (checkout, pull, stash) from leaving the editor holding pre-change content.

**Phase 6: Six new git verbs.** Fetch, pull (`--ff-only`), branches (switch/create), log, stash (`push -u`, `pop`, `list`). Endpoints report absence as 200 + flags (read convention); mutations return 4xx (write convention); deliberately asymmetric and documented. **First time the codebase turns user-supplied strings into git argv.** Validation gates option injection and ref traversal via `validBranchName` (leading `-`, C0/C1/DEL, invalid UTF-8, length) before argv construction, deferring ref-format validity to git itself (a deliberate deviation from the plan, pinned by test).

## Release gate findings — all fixed before SHIP

Reviewing v1.21.0..b6db0b9 as a single range found six things no per-phase review could catch, all fixed in commit b6db0b9 and re-verified:

1. **Two source files were never reviewable.** `web/src/components/DiffPane.tsx` and `web/src/lib/diffReveal.test.ts` contained literal NUL bytes (cache key separators, test control bytes where escapes were meant), so git classified both as binary and their contents were invisible in diffs — two reviewers and a security pass had signed off on files they could not see. Fixed to `\uXXXX` escapes; both verified NUL-free, tests still 69/69.

2. **`gitPush` put a guest-controlled branch name into argv unvalidated.** Plumbing can create `refs/heads/-foo`; `rev-parse --abbrev-ref HEAD` reports it verbatim and `git push -u origin -foo` reads the leading `-foo` as options (verified on git 2.47.3: `-f` plus `-o o`). Sibling `gitCheckout` gated exactly this. Now validates with `validBranchName` before argv.

3. **Tree-rewriting verbs left the editor holding pre-change content.** checkout / pull / stash never told the editor pane, so an open buffer silently predated the new tree and Save would write it back over the checkout — a data-loss path. Now `evictCleanProjectPanes` drops CLEAN project buffers so the next open re-reads; deliberately does NOT discard dirty ones (that trades one data loss for another). Dirty buffers are reported to the user instead.

4. **The `firstLine` → `guestErrMessage` remediation landed on 2 of 4 sites.** `gitCommit`'s 409 and `gitPush`'s 502 still returned uncapped, unstripped git output. Both fixed; `firstLine` itself stays (still used by `format.go`).

5. **Fetch tooltip still advertised `--prune`,** removed as a deliberate security decision. Same class as the phase-6 comment claiming a trailing `--` terminated options — a description that outlived the behaviour.

6. **README's Git-tab bullet was still the v1.7.0 feature list** and `AGENTS.md:58` claimed 60 integration checks (now 68). Fixed by the `documentation` agent.

## Notable engineering decisions (pinned by tests)

- **`validBranchName` gates argv danger only, defers ref-format to git.** Reimplementing git's ref rules would mean silently drifting from a spec we don't own. The server's 400 response carries git's own rejection, keeping validation end-to-end with git as the authority. Pinned by `TestValidBranchNameDefersRefFormatToGit` against leading `-`, traversal, and invalid UTF-8.

- **Reads answer 200 with state/repo flags; mutations answer 4xx.** Deliberate asymmetry following `gitStatus`'s existing convention. Documented in `api.md`. Not to be "unified".

- **`GIT_CEILING_DIRECTORIES` now bounds git's repository discovery on every exec.** Prevents `git rev-parse --show-toplevel` from escaping the workspace.

- **`DiffView` reveals bidi and control characters as `<U+202E>`-style markers.** The pane's job is reviewing a change before committing it. Literal byte rendering would be unsafe; `reveal()` sanitiser is in the shipped `web/dist` bundle, verified by security.

## What was NOT checked

Named honestly, because the gate's rows do not cover them:

- **Coverage tracing is incomplete.** The verifier ran every command green but did not finish tracing each changed file to a covering test. Largest untraced: `SidePanelGit.tsx` (351 changed lines); also untraced: `deploy/verify-commit.sh`'s new gate step, `image/skel/*`, and `integration.sh`'s own additions. Per AGENTS.md a changed file with no covering test is a FAIL row; these are unknown, not established failures. `SidePanelGit.tsx` is exercised by e2e git checks, but not line-for-line.

- **The six new git HTTP handlers have no Go unit test.** `Server.orch` is a concrete `*orchestrator.Orchestrator` with no exec seam to fake — a gap already recorded for `checkFile`/`formatFile` and as BUG-003's residual. Only `validCommitHash`/`validBranchName`/`stashOps` are unit-tested; handlers are covered by e2e and integration only.

- **No reviewer executed anything against real Kata.** E2e and integration results are from local runs, not independently reproduced by another operator.

- **Phase 2's "live font update" is not shipped behaviour.** `/settings` unmounts the panes, so the preference applies on next mount. Recorded in the plan; repeated here so the release note does not overclaim.
