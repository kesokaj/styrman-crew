# v1.41.0 deployed on dave by the break-glass path   (2026-10-03)

The operator asked: "Research how you do it on Dave and push the new version".
dave (the NUC, crew.styrman.xyz) was on 1.38.0. Its auto-updater cannot fetch,
because GitHub rejects `/etc/styrman/gh-token` (BUG-084). The documented
fallback for "a host where the auto-updater ... is itself broken" is
`specs/styrman/versioning.md` "Manual / break-glass fallback". The root steps
were run by the agent this once, at the operator's word ("Yes, run them now
(Recommended)"). `deploy/local.md` records no standing permission, and none was
added.

## What ran (2026-10-03, 03:25–03:27 CEST)
Two changes from the documented fallback, both because of BUG-084's token:
the tag was fetched from the operator's checkout, not GitHub, and the runtime
image's build secret was the operator's `gh` login, not `/etc/styrman/gh-token`.
1. `sudo git -C /opt/styrman fetch --no-tags <checkout> refs/tags/v1.41.0:refs/tags/v1.41.0`
   → the tag at `c2b1f61`.
2. `sudo git -C /opt/styrman -c gpg.ssh.allowedSignersFile=/etc/styrman/allowed_signers verify-tag v1.41.0`
   → `Good "git" signature … SHA256:5HpYQJjpG+…` (the updater's own check).
3. `sudo git -C /opt/styrman clean -d --dry-run` (nothing), then
   `checkout --detach v1.41.0` → `describe` prints `v1.41.0`.
4. `GH_TOKEN=$(gh auth token) docker build -t styrman-runtime:1.41.0 --secret id=gh_token,env=GH_TOKEN --build-arg STYRMAN_VERSION=1.41.0 /opt/styrman/image`
   → rc 0. This is the updater's build command; the token is a build secret,
   not a layer.
5. From `/opt/styrman/deploy`, as root:
   `STYRMAN_VERSION=1.41.0 STYRMAN_IMAGE=styrman-runtime:1.41.0 docker compose -f docker-compose.yml build`
   → rc 0, then `… up -d` → rc 0. Both containers were recreated at 03:27:05–06.

- The two project containers on dave had been stopped since 2026-09-30 and
  were untouched. They start on the 1.41.0 runtime image when next opened.
- Not checked: a fresh Google sign-in in a browser (the operator's), and a

## What is still broken on dave
- The auto-updater still exits 1 on every tick (BUG-084). The installed
  updater is still 1.38.0's script and unit, which the new updater would
  replace with itself on its first successful tick. So no status file is
  written yet, and Settings shows nothing about the updater.
- `/etc/styrman/update/deployed-version` still reads v1.38.0; it was left
  alone, so as not to hand-write the updater's rollback state. When the token is
  replaced, the first tick will rebuild and redeploy v1.41.0 itself, which is
  harmless, and then write the status file.
- Rollback, if needed: `STYRMAN_VERSION=1.38.0 docker compose -f docker-compose.yml up -d`
  from `/opt/styrman/deploy` as root (the 1.38.0 images are still on dave),
  and `git checkout --detach v1.38.0` in `/opt/styrman`.

## Found on the way
dave's `/etc/styrman/allowed_signers` holds exactly one key,
`SHA256:5HpYQJjpG+yE1xXBTOIZPsTkbkgkVnV8z0eG8hBawyU`. The Mac key is not
listed, so dave would refuse a tag the Mac key signed. Appended to ADR-082.

## Learnings for the local host
- With BUG-084 open, the break-glass fallback works without the token: fetch
  the tag from a local checkout and verify it against `allowed_signers`, and
  build the runtime image with `gh auth token` as the secret. The fallback's
  text assumes a working `/etc/styrman/gh-token`.
