# ADR-067 Phase 0 — the requirement and the decision, before any code

The per-project LAN switch is being rebuilt. ADR-065/066's design — a marker
directory, a `/run` spool, a systemd path unit, a root reconciler with three
rule families, a status file, a version handshake, a rate limiter, two conf
opt-ins, an sshd precondition and a permanent SSH-key latch — is replaced by
one fact: **every styrman rule keys on the bridge interface name, and the
server chooses that name at `docker network create`.**

Sandbox keeps `sdb-<hash>` and is matched by the drops. LAN gets `lan-<hash>`
and is matched by nothing, which makes it exactly a normal Docker container on
this host. Cross-project isolation is unaffected because it is Docker's, not
styrman's.

This phase is records only; no source file was touched.

## Two facts measured, not assumed

Both had been assumed wrong, or never asked, in ADR-065/066:

1. **The prefix alone decides LAN reach.** Two throwaway Docker networks
   differing only in the four-character bridge prefix: `lan-` reached the
   gateway, the host and the internet; `sdb-` reached only the internet.
2. **R12's cross-project guarantee is Docker's.** Docker 29.7.2 writes
   `-A DOCKER ! -i <br> -o <br> -j DROP` per bridge. From the `lan-` bridge,
   the other bridge's container was unreachable by ICMP and TCP — including
   with `NET_ADMIN` and a manual route added, the attack R12 names by name.

Also established: `iptables -S` on this host showed **zero `styrman-lan*`
rules**, with the v4 script installed, `/etc/styrman/firewall.conf` written and
the status file current. ADR-066's feature was never once applied.

## Process finding, carried into ADR-067

The cold-reader gate found eleven items across three rounds. **Nine were the
same class** — a consumer of a deleted identifier missing from a hand-written
"Surfaces touched" table. Adding the named items by hand each round and finding
more the next round is the method failing, not the requirement being unclear.
The list was regenerated by grepping every deleted identifier across the tree,
which found eight surfaces three review rounds had not — including
`deploy/verify-commit.sh:162`, which runs `systemd-analyze verify` on a unit
file this work deletes and would have failed the release gate. Re-running that
sweep, expecting zero hits, is now the completion check for each deletion
phase (plan Appendix B).

Round 1 also caught a design defect that would have shipped as a silent no-op:
the bridge-name heal was placed in `create()`, which only runs when the
container does not exist, so a toggle would have restarted the same container
on the same bridge and done nothing at all.
