# v1.38.0 — the whole-project review, acted on   (2026-09-22)

Release of the work in `changes/2026-09-22-review-remediation-phase-{0,0b,1,2,3,4,5}.md`.
Gate report: `reviews/2026-09-22-preflight-v1.38.0.md` — SHIP. MINOR: new
user-visible behaviour (a capped file listing that says when it was cut),
nothing an existing deployment must react to.

It began as `/review --project --all --high` — six lenses over the whole
repository at c05219c — and the plan that followed
(`plans/2026-09-22-project-review-remediation.md`) was ordered by what could
still surprise us rather than by severity. That ordering is what produced the
release: Phase 0 edited nothing and existed only to read the one package no
lens had opened.

## What ships

- **The file listing is bounded.** `internal/files.List` read a guest-owned
  directory with `ReadDir(-1)` and sorted it with a hand-rolled insertion sort
  — quadratic, in the one process serving every tenant: 20 000 entries took
  **5.88 s**, measured on the real function. It now caps at 5000 and sorts with
  `slices.SortStableFunc`: **13.4 ms**. `ListNames` twelve lines below had
  carried both the cap and the reason in a comment since 2026-09-03; `List`
  never got it.
- **A cut listing says so.** The response carries `truncated` and the explorer
  renders "Some are not shown". The cap is applied to raw directory order
  before sorting, so which entries are missing is arbitrary — a silently cut
  listing would be a way to keep a file out of a human's sight. That notice was
  itself a defect this release created and then closed.
- **The managed-subtree guard is a boundary now.** `~/projects`, `~/.dockerd`,
  `~/.styrman` and `~/.ssh` were matched as strings while `os.Root` follows
  in-root symlinks, so `ln -s .dockerd x` reached the subtree through an
  unmanaged name. Every path component except the last is checked, and acting
  on a link itself is still allowed — removing a bad symlink is housekeeping.
- **`ReadRawNoFollow` no longer wedges on a planted FIFO.** Its parent open was
  the only one in `internal/files` without `O_NONBLOCK`; a guest replacing
  `~/.ssh` with a FIFO hung the serving goroutine and its OS thread.
- **The R12 boot assertion fails closed.** A containerized server refused every
  unreadable `ip_forward` state except a missing file, which warned and
  continued — the one guard behind R12 reporting "fine" in the single case
  where it had measured nothing. `STYRMAN_ALLOW_IP_FORWARD=1` is unchanged as
  the documented way through.
- **The release gate measures content.** `deploy/verify-commit.sh` compared
  `web/dist` by FILE NAME. The bundles carry a content hash so they were
  caught; `_shell.html` and `favicon.svg` do not, so an edit committed without
  a rebuild shipped stale inside `//go:embed` while the gate printed "match".
  Proved on the real gate: with a stale favicon the OLD gate ran the commit to
  completion and passed it. It now compares a sha256 set. Its shellcheck line
  also gained `deploy/host-setup.sh` — where BUG-070 hid for months behind an
  "already installed" guard — plus `deploy/styrman-ctl` and `image/entrypoint.sh`.
- **Hardening that had not travelled.** `deploy/gcp/install.sh` forked `env_get`
  and `private_file` from `styrman-ctl`; the `env_get` fork had lost its
  `is_key` guard and interpolated the key into a regex. Both now come from
  `deploy/gcp/lib.sh`, with `private_file`'s two genuine context differences
  turned into arguments and written down. The ingress strips a client-supplied
  `X-Caddy-Role` in role-gated mode. `credPushing`/`credPushRerun` have their
  own mutex.
- **Documentation that matched the code again.** Five copies of the
  runtime-image build command omitted ADR-074's required `--secret` and failed
  as written; `README.md` described the LAN model ADR-067 deleted two releases
  ago; `deploy/local.md` and `.env.example` passed a variable no code reads.
- **ADR-076:** the approved-dependency list names what the module actually
  requires — it had listed `creack/pty`, gone from `go.mod` entirely, and
  omitted two direct requirements.

## Verification

Every row in the gate report. In short: `deploy/verify-commit.sh` on the tagged
commit ("safe to tag"), `go test ./...` 329 pass (311 before the review, no
test removed), the ingress module 55, the frontend 15 files / 178 tests, Tier 2
`passed=112 failed=0 skipped=3`, Tier 4 `passed=93 failed=0 skipped=2`,
`deploy/vulncheck.sh` reporting only the accepted `docker/docker` pair.

**Every fix in this release was seen red before it was believed.** Nine
mutations, each of which compiled and made a NAMED test fail, each file then
restored from a checksummed copy and verified byte-identical. Two of those
probes found defects in the probes themselves rather than in the code — a
shellcheck warning below the gate's severity threshold, and an e2e check that
cascaded eight failures when it failed — and both are recorded.

**Known unexercised, stated rather than implied:** the fresh-host path. This
release changes `deploy/gcp/*`, and `host-setup.sh`'s guarded steps are
reachable only by a host that has not installed them. The GCP instance is
deleted, so the next bring-up is this code's first real exercise
(`.agents/rules/shared-path-learnings.md`).

## Accepted, not fixed

Named here rather than shipped in silence, each with its follow-up:

- `deploy/gcp/vm.sh` still interpolates the remote's answer into
  `vm_ssh "sudo ${ctl} status"`. The characters are now bounded and the
  security review probed the pattern with 16 hostile candidates, all refused;
  closing it means re-deriving the path remotely and deleting the allowlist.
- `deploy/gcp/vm.sh:114` can exit with ssh's own code and no output when a
  transient drop follows a passing reachability probe — the
  transport-first rule's shape, pre-existing from 07741b2.
- `STYRMAN_ALLOW_IP_FORWARD=1` is sticky: one Warn at boot, then R12 is
  unasserted on every later restart.
- `web/src/lib/api.ts` and `FileExplorer.tsx` have no UNIT test. Both are
  covered end to end by Tier 4's "a directory past the listing cap says so",
  proved by suppressing the notice and watching that check fail. A unit test
  needs a component-testing framework, which is a dependency decision and has
  not been taken.
- One append-only violation by the main agent, recorded in the gate report:
  `changes/…phase-3.md` was edited in place to correct an overclaim rather than
  corrected only in the following entry.

## Deploy

The auto-updater is the path: `styrman-update.timer` verifies the signed tag
and brings the stack up at `/opt/styrman` within ~5 min. **Watch the tick
rather than assuming it** — this release changes boot behaviour, and a
containerized server that cannot read its `ip_forward` sysctl now refuses to
start where it previously warned. A tripped guard fails the updater's health
check and rolls back.
