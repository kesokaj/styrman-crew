# Project repo provisioning fix + secure clone URLs — v1.18.1     (date: 2026-09-02)

## Summary

**v1.18.1 is the live release** (v1.18.0 failed to build — see the v1.18.0 changelog correction). It carries the full project provisioning fix from v1.18.0 (attach before provision, login shell for credentials) PLUS two new security hardening changes.

**Missing file fix:** Commit `b321f35` (v1.18.0 tag) staged `server.go` without `provision.go`, causing a compile error. Commit `cb1c18c` added the missing file and was tagged v1.18.1.

**Credential URL refusal:** Clone URLs that embed a password (`https://user:token@host/repo`) are now REFUSED at the API boundary with a 400 Bad Request, rather than accepted and redacted. Rationale: the credential broker makes embedded credentials unnecessary (ADR-030/032 deliver the user's ssh key and answer git-credential-helper requests per HOST). A token in the URL is a worse alternative path: git writes it verbatim into the project's `.git/config` on the host, where nothing redacts it, and a later push to that host persists it as history. Refusing at the boundary deletes the class of vulnerability rather than trying to mitigate it. A bare USERNAME is still allowed (`ssh://git@host/o/r` is the standard SSH form).

Implementation: `cloneURLHasSecret` in `internal/httpapi/server.go` (rejects any scheme-bearing URL with userinfo containing `:`) mirrors client-side `cloneURLError` in `web/src/lib/api.ts`. Addresses the operator decision from the 2026-09-02 security review (ADR-059).

**SSH clone verified live:** An SSH clone of `git@github.com:kesokaj/styrman-harness.git` that previously failed at 13:42 with "Permission denied (publickey)" now succeeds and populates the workspace with no `provisionError`. Test project was deleted afterwards.
