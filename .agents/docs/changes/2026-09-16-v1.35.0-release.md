# v1.35.0 — the harness channel: styrman-harness releases reach every project without a crew release (2026-09-16)

**MINOR.** Base `v1.34.1` (release tag `f7d1b15`). Range `v1.34.1..19d882c`, 19 commits, 67 files, plus the release commit (this entry, the gate report, the README bullet). Adds behaviour, breaks nothing: an existing deployment picks the release up through the updater and needs no action; the channel itself starts delivering only after the operator's one-time setup (Next).

## What changes for a user

Every project home's agent harness (`claude`/`agy` skills, subagents, the global context) is now delivered by the host's HARNESS CHANNEL (ADR-073; `REQUIREMENTS.md` R5 amended with the operator's approval, 2026-09-16) instead of by a crew release that re-mirrors `image/harness/`. `styrman-update harness` (`deploy/update/styrman-update`), run by `styrman-harness-update.timer` (7 min after boot, then every 5 min), fetches the root-owned clone `/opt/styrman-harness` with its own read-only fine-grained token (`/etc/styrman/gh-token-harness`), walks the `vX.Y.Z` tags downward to the newest annotated SSH-signed tag that verifies against `/etc/styrman/allowed_signers` — every refusal alarms in the journal and `/etc/styrman/update/harness-refused`, a tag below the installed one is refused, a tag that fails export or smoke is latched in `harness-failed-version` — exports it as a plain copy (no `.git`, no symlinks; `COMMIT`, `TAG`, `SHA256SUMS`) with `sh-agent` built offline in the image's pinned Go builder, smokes it in the deployed runtime image as uid 1000, and swaps `/var/lib/styrman/harness/current` to it in one rename. The server (`STYRMAN_HARNESS_DIR`, compose `/var/lib/styrman/harness`) bind-mounts `current/repo` at `/styrman/harness` and `current/bin/sh-agent` at `/styrman/bin/sh-agent`, read-only, into every project VM (never the setup VM) when the channel is present and trusted; a stopped VM is rebuilt on its next start whenever the harness binds it carries differ from what the server would mount now (gained once the channel delivers; dropped when it is absent, disabled or refused; re-bound when it moved), and Docker re-resolves `current` on every start, so a swapped export is what the next boot mounts. The entrypoint (`image/entrypoint.sh`) seeds a home write-once keyed on `<STYRMAN_VERSION>+<harness COMMIT>` and its pass line says `source channel tag <tag>` or `source image`. The image's mirror `image/harness/` stays the fallback until the channel has delivered.

Operator surface: `styrman-ctl install` and `update --setup` take `--harness-token-file <file>`; `styrman-ctl status` prints a `harness` line (the delivered tag and commit, or "waiting for the first signed styrman-harness tag", or "not set up") and is DEGRADED on a refusal newer than the last delivery or a latched failed tag; the two harness units are installed by `host-setup.sh` and, on every tick, by the updater's `host_converge` (BUG-064).
