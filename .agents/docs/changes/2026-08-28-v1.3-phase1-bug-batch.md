# v1.3 Phase 1 — bug batch (files, delete, dotfiles)

Date: 2026-08-28. First of four planned v1.3 phases (see
`.agents/docs/plans/2026-08-28-v1.3-frontend-functionality-research.md`,
answers in §4b). Fixes everything the operator screenshotted in `screens/`.

## Summary

- **File save in project scope fixed** (the "cannot write file" screenshot):
  `readFile` now reports scope-relative paths like `listFiles` always did —
  the editor's save round-trip used to re-apply the `projects/<dir>` prefix
  and ENOENT. Also fixes the file viewer's Download link for the same reason.
- **File delete / rename / new-folder exist now** — end-to-end (API routes,
  confined `files.Rename`, explorer UI row actions + toolbar button). The
  scope root is refused as a target. Delete of a directory is recursive.
- **Editor save body cap 1 MB → 8 MB** (`/file` PUTs only): files between
  1–2 MiB used to open editable but could never save (read cap 2 MiB, JSON
  escaping overhead on top).
- **Project delete is async** (the "Failed to fetch" screenshot): `DELETE
/api/projects/{id}` returns 202 immediately; the destroy runs detached (a
  Kata teardown can exceed any sane fetch timeout), the project shows
  `state:"deleting"` in the sidebar (pulsing dot, row disabled) until the
  record disappears; repeat DELETEs are idempotent; failures leave the
  record for retry. `orchestrator.Destroy` now takes the per-project lock so
  a terminal WS reconnect can't recreate the container mid-removal.
- **Start/stop client timeout 20 s → 150 s** — same false-failure gap.
- **Shell dotfiles**: new `internal/dotfiles` package (embedded userprofile
  ported from devbox: history config, readline, git-branch prompt, aliases,
  PATH dedup, modular exports/aliases/secrets). `ensureHome` deploys it
  write-once on EVERY server start — the old whole-home early-return meant
  pre-existing homes never got a `.bashrc` at all (the operator's report).
  Recognized pre-v1.3 minimal seeds (ensureHome's `# styrman home`,
  home-init's `# styrman shared home`, one-line aliases/exports) are moved
  aside (`.pre-v1.3` suffix) and upgraded; anything user-edited — and
  `.bash_secrets` always (R10) — is never touched. `home-init.sh` no longer
  seeds dotfiles (single source of truth).
- **Runtime image base tools** (operator Q7): added bash-completion (the new
  bashrc sources it), lsof, mtr-tiny, traceroute, net-tools,
  python-is-python3, gettext-base, openssl.
- **History read `?bytes=` clamped to 4 MiB** — was an unbounded
  server-side allocation for any authenticated caller.

## Review fixes (reviewer subagent, same session)

The adversarial review found three blockers, all fixed:

1. **Resurrection race**: after the async 202, a terminal WS auto-reconnect
   (force-remove closes with a TRANSIENT code) could call `ensureFor` →
   `EnsureRunning` and recreate the container mid-destroy, leaving an orphan
   microVM with no record. Fixed: `ensureFor` and `startProject` refuse while
   `deletingState` reports an in-flight destroy (409 on start).
2. **Unconfined dotfile writes**: `dotfiles.Deploy` used `os.ReadFile`/
   `os.WriteFile`/`os.Rename`, which follow guest-planted symlinks on the
   shared home — a confined-write bypass reachable on every server start once
   the ensureHome early-return was removed. Rewritten on `os.Root` with
   `Lstat` (non-regular files skipped entirely) and `O_CREATE|O_EXCL` writes;
   `ensureHome`'s MkdirAll/Chmod likewise confined. Regression test plants
   symlinks (dangling + escaping) and asserts nothing outside is touched.
3. **Legacy-seed detector was a prefix match**: a user who APPENDED to the
   seeded `.bashrc` would have had their file moved aside and replaced.
   Now byte-for-byte comparison against the two known legacy seeds (modulo
   trailing newline); backups are never clobbered. Test covers the appended
   case.

Should-fix items also addressed: home-scope delete/rename refuse managed
subtrees (`projects`, `.dockerd`, `.styrman`, `.ssh`); real errors logged on
the destructive endpoints ("destination already exists" surfaced verbatim);
failed background destroys surface as `deleteError` in the project views +
sidebar "delete failed" chip; both background goroutines (delete, create-boot)
recover panics; the open editor closes when its file is renamed/deleted; the
sidebar action menu is gated during "deleting"; name validation rejects
`.`/`..`/whitespace; `?bytes=` negative → 256 KiB default; dead `put_once`
removed from home-init.sh; symlink-escape + no-clobber + managed-path tests
added. (Kept `net-tools` despite the reviewer's leaner-image nit — devbox
parity was an explicit operator ask.)
