# REST API spec

Base: the styrman server. All bodies JSON, camelCase; errors
`{"error":{"message":"..."}}`. Every request carries an identity: the
Google email injected by the ingress (`X-Caddy-Email`, auth mode `header`),
or the configured default user on the loopback dev listener (mode `none`).
All project/terminal/file/history resources are scoped to that user
(ADR-019). `{id}` below is always the project **UUID** (ADR-020); friendly
names are display-only.

## Projects

| Method & path                             | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/projects`                       | The user's projects, newest first: `{id, name, dir, createdAt, gitInit, state}` (+ `deleteError` after a failed destroy).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `POST /api/projects`                      | Create: `{"name","cloneUrl","github","gitInit"}`. Every project is a git repo, no exceptions (R13, ADR-022): by default a synchronous `git init -b main` runs before the `201`; `cloneUrl` (mutually exclusive with `github`) clones that URL in-guest instead, using the user's ssh key/gh credentials, falling back to an empty repo on failure; `github` (`"private"` or `"public"`) also creates and pushes a GitHub repo via the user's `gh` login. `gitInit` is accepted for compatibility and ignored. `fromBackup: {project, id}` (v1.13.0, ADR-044; mutually exclusive with `cloneUrl`/`github`) seeds the new project from an existing backup — workspace, home, and the source project's scoped env variables — before the boot. Returns **201 immediately** with `state:"creating"`; the microVM boots in the background (terminal attach waits for readiness). Name must not collide with a _current_ project; reuse after deletion is fine. |
| `GET /api/projects/{id}`                  | One project + live state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `PATCH /api/projects/{id}`                | Rename (friendly name only): `{"name"}`. The workspace dir (`dir`) never moves.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `DELETE /api/projects/{id}[?wipe=true]`   | Destroy the microVM + records. Returns **202 immediately**; the destroy runs detached (a Kata teardown can take minutes) and the project reports `state:"deleting"` until its record disappears from the list. Repeated DELETEs while in flight are idempotent 202s; boot paths (start, terminal attach) refuse while a destroy is in flight so a reconnecting terminal can't resurrect the container. On failure the record stays, `deleteError` carries the message in the list/get views, and the delete can be retried. `wipe` also deletes workspace, `~/.dockerd/<id>.img`, and transcripts — the UI requires typing "delete".                                                                                        |
| `POST /api/projects/{id}/start` · `/stop` | Boot / stop the microVM.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `GET /api/projects/{id}/stats`            | Live resource snapshot of the running microVM, behind the terminal status bar: CPU %, vCPU count, 1-min load, memory used/total, disk used/total (`df` of the guest `$HOME`, a host-backed mount — shown as a % to stay meaningful), process count, uptime, guest hostname, bridge IP (resolved host-side). Sampled in ONE guest pass with a non-login shell so it never triggers the per-login credential pull. Stopped/absent project → the full stats object with `state` set and every numeric metric ZEROED (those fields have no `omitempty`, so they're present as `0` rather than omitted); an exec failure on a running project also returns zeros rather than erroring. `ip`/`host` are `omitempty` and so are absent when empty.                                                                                                                                                                                            |
| `POST /api/projects/{id}/backups`         | Create a backup NOW (v1.13.0, ADR-044): tar.gz of workspace + per-project home, `~/.dockerd` excluded (reproducible cache). Fine while running (crash-consistent). Stored server-side under `StateDir/backups/<user>/<projectID>/<stamp>.tar.gz` + meta json; returns `{id, projectId, projectName, createdAt, sizeBytes}`.                                                                                                                                                                                                                                                                                                                                            |
| `GET /api/projects/{id}/backups`          | This project's backups, newest first.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `POST .../backups/{bid}/restore`          | Replace the STOPPED project's workspace + home with the archive (409 while running/deleting; the `restoring` guard 409s any boot until it settles). TRANSACTIONAL: current state is quarantined by rename (root-assisted via the server's own container for root-owned entries — dockerd stubs, guest-sudo files) and renamed back if extraction fails; `~/.dockerd` is untouched.                                                                                                                                                                                                                                                                                     |
| `GET /api/settings/backups`               | Every backup the user owns — including backups of DELETED projects, which stay restorable into a new project via create-from-backup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `DELETE /api/settings/backups/{pid}/{bid}` | Remove one archive + meta. Lives under /api/settings (raw regexp-validated ids) precisely because the project record may no longer exist.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `GET /api/projects/{id}/env`              | Project-scoped env variables (v1.12.0, ADR-043), keys only: `{brokerEnabled, keys}` — values are never listed wholesale. Delivered by the broker to THIS project's new login shells only; a project variable wins over a same-named user-wide one.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `PUT /api/projects/{id}/env`              | Store/replace one variable: `{"key","value"}`. Same rules as the user-wide tier (identifier key, single-line value ≤4096 bytes). 503 when the broker is disabled.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `GET /api/projects/{id}/env/{key}`        | Reveal one value (the owner reading their own secret; audit-logged).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `DELETE /api/projects/{id}/env/{key}`     | Remove one variable (404 if absent). Deleting the project removes its whole scoped set.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Git (real client)

Every git command in the Git side panel runs INSIDE the project's guest VM —
where the user's git identity and the broker's credential helper live, so
commits carry the right author and push authenticates — as direct argv,
never a shell, so client-supplied paths can never be interpreted as shell.
The project must be running: `status`/`diff` degrade to `{state:"stopped"}`;
every mutating route 409s `"start the project to use git"` instead.

Host-side git is bootstrap-only: the server itself only ever runs `git init`
and `git rev-parse` (`internal/gitrepo`), both hardened against a
guest-controlled `.git/config` (`-c core.fsmonitor=`/`core.hooksPath=/dev/null`/
`protocol.ext.allow=never`/etc., `GIT_CONFIG_GLOBAL=/dev/null`). The former
host-side checkpoint machinery (`GET/POST /api/projects/{id}/checkpoints`,
`.../restore`) and the standalone `GET /api/projects/{id}/diff` route are
**deleted** — both ran arbitrary host-side git against a bind-mounted,
guest-writable tree, a guest→server RCE (ADR-039). Backups are now expected
to come from microVM volume snapshots of `/var/lib/styrman` (host infra —
LVM/ZFS/restic; tracked in `TODO.md`, not yet built).

| Method & path                                            | Purpose                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/projects/{id}/git/status`                       | Branch, upstream, ahead/behind, and every changed path from `git status --porcelain=v2`: `{state, repo, branch, upstream, ahead, behind, clean, files:[{path, staged, unstaged, untracked, origPath}]}`. Not a repo (or git failed) → `repo:false, clean:true` — reported cleanly, not an error. |
| `GET /api/projects/{id}/git/diff?path=&staged=&untracked=` | Diff for one path (worktree by default; `staged=true` reads the index) or the whole tree with no `path`. `untracked=true` diffs an untracked file against `/dev/null` via `git diff --no-index`.                                                                                               |
| `POST /api/projects/{id}/git/stage`                        | `{"path"}` or `{"all":true}` → `git add`.                                                                                                                                                                                                                                                        |
| `POST /api/projects/{id}/git/unstage`                      | `{"path"}` or `{"all":true}` → `git reset`.                                                                                                                                                                                                                                                      |
| `POST /api/projects/{id}/git/discard`                      | `{"path","untracked"?}` → `git checkout --` (or `git clean -fd --` for an untracked path). Destructive; confirmed in the UI.                                                                                                                                                                    |
| `POST /api/projects/{id}/git/commit`                       | `{"message"}` → commits staged changes. Author is injected via `-c user.name/user.email` read from the user's SHARED-home `.gitconfig` (per-project homes carry no identity — the broker syncs the auth token, not the identity); falls back to git's own "who are you" error if none is set. `409` with git's first output line on failure (e.g. nothing staged). |
| `POST /api/projects/{id}/git/push`                         | Pushes the current branch; sets upstream (`push -u origin <branch>`) on first push. `409` "no commits yet — make a commit first" if `HEAD` doesn't resolve; `502` with git's error line on push failure.                                                                                       |

## Terminals (durable, ADR-016)

A terminal is a persisted record whose live view is a tmux session
(`conv-<n>`) in the project microVM. Every terminal is a login shell — run
`claude`, `agy`, or anything; several at once to drive several agents.

| Method & path                       | Purpose                                                                                                                                                                                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/projects/{id}/terminals`  | Records merged with live tmux state: `{id, title, createdAt, lastOpened, live, attached, bell}`. `bell` (bool): rang the terminal bell while unattended — agent likely waiting for input; cleared by tmux when the session is viewed. Listed even when the project is stopped. |
| `POST /api/projects/{id}/terminals` | Create: `{"title"}` optional — empty gets a GENERATED friendly name (adjective-noun, collision-avoiding; rename any time). Session created lazily on WS attach. Records also carry `command` — the optional autostart (see PATCH).                                                                                                                                                                                      |
| `PATCH .../terminals/{t}`           | Update: `{"title"?, "command"?}` — PATCH semantics, absent fields untouched. `command` is the autostart (one line, ≤500 chars, `""` clears): runs when the tmux session is CREATED (first open, re-opens after pause/VM restart — never on reconnect), then drops to the login shell.                                                                                                                                                                                                                                                           |
| `POST .../terminals/{t}/pause`      | Kill the session, keep the record + transcript ("paused"; reopening starts a fresh shell).                                                                                                                                                                                     |
| `DELETE .../terminals/{t}`          | Kill session + remove record (transcript stays in History).                                                                                                                                                                                                                    |
| `DELETE .../terminals`              | Close all terminals in the project.                                                                                                                                                                                                                                            |

`GET /ws/term/{id}/{t}[?boot=1]` — the terminal WebSocket (see
terminal-protocol.md). `boot=1` marks user intent to run the project (the
first connect of an opened/resumed pane sends it); without it, a connect to
a deliberately-stopped project is answered with close 4002 instead of
booting the VM (v1.11.0).
`GET /ws/setup[?tool=git|ssh|gh|gcloud|claude|agy]` — the user's hidden
onboarding VM terminal. `tool` is optional and STRICTLY allowlisted (any
other value is ignored, falling back to the full flow) since it's
interpolated into `bash -lc 'styrman-setup <tool>'`; a targeted run gets its
own tmux session (`styrman-setup-<tool>`) so tools don't replace one
another (v1.10.0, see terminal-protocol.md).

### Notifications

| Method & path            | Purpose                                                                                                                                                                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/notifications` | `{"notifications":[{"projectId","projectName","terminalId","title"}]}` — terminals across the user's _running_ projects whose tmux window bell flag is set. One docker exec per running project per call; the UI polls this every 8 s. |

## Ports & preview

| Method & path                             | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/projects/{id}/ports`            | Listening TCP ports ≥1024 inside the microVM: `{port, process?, image?}` — process from /proc, image when the port belongs to the project's inner docker.                                                                                                                                                                                                                                                                                                                                        |
| `/p/{id}/{t}/port/{port}/...`             | Shareable link proxying to the app inside the microVM (WS pass-through). Bare form 301s to the trailing slash; a first-ever preview may 307 once while the server joins the project network. Reachable by the owner, or by a Google email the owner shared that port with (ADR-024) — `previewAllowed` in `internal/httpapi/shares.go` is the gate.                                                                                                                                              |
| `/proxy/{id}/{port}/...`                  | Terminal-independent form; same access rule.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `GET .../ports/{port}/shares`             | Emails allowed to reach this port's preview (owner only): `{"emails":[...],"url":"…"}`. `url` is the port's stable **private share link** (empty until someone is shared).                                                                                                                                                                                                                                                                                                                       |
| `PUT .../ports/{port}/shares`             | Replace the list (owner only): body `{"emails":[...]}` → normalized (lowercased, trimmed, deduped) and validated; capped at 50 entries, 254 bytes each. Returns the stored list + `url`. A non-empty list mints the port's private link (idempotent — the URL is stable across edits); emptying the list deletes it.                                                                                                                                                                             |
| `POST .../ports/{port}/links`             | Mint a public TTL link for this port (owner only): body `{"ttl":"1h"\|"24h"\|"7d"}` → `{"token","port","url","expires"}`.                                                                                                                                                                                                                                                                                                                                                                        |
| `GET /api/projects/{id}/links`            | The project's live public links (owner only): `{"links":[{token,port,url,expires}]}`.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `DELETE /api/projects/{id}/links/{token}` | Revoke a link — **204**. Owner only; 404s if the token doesn't belong to this project.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `GET /link/{token}/...`                   | **Public, unauthenticated** (ADR-025) — the token is the capability; `authGuard` exempts this route entirely. Proxies to exactly the linked port of the owning project; unknown/expired/revoked token → 404 either way (no oracle). A PRIVATE token is refused here (kind lock) — the no-login route must never honor an email-gated link. Also reachable as `https://{token}.<STYRMAN_PREVIEW_BASE>/...` via a Host-header rewrite when that env is set — each token gets its own origin.       |
| `GET /shared/{token}/...`                 | **Email-gated share route** (ADR-026). Requires an ingress-verified identity (`authGuard` lets non-styrman Google users through to this route only); `serveShared` then requires owner or membership in the port's CURRENT share list — removing an email cuts access immediately. Public tokens are refused (kind lock). Reachable as `https://{token}.<STYRMAN_PRIVATE_BASE>/...` — the OAuth-gated private wildcard — giving each share its own origin (no CSP sandbox needed, unlike `/p/`). |

Sharing and public links are both least-privilege: scoped to ONE exposed
port, never the terminal, files, dashboard, or other ports. Per-port shares
live on the project record: `project.Project.SharedPorts` is
`map[int][]string` (port → emails), JSON key `sharedPorts`; an absent/empty
entry is owner-only (`internal/project/store.go`). Public links live in a
separate token store (`internal/links`), not on the project record.

## Files (ADR-018)

Scopes: the project workspace (`/api/projects/{id}/...`) or the project's OWN
home (`/api/projects/{id}/home/...` — per-project since ADR-031; the old
`/api/home/*` family is gone). Served from the host mount — works while
stopped. Traversal and symlink escapes refused.

| Method & path                | Purpose                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET .../files?path=`        | Directory listing (dirs first, dotfiles included). Paths in and out are scope-relative.                                                                  |
| `GET .../file?path=`         | Contents (2 MiB cap, binary-flagged). The returned `path` is scope-relative, round-trippable straight into `PUT`.                                        |
| `PUT .../file?path=`         | Save/create: `{"content"}` (body cap 8 MB — must exceed the 2 MiB read cap plus JSON escaping).                                                          |
| `DELETE .../file?path=`      | Delete a file or directory (recursive). The scope root is refused; in home scope so are the managed subtrees `projects`, `.dockerd`, `.styrman`, `.ssh`. |
| `POST .../file/rename?path=` | Move/rename: `{"to"}` (scope-relative). Refuses to clobber an existing destination; same managed-subtree guard as delete (either side).                  |
| `POST .../mkdir?path=`       | Create a directory (with parents).                                                                                                                       |
| `POST .../upload?path=`      | Multipart upload into a directory (drag & drop; ≤512 MB).                                                                                                |
| `GET .../download?path=`     | Raw download.                                                                                                                                            |

## Format (server-side)

| Method & path                    | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/projects/{id}/format` | `{"path","content"}` → runs that file's real CLI formatter INSIDE the guest VM (where the toolchain lives) and returns `{"content"}` reformatted. Picked by extension: `gofmt` (go); `terraform fmt` falling back to `tofu fmt` (tf/tfvars/hcl); `rustfmt` (rs); `black` falling back to `ruff format` (py); `shfmt` (sh/bash); `prettier` (js/jsx/ts/tsx/mjs/cjs/json/css/scss/less/html/htm/md/markdown/yaml/yml/vue/graphql). Content is piped over the exec's stdin into a temp file created in the workspace root (no argv size limit, no shell interpolation — M9) so formatters discover the project's own config. `413` if content exceeds 5 MiB, `400` for an unsupported extension, `409` if the project isn't running, `422` with the formatter's own first output line if the tool is missing ("command not found") or rejects the input. The editor's own JSON Format button still formats locally/offline instead of calling this. |

## History (ADR-017)

| Method & path                    | Purpose                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/projects/{id}/history` | Terminal transcripts (`~/.styrman/logs/<id>/`): `{id, size, modified, title}` — `title` is the terminal's friendly name while its record exists (transcripts deliberately outlive records). |
| `GET .../history/search?q=` | Full-text search across the project's transcripts (agent sessions included — they're raw PTY captures), case-insensitive, ANSI-stripped: `{matches:[{transcript, line, title}]}`. Bounded: only the 50 NEWEST transcripts are scanned (`searchMaxFiles`, `internal/history`), last 4 MiB per transcript, ≤20 hits/file, ≤200 total — older transcripts in a project with more than 50 are skipped. |
| `GET .../history/{session}`      | Transcript text, ANSI-stripped, tail-capped (`?bytes=`, clamped to 4 MiB).                                                            |

There is no longer a standalone `/diff` route or any checkpoint endpoints —
see the "Git (real client)" section above (ADR-039).

## Settings, profile & admin

| Method & path                                                     | Purpose                                                                                                                                                 |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/settings`                                               | Version, identity (`user`, `username`, `isAdmin`), auth mode, per-user home, runtime/storage facts, `terminalUsername`, setup status. |
| `POST /api/settings/profile`                                      | Set `{"terminalUsername"}` — the in-guest username; applies to microVMs started afterwards. Empty resets to the identity slug.                          |
| `GET /api/settings/tools`                                         | Per-tool cards from the SETUP VM's home (`homes/<user>` — projects have their own homes since ADR-031): git/ssh/github/claude/agy — ready state, details, and claude/agy skills, subagents, commands.                      |
| `PATCH /api/settings/runtime` | **Admin only.** Operator tunables `{"dockerDiskGB","idleTimeout"}` — disk 5-500 GB (new project VMs only), idle a Go duration ≥10m or `0s` = never (applies to the reaper immediately). Persisted in `StateDir/settings.json`, overriding the env defaults across restarts. |
| `GET /api/settings/credentials` | List what the user has onboarded into the broker (ADR-032), value-free: `{"items":[{"kind":"git\|env\|file","id","name"}],"brokerEnabled":bool}`. `id` is the delete key (host / KEY / file id); `name` is the label (host / KEY / path). Never returns the secret. When the broker is disabled (host-mode dev, no self-container), this is `{"items":[],"brokerEnabled":false}` — not an error, so Settings still renders cleanly. There is no `keyring` kind — that tier was deleted outright (ADR-040); agy is a plain `file` credential (see runtime-image.md). |
| `POST /api/settings/credentials/import` | Onboard everything from one running reference project in a single pass (`harvestCredentials`, ADR-032/034 — the same helper `POST /api/setup/done` calls against the setup VM): `{"project":"<running id>"}`. Extracts gh (`gh auth token` → `GH_TOKEN` + git helper), the user's git identity from their shared-home `.gitconfig` (env creds `STYRMAN_GIT_NAME`/`STYRMAN_GIT_EMAIL`), claude (`~/.claude/.credentials.json`), gcloud ADC AND the CLI account login (`credentials.db` + active config, default config only), the first `~/.ssh/id_*`, an npm authToken, and agy's OAuth token file (`~/.gemini/antigravity-cli/antigravity-oauth-token`, file tier — ADR-038 superseded ADR-032a's keyring assumption) — each best-effort, returned as `{"report":{tool: status}}`. Since v1.5.4 this is largely a supplementary/refresh path: finishing first-run setup already seeds the broker automatically (ADR-034). |
| `POST /api/settings/credentials/git` | Git-only subset of `/import` (ADR-030): `{"project":"<running id>","host"?}` → the `gh` token as the git helper credential. |
| `POST /api/settings/credentials/token` | Store/update ANY custom env-var credential — an npm token, a database URL, an API key, etc. (ADR-032): `{"key":"NPM_TOKEN","value":"…"}`. `key` must be a shell identifier (upper-cased by the UI); re-storing a name updates it. Exported into every project's login shells. |
| `DELETE /api/settings/credentials/{kind}/{name}` | Remove one credential (ADR-032). `kind` ∈ `git\|env\|file`; `name` is the `id` from the list (host / KEY / file id). `204`, or `404` if absent. For a `file` credential, also sweeps any already-materialized copies out of every project home the user has (M22) — deleting actually revokes it, not just future delivery. |
| `GET /api/settings/credentials/{kind}/{id}/content` | Read one stored credential's value — the "click to read" viewer on the admin-only Settings surface, the exact value the broker materializes into every project. Requires `Authorized`; every read is audit-logged. `file` returns `{"content","path"}` (or `{"path","binary":true}` for non-UTF8 data); `env` returns `{"content","path"}` (the value); `git` returns `{"content","path"}` (the token, path = `"<host> (<username>)"`). `503` if the broker is disabled, `404` if the id isn't found or `kind` is unrecognized. |
| `POST /api/settings/users` · `DELETE /api/settings/users/{email}` | **Admin only** (env-provided accounts). Manage who may sign in; each user gets their own isolated space. API-only since v1.3 (operator Q4): the Settings UI card was removed and `allowedUsers` no longer appears in `GET /api/settings`. |

## Setup (first-time onboarding, per user)

Only git identity + an ssh key are REQUIRED (v1.8.0); GitHub, Google Cloud,
Claude and agy are optional, each skippable and re-runnable later — either
the full `styrman-setup`, or one tool at a time from Settings → Credentials
(`styrman-setup <tool>`, backed by `POST /api/setup/harvest`, v1.10.0).

| Method & path              | Purpose                                                                                                                                                                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/setup/status`    | Probe of the user's home: `{gitIdentity, sshKey, github, gcloud, claude, agy, done, vmRunning}`. `gitIdentity`/`sshKey` are required; the rest optional. `gcloud` checks for ADC; `agy` checks its OAuth token file (`~/.gemini/antigravity-cli/antigravity-oauth-token`) — there is no keyring fallback (ADR-038/ADR-040). |
| `POST /api/setup/start`    | Boot the user's hidden minimal VM (~1 s).                                                                                                                                                                                                    |
| `POST /api/setup/harvest`  | Seeds the credential broker from the RUNNING setup VM (same `harvestCredentials` pass `/done` uses below) WITHOUT marking setup done or destroying the VM: `{"report":{tool: status}}`. Backs "add a credential" in Settings → Credentials — the VM stays up so several tools can be signed into in one sitting (v1.10.0). |
| `POST /api/setup/done`     | Seeds the credential broker from the setup VM's shared home first — best-effort, never blocks completion (ADR-034; same `harvestCredentials` helper as `/import` above) — then writes `~/.styrman/setup-done` and destroys the VM. The terminal itself now closes automatically when `styrman-setup` exits (v1.5.4), no manual "Done" click. |
| `DELETE /api/setup`        | Destroy the VM without marking done.                                                                                                                                                                                                        |

## Server environment

| Var                                                                      | Default                          | Meaning                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `STYRMAN_ADDR`                                                           | `127.0.0.1:8080`                 | Main listener                                                                                                                                                                                                                                    |
| `STYRMAN_DEV_ADDR`                                                       | unset                            | Auth-bypassed second listener — publish on host loopback ONLY                                                                                                                                                                                    |
| `STYRMAN_AUTH`                                                           | `none`                           | `header` behind the ingress. Any other value is rejected at startup (M16) — no silent fallthrough to an unguarded mode                                                                                                                          |
| `STYRMAN_INGRESS_TOKEN`                                                  | unset (disabled)                 | Shared secret the ingress injects as `X-Styrman-Ingress`; header mode rejects requests without it when set — blocks a project VM from spoofing `X-Caddy-Email` directly against the server. **Required, non-empty, when `STYRMAN_AUTH=header`** — `config.Load` refuses to start otherwise (H2), since an empty token would let any project VM impersonate any identity |
| `STYRMAN_PREVIEW_BASE`                                                   | unset (off)                      | Public preview host base (ADR-025), e.g. `public.crew.styrman.xyz`; when set, `/link/{token}` is also reachable as `https://{token}.<base>/` and minted link URLs use that form.
