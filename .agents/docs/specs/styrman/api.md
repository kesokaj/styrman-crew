# REST API spec

Base: the styrman server. All bodies JSON, camelCase; errors
`{"error":{"message":"..."}}`. Every request carries an identity: the
Google email injected by the ingress (`X-Caddy-Email`, auth mode `header`),
or the configured default user on the loopback dev listener (mode `none`).
All project/terminal/file/history resources are scoped to that user
(ADR-019). `{id}` below is always the project **UUID** (ADR-020); friendly
names are display-only.

## Load limits (ADR-086)

- **Memory budget.** Every API request reserves its route's worst-case
  memory before it runs, from a server-wide budget of 1 GiB, at most 256 MiB
  per user. When it does not fit, the request waits up to 2 s, then gets
  **503** `{"error":{"message":"server busy, try again"}}` with
  `Retry-After: 1`. Not charged: WebSockets, preview/link/shared/proxy
  tunnels, downloads, the SPA, `/api/health`, `/api/version`. The price
  table is `routeWeight` in `internal/httpapi/budget.go`.
- **Request bodies.** Every API request that carries a body (uploads
  excepted) must finish sending it within 30 s. The file endpoints
  PUT `.../file`, POST `.../format`, POST `.../check` answer **408**
  "request body took too long"; other endpoints answer 400 as before. GET
  requests carry no body deadline.
- **Per-user slot shares.** The server-wide pools stay (file operations 8,
  transcript reads 8, history searches 4); one user may hold at most half of
  each (4, 4, 2). Over a user's share: **429** "you already have N of these
  running — try again when one finishes"; pool full: 429 with the existing
  message.

| `POST /api/projects`                      | Create: `{"name","cloneUrl","github","gitInit"}`. Every project is a git repo, no exceptions (R13, ADR-022): by default a synchronous `git init -b main` runs before the `201`; `cloneUrl` (mutually exclusive with `github`) clones that URL in-guest instead, using the user's ssh key/gh credentials, falling back to an empty repo on failure — a clone URL that embeds a PASSWORD is refused outright with **400** (`cloneURLHasSecret`, `internal/httpapi/server.go`): nothing needs one, since the credential broker already delivers the ssh key and answers git's credential helper per host (ADR-030/032), and a token in the URL would otherwise be written verbatim into the project's `.git/config`; a bare username (`ssh://git@host/o/r`, `git@host:path`) is still allowed; `github` (`"private"` or `"public"`) also creates and pushes a GitHub repo via the user's `gh` login. Both credentialed paths are built into one `provisionSpec` (`internal/httpapi/provision.go`, split out of `server.go` so the step order lives next to `provision_test.go`, which pins it) BEFORE the microVM boots, then routed to whichever of two outcomes actually happens: `bootFailed`, if the microVM never comes up — nothing that needs the guest can run, so a clone/GitHub request still reports a `provisionError` instead of failing silently, the v1.18.1 fix for exactly that silent-failure defect class — or `provisionRepo`, once it has — a method the background boot calls with the attach and exec steps injected as funcs so their ORDER is unit-testable without a Docker daemon — which joins the project's own bridge to the credential broker (`EnsureSelfAttached`, ADR-030/032) FIRST, then a `waitForBroker` poll of `$STYRMAN_CRED_BROKER/healthz` (from inside the guest, over a PLAIN shell using the broker URL already injected into the container env — a login shell would re-materialize the user's ssh key/tokens into the project home on every one of up to ten probes, just to answer "is the broker up?") confirms the broker actually answers before anything credentialed runs — attach used to run LAST, after provisioning, so every clone/create ran against an unreachable broker and failed (`Permission denied (publickey)` over ssh, `could not read Username` over https), silently degrading to an empty repo. Provisioning itself (the clone / commit / `gh repo create` commands) still runs in a LOGIN shell (`bash -lc`) so `/etc/profile.d/zz-styrman-credentials.sh` has materialized the ssh key/git identity/`GH_TOKEN` first. In host-mode dev (`STYRMAN_SELF_CONTAINER` unset) there is no bridge to attach and no broker to wait for — `EnsureSelfAttached` no-ops and `waitForBroker` returns false immediately — so provisioning there can only exercise a PUBLIC clone or an already-credentialed `gh`; it never delivers credentials itself. Guest command output that lands in a `provisionError` or a server log is redacted (`redactSecrets` strips userinfo off every scheme-bearing URL in free-form guest output, not just the one clone URL `redactURL` handles). `gitInit` is accepted for compatibility and ignored. Returns **201 immediately** with `state:"creating"`; the microVM boots in the background (terminal attach waits for readiness) — a background provisioning failure can't ride that response, so it surfaces as `provisionError` in the list/get views instead (same shape as `deleteError`). Once the boot goroutine is spawned the project reports `state:"provisioning"` (see the list row above) until the clone/init/`gh` step finishes, whichever of its return paths is taken. Name must not collide with a _current_ project; reuse after deletion is fine. |

| `PATCH /api/projects/{id}`                | Rename (friendly name only): `{"name"}`. The workspace dir (`dir`) never moves.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `GET /api/projects/{id}/network`          | Per-project network mode (ADR-067): `{"lanAccess","canEnable"}`. `lanAccess` is the record (Sandbox = false, LAN = true); `canEnable` says whether THIS caller may turn LAN on (i.e. is admin) — its own field rather than something the UI infers from another value, since more than one thing can cause an absence (BUG-019). Disabling never needs it — tightening is never refused. 404 for an unknown or another user's project (checked before any authorization signal, so another user's project looks exactly like one that doesn't exist). |
| `PUT /api/projects/{id}/network`          | Body `{"lanAccess": true\|false}` (the key is required — 400 otherwise). ENABLE is **admin only** (403); DISABLE is always allowed to the owner — tightening is never refused. 409 while the project is being deleted. Applying a mode change REBUILDS the project's container — the mode is literally the Docker bridge interface prefix (`sdb-`/`lan-`), which is immutable once created; home and workspace (bind mounts) survive, installed packages replay from the ADR-028 apt manifest. Under the project's lock for the whole decision: inspect the container; if it is RUNNING on a bridge whose prefix disagrees with the requested mode, stop it, persist the record, then start it; otherwise just persist the record (a stopped or absent project has nothing in force, so the next start alone applies it). The record is written at the one moment nothing is in force — after the old bridge is gone and before the new one exists — so no single failure can leave it claiming LESS access than the container has (ADR-067; an earlier record-first-then-rollback design caused three fail-opens in one day, BUG-028/029/031). Whether the request is a no-op is decided against the container's LIVE bridge name, not the stored record, so a record that has drifted from the bridge is repaired by simply re-issuing the same PUT. Failure replies are worded to say exactly what state the project is now in: 500 "…the mode was NOT changed" on an inspect or stop failure (nothing happened); 500 "…stopped but the setting could not be saved — start it to continue in the previous mode" on a persist failure after the stop (container down, old mode); 500 "saved, but the project could not be restarted — start it to apply" on a start failure after a successful persist. On success returns the GET body plus `rebuilt` (bool): false for a no-op or a stopped project (applies at next start), true when the container was actually rebuilt. Audit-logged. |
| `GET /api/projects/{id}/resources` | Per-project VM size (ADR-083): `{cpus, memoryGiB, diskGB, pending, limits:{maxCpus, maxMemoryGiB, minDiskGB, maxDiskGB}}`. `cpus`/`memoryGiB` are the record (0 = unlimited = the whole host); `diskGB` is the EFFECTIVE Docker disk size; `pending` is true when the project runs at another size than its record; `maxMemoryGiB` 0 = the host is too small to set memory; `minDiskGB` = max(5, current disk). For a NON-admin owner (ADR-087) `limits.maxCpus`/`limits.maxMemoryGiB` are the admin cap (`userMaxCpus`/`userMaxMemoryGiB`, see Settings), `limits.capped` is `true`, a stored value above the cap reads as the cap, and 0 stays 0. Admins (env-listed admins, every user on a `STYRMAN_AUTH=none` listener, the dev listener's default user) get the host limits and are never capped. Takes no project lock. 404 for another user's or unknown project; 503 when the host size is unknown. |
| `PUT /api/projects/{id}/resources` | Body `{cpus, memoryGiB, diskGB}`, all required integers. Owner only. 400 names the field: `cpus` not 0 or 1..`maxCpus`; `memoryGiB` not 0 or 1..`maxMemoryGiB`; `diskGB` below the current size or above 500 (grow only). A non-admin above the cap gets 400 "at most N CPUs for your projects; an admin can raise this in Settings" (or the GiB equivalent); disk is not capped. 404 unknown/another user's project; 409 while deleting; 503 host size unknown. Decided against the live container: running at another size → stop, save, start (`rebuilt:true`); running at the requested size → save only; stopped → save only (the next start applies it). Returns the GET body plus `rebuilt`. |
| `DELETE /api/projects/{id}[?wipe=true]`   | Destroy the microVM + records. Returns **202 immediately**; the destroy runs detached (a Kata teardown can take minutes) and the project reports `state:"deleting"` until its record disappears from the list. Repeated DELETEs while in flight are idempotent 202s; boot paths (start, terminal attach) refuse while a destroy is in flight so a reconnecting terminal can't resurrect the container. On failure the record stays, `deleteError` carries the message in the list/get views, and the delete can be retried. Every successful delete — wipe or not — also sweeps every materialized file-tier credential (ssh private key, gcloud ADC, agy's OAuth token, …) out of the project's home (`sweepProjectCredentials`, `internal/httpapi/credentials.go`): a non-wipe delete keeps the workspace and the rest of the home on disk, and without this sweep the user's private key would sit there orphaned — no UI path to it, no sweeper, nothing to revoke it — since the project record (the only thing gating access to it) is gone (security review 2026-09-02). `wipe` additionally deletes workspace, `~/.dockerd/<id>.img`, and transcripts — the UI requires typing "delete".                                                                                        |
| `POST /api/projects/{id}/start` · `/stop` | Boot / stop the microVM. The setup VM is not capped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

Stopped/absent project → the full stats object with `state` set and every numeric metric ZEROED (those fields have no `omitempty`, so they're present as `0` rather than omitted); an exec failure on a running project also returns zeros rather than erroring. `ip`/`host` are `omitempty` and so are absent when empty.                                                                                                                                                                                            |

## Git (real client)

Every git command in the Git side panel runs INSIDE the project's guest VM —
where the user's git identity and the broker's credential helper live, so
commits carry the right author and push authenticates — as direct argv,
never a shell, so client-supplied paths can never be interpreted as shell.
The project must be running: `status`/`diff` degrade to `{state:"stopped"}`;
every mutating route 409s `"start the project to use git"` instead.

Host-side git is bootstrap-only: the server itself only ever runs `git init`
and `git rev-parse` (`internal/gitrepo`), both hardened against a
guest-controlled `.git/config` (`-c core.fsmonitor=`/`core.hooksPath=/dev/null`/
`protocol.ext.allow=never`/etc., `GIT_CONFIG_GLOBAL=/dev/null`). The former
host-side checkpoint machinery (`GET/POST /api/projects/{id}/checkpoints`,
`.../restore`) and the standalone `GET /api/projects/{id}/diff` route are
**deleted** — both ran arbitrary host-side git against a bind-mounted,
guest-writable tree, a guest→server RCE (ADR-039). There is no backup layer
of any kind (operator decision 2026-09-01: durability is git — commit and
push); a wipe-delete is plainly irreversible. See `deploy.md` for the host
rebuild story.

| Method & path                                            | Purpose                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/projects/{id}/git/status`                       | Branch, upstream, ahead/behind, and every changed path from `git status --porcelain=v2`: `{state, repo, branch, upstream, ahead, behind, clean, files:[{path, staged, unstaged, untracked, origPath}]}`. Not a repo (or git failed) → `repo:false, clean:true` — reported cleanly, not an error. |
| `GET /api/projects/{id}/git/diff?path=&staged=&untracked=&commit=` | Diff for one path (worktree by default; `staged=true` reads the index) or the whole tree with no `path`. `untracked=true` diffs an untracked file against `/dev/null` via `git diff --no-index`. **`commit=<hash>`** (v1.22.0) returns that single commit's patch via `git show --format= --patch` — chosen over a `<hash>~1..<hash>` range because `~1` fails outright on a ROOT commit, which every freshly created project has exactly one of (R13). A merge commit yields an empty patch (git's default without `-m`/`--cc`). `400` on a malformed hash (hex, 7..40 chars), `404` on an unknown revision. NOTE the deliberate asymmetry: only the `commit=` branch checks git's exit code. The `--no-index` branch must NOT, because it exits 1 when the files DIFFER — the normal success case for an untracked file.                                                                                               |
| `POST /api/projects/{id}/git/stage`                        | `{"path"}` or `{"all":true}` → `git add`.                                                                                                                                                                                                                                                        |
| `POST /api/projects/{id}/git/unstage`                      | `{"path"}` or `{"all":true}` → `git reset`.                                                                                                                                                                                                                                                      |
| `POST /api/projects/{id}/git/discard`                      | `{"path","untracked"?}` → `git checkout --` (or `git clean -fd --` for an untracked path). Destructive; confirmed in the UI.                                                                                                                                                                    |
| `POST /api/projects/{id}/git/commit`                       | `{"message", "all"?}` → commits staged changes. **`"all": true`** (the UI's Fast commit, v1.22.0) first runs `git add -A` in the same handler under the same timeout — `add -A`, NOT `commit -a`, because `-a` skips untracked files and a control that says it commits everything must include new ones. If that staging succeeds and the commit then FAILS, the tree is left STAGED and the 409 carries git's message; nothing is auto-unwound, since a reset here could discard staging the user did by hand beforehand. Otherwise, commits staged changes. Author is injected via `-c user.name/user.email` read from the user's SHARED-home `.gitconfig` (a per-project home may lack the identity until its first login shell — the broker delivers STYRMAN_GIT_NAME/EMAIL at login, applied as global git config, v1.7.1); falls back to git's own "who are you" error if none is set. `409` with git's first output line on failure (e.g. nothing staged). |
| `POST /api/projects/{id}/git/push`                         | Pushes the current branch; sets upstream (`push -u origin <branch>`) on first push. `409` "no commits yet — make a commit first" if `HEAD` doesn't resolve; `502` with git's error line on push failure.                                                                                       |
| `GET /api/projects/{id}/git/branches`                      | Local and remote-tracking branches: `{state, repo, current, local[], remote[]}`. A READ, so a missing repo is `200` with `repo:false` and a stopped VM is `200` with `state:"stopped"` — matching `git/status` and `git/diff`, not the mutations. |
| `GET /api/projects/{id}/git/log?limit=`                    | Recent commits newest-first: `{state, repo, commits:[{hash, shortHash, subject, author, date}]}`, NUL-separated server-side so any subject parses. `limit` is clamped to 1..200 (default 50); anything else falls back to the default rather than erroring. A repo with NO commits is `200` with an empty list — an empty list is the honest answer, and the panel needs that empty state anyway. (`git/push`'s 409 for the same condition is right there because pushing nothing is a failed ACTION.) |
| `POST /api/projects/{id}/git/fetch`                        | `git fetch --all`. Deliberately NOT `--prune`: the refspec fetch obeys is `remote.<name>.fetch` from the workspace's `.git/config`, which the GUEST can write, and a pruning fetch under a crafted refspec deletes LOCAL branches (demonstrated, security review 2026-09-04). `--all` also keeps guest-chosen remote names out of argv entirely. `409` with git's line on failure. |
| `POST /api/projects/{id}/git/pull`                         | `git pull --ff-only`. `409` when there is no upstream, and when the pull is not a fast-forward — deliberately never a merge: a conflicted merge would leave a half-merged tree in a VM with no interactive git to finish it. |
| `POST /api/projects/{id}/git/checkout`                     | `{"branch", "create"?}` → switches branches, `create:true` makes one from HEAD. `400` on a branch name that fails the argv gate (leading `-`, control bytes, space, invalid UTF-8, >255 bytes); everything else about ref VALIDITY is git's call and comes back as its own `409`. The switch form runs `checkout --end-of-options <name> --`; a TRAILING `--` does not terminate options (git parses left to right), so the separator alone would protect nothing. The create form (`-b <name>`) is already immune, since `-b` consumes its argument as a value. A dirty tree that would be overwritten is a `409` carrying git's message, raised BEFORE any mutation. |
| `POST /api/projects/{id}/git/stash`                        | `{"op": "push"\|"pop"\|"list"}`, a closed set — the op selects a fixed argument slice and never reaches argv as data; anything else is `400`. **`push` uses `-u`**, so untracked files are stashed too (a "stash my work" button that leaves new files behind loses exactly the work the user thought they had put away); ignored files are not. `list` returns typed `{entries:[{ref, subject}]}` parsed server-side — the frontend never reads git porcelain. **A conflicting `pop` is a `409` with the tree ALREADY MODIFIED and the stash entry KEPT** (git's own behaviour, and the safe half of it); nothing is auto-resolved, because unwinding could destroy the very work being restored. |

## Terminals (durable, ADR-016)

A terminal is a persisted record whose live view is a tmux session
(`conv-<n>`) in the project microVM. Every terminal is a login shell — run
`claude`, `agy`, or anything; several at once to drive several agents.

| Method & path                       | Purpose                                                                                                                                                                                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/projects/{id}/terminals`  | Records merged with live tmux state: `{id, title, createdAt, lastOpened, live, attached, bell}`. `bell` (bool): rang the terminal bell while unattended — agent likely waiting for input; cleared by tmux when the session is viewed. Listed even when the project is stopped. |
| `POST /api/projects/{id}/terminals` | Create: `{"title"}` optional — empty gets a GENERATED friendly name (adjective-noun, collision-avoiding; rename any time). Session created lazily on WS attach. Records also carry `command` — the optional autostart (see PATCH).                                                                                                                                                                                      |
| `PATCH .../terminals/{t}`           | Update: `{"title"?, "command"?}` — PATCH semantics, absent fields untouched. `command` is the autostart (one line, ≤500 chars, `""` clears): runs when the tmux session is CREATED (first open, re-opens after pause/VM restart — never on reconnect), then drops to the login shell.                                                                                                                                                                                                                                                           |
| `POST .../terminals/{t}/pause`      | Kill the session, keep the record + transcript ("paused"; reopening starts a fresh shell).                                                                                                                                                                                     |
| `DELETE .../terminals/{t}`          | Kill session + remove record (transcript stays in History).                                                                                                                                                                                                                    |
| `DELETE .../terminals`              | Close all terminals in the project.                                                                                                                                                                                                                                            |

`GET /ws/term/{id}/{t}[?boot=1]` — the terminal WebSocket (see
terminal-protocol.md). `boot=1` marks user intent to run the project (the
first connect of an opened/resumed pane sends it); without it, a connect to
a deliberately-stopped project is answered with close 4002 instead of
booting the VM (v1.11.0). Beside 4000/4001/4002: close **4003** = access
revoked (TODO close-out 2026-09-10, item I). In auth mode `header` the
bridge re-checks the caller against the user allowlist every 60 s for as
long as the terminal stays open; the moment an admin removes that user, its
next check closes every one of that user's open terminals with 4003. The
client must NOT reconnect — the removed user has nothing left to reconnect
to. Auth mode `none` (local dev, e2e) never re-checks, since its identity
isn't in the allowlist store to begin with.
`GET /ws/setup[?tool=git|ssh|gh|gcloud|claude|agy]` — the user's hidden
onboarding VM terminal. `tool` is optional and STRICTLY allowlisted (any
other value is ignored, falling back to the full flow) since it's
interpolated into `bash -lc 'styrman-setup <tool>'`; a targeted run gets its
own tmux session (`styrman-setup-<tool>`) so tools don't replace one
another (v1.10.0, see terminal-protocol.md).

| Method & path            | Purpose                                                                                                                                                                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/notifications` | `{"notifications":[{"projectId","projectName","terminalId","title"}]}` — terminals across the user's _running_ projects whose tmux window bell flag is set. ## Ports & preview

Returns the stored list + `url`. A non-empty list mints the port's private link (idempotent — the URL is stable across edits); emptying the list deletes it.                                                                                                                                                                             |
| `POST .../ports/{port}/links`             | Mint a public TTL link for this port (owner only): body `{"ttl":"1h"\|"24h"\|"7d"}` → `{"token","port","url","expires"}`.                                                                                                                                                                                                                                                                                                                                                                        |
| `GET /api/projects/{id}/links`            | The project's live public links (owner only): `{"links":[{token,port,url,expires}]}`.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `DELETE /api/projects/{id}/links/{token}` | Revoke a link — **204**. Owner only; 404s if the token doesn't belong to this project.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `GET /link/{token}/...`                   | **Public, unauthenticated** (ADR-025) — the token is the capability; `authGuard` exempts this route entirely. Proxies to exactly the linked port of the owning project; unknown/expired/revoked token → 404 either way (no oracle). A PRIVATE token is refused here (kind lock) — the no-login route must never honor an email-gated link. Also reachable as `https://{token}.<STYRMAN_PREVIEW_BASE>/...` via a Host-header rewrite when that env is set — each token gets its own origin.       |
| `GET /shared/{token}/...`                 | **Email-gated share route** (ADR-026). Requires an ingress-verified identity (`authGuard` lets non-styrman Google users through to this route only); `serveShared` then requires owner or membership in the port's CURRENT share list — removing an email cuts access immediately. Public tokens are refused (kind lock). Reachable as `https://{token}.<STYRMAN_PRIVATE_BASE>/...` — the OAuth-gated private wildcard — giving each share its own origin (no CSP sandbox needed, unlike `/p/`). |

Sharing and public links are both least-privilege: scoped to ONE exposed
port, never the terminal, files, dashboard, or other ports. Per-port shares
live on the project record: `project.Project.SharedPorts` is
`map[int][]string` (port → emails), JSON key `sharedPorts`; an absent/empty
entry is owner-only (`internal/project/store.go`). Public links live in a
separate token store (`internal/links`), not on the project record.

## Browser (ADR-068)

One headless Chromium per project microVM, started on demand as the project
user by `/styrman/bin/styrman-browser`, watched by the operator through the
SPA's Browser view and driven by the agents through the `styrman-browser`
MCP server. All routes are **owner only** (`getProjectFor`, never
`previewAccess`): a shared guest gets the same 404 as for any other project
route. Server side lives in `internal/httpapi/browser.go`.

| Method & path | Purpose |
|---|---|
| `GET /api/projects/{id}/browser` | `{"running":bool,"version":"Chrome/…"}`; a project that is not running reports `{"running":false}` (an honest answer, not an error). 500 only when the launcher's reply is unreadable. |
| `POST /api/projects/{id}/browser/start` | Starts the browser (idempotent in the launcher) and returns its status. **409** when the project is not running; **503 + `Retry-After: 1`** when this server has JUST attached to the project bridge (the reply may never arrive through a netns that was reconfigured — the client retries once); **502** with the launcher's full log tail when Chromium does not come up — including when the server cannot learn its own bridge address to hand the launcher as the forwarder's peer ("no usable peer address for :9222…"): starting a browser the pane could never reach is refused rather than silently produced. |
| `POST /api/projects/{id}/browser/stop` | **204**; 409 when the project is not running. Unchanged by this batch: never sets the peer variable. |
| `GET /ws/browser/{id}` | The CDP relay the Browser pane speaks over — see `terminal-protocol.md` "Browser relay". Plain-HTTP failures (404, 502, 503) happen BEFORE the upgrade; once accepted, closes are 4002 (project stopped), 4003 (access revoked, re-checked every 60 s like a terminal), 4004 (browser unavailable, reason = the END of the launcher's message), 1011 (guest side dropped), 1009 (a guest frame over 16 MiB — "frame too large"). |

The browser's ports — 9222 (the socat-published DevTools endpoint) and 9229
(Chromium's loopback listener) — are **never** listed by `GET .../ports`,
and `/proxy/…`, `/p/…/port/…`, `GET|PUT .../ports/{port}/shares` and
`POST .../ports/{port}/links` all answer **400** `port 9222 is the project's
browser and cannot be previewed or shared` for either: a DevTools client
controls the whole browser (every tab, its cookies, `file://` inside the
guest), so it stays behind the owner-only relay. `previewPortAllowed` in
`browser.go` is the one gate; `sharePort` and `proxyPort` call it.

## Files (ADR-018)

Scopes: the project workspace (`/api/projects/{id}/...`) or the project's OWN
home (`/api/projects/{id}/home/...` — per-project since ADR-031; the old
`/api/home/*` family is gone). Served from the host mount — works while
stopped. Traversal and symlink escapes refused.

| Method & path                | Purpose                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET .../files?path=`        | Directory listing (dirs first, dotfiles included), capped at 5000 entries AND at 2 MiB of entry names plus paths, applied to raw directory order before sorting (which entries are cut is arbitrary); the response carries `truncated` beside `entries`, set when either cap cuts the listing (same for `GET .../home/files`). Paths in and out are scope-relative.                                                                  |
| `GET .../file?path=`         | Contents (2 MiB cap, binary-flagged). **429** when 8 file operations (this read, PUT `.../file`, `/format`, `/check`) are in flight server-wide — each holds up to ~12 MiB, under the server's 4g cap (ADR-085); one user may hold at most half the pool (4); over that share the answer is **429** "you already have N of these running — try again when one finishes". A GET carries no body deadline; the 30 s body deadline applies to the PUT `.../file`, POST `.../format` and POST `.../check` that share the pool, which answer **408** "request body took too long" when the body is not fully sent in time (other endpoints answer 400 as before). The response has a 30 s write deadline. The returned `path` is scope-relative, round-trippable straight into `PUT`.                                        |
| `PUT .../file?path=[&create=true]` | Save/create: `{"content"}` (body cap 8 MB — must exceed the 2 MiB read cap plus JSON escaping). Plain form overwrites unconditionally. `?create=true` is CREATE-ONLY — `files.Create` opens with `O_EXCL`, so the kernel refuses if the name is already taken: `409` `"a file with that name already exists"`. The client calls it `api.createFile`. Exists because the New-file dialog's "name already taken" check is client-side against the last-loaded directory listing — a courtesy, not a guarantee: a raw API caller, or two people creating the same name at once, could otherwise truncate an existing file through the plain write path (TOCTOU, v1.17.2 review); `O_EXCL` is the only place the kernel can actually settle the race. |
| `DELETE .../file?path=`      | Delete a file or directory (recursive). The scope root is refused; in home scope so are the managed subtrees `projects`, `.dockerd`, `.styrman`, `.ssh`; also refused, in home scope, is any path that traverses a symlink at any component except the last (acting on the link itself is still allowed, since it removes only the link). |
| `POST .../file/rename?path=` | Move/rename: `{"to"}` (scope-relative). Refuses to clobber an existing destination; same managed-subtree and symlink-traversal guard as delete (either side).                  |
| `POST .../mkdir?path=`       | Create a directory (with parents).                                                                                                                       |
| `POST .../upload?path=`      | Multipart upload into a directory (drag & drop; ≤512 MB).                                                                                                |
| `GET .../download?path=`     | Raw download.                                                                                                                                            |

## Format (server-side)

| Method & path                    | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/projects/{id}/format` | `{"path","content"}` → runs that file's real CLI formatter INSIDE the guest VM (where the toolchain lives) and returns `{"content"}` reformatted. `path` must be workspace-relative (`400` "path must be workspace-relative" for an absolute path, `400` "path escapes the workspace" for one that climbs out via `..`). Picked by extension: `gofmt` (go); `terraform fmt` falling back to `tofu fmt` (tf/tfvars/hcl); `rustfmt` (rs); `black` falling back to `ruff format` (py); `shfmt` (sh/bash); `prettier` (js/jsx/ts/tsx/mjs/cjs/json/css/scss/less/html/htm/md/markdown/yaml/yml/vue/graphql). Content is piped over the exec's stdin into a temp file created BESIDE the edited file, inside the directory `body.Path` names within the workspace (never `~/.styrman/tmp` — formatters resolve their config from the file's own directory upward, so a monorepo's `web/.prettierrc` is found as well as the root's); the directory travels to the guest as an env var (`STYRMAN_FMT_DIR`), never interpolated into the script, and the script re-confines it under `$PWD` via `realpath`. The temp file is named `.styrman-fmt-XXXXXX.<ext>`, hidden from `git status`/"Stage all" by a line the script appends to `$PWD/.git/info/exclude` on first use, and from the file explorer's listing (`.styrman-fmt-*` is filtered out); crash leftovers older than 60 min are swept from that one directory on every run. `prettier` runs with `--ignore-path /dev/null` so a project's own `.prettierignore` can't turn an explicit-path format into a silent no-op. `413` if content exceeds 5 MiB, `400` for an unsupported extension, `409` if the project isn't running, `422` with the formatter's own first output line if the tool is missing ("command not found") or rejects the input. The editor's own JSON Format button still formats locally/offline instead of calling this. |

## Check (server-side, syntax)

| Method & path                   | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/projects/{project}/check` | `{"path","content"}` → syntax-checks the file with its REAL CLI checker INSIDE the project's microVM (same exec-in-guest shape as `/format` — content piped over stdin into a temp file, always cleaned up). UNLIKE `/format`, the temp file stays OUTSIDE the workspace, in the guest's own `~/.styrman/tmp`: a checker takes the file by path and needs no config-discovery context, and check runs on every keystroke-pause debounce tick — a workspace-root temp file used to flicker in and out of `git status` and the file explorer on every tick (2026-09-01 review), which is exactly the symptom `/format`'s beside-the-file placement would reintroduce here for no benefit, since no checker resolves config relative to the file. Picked by extension/basename: `gofmt -e` (go), `shellcheck` falling back to `bash -n` (sh/bash), `python3 -m py_compile` (py), `node --check` (js/jsx/mjs/cjs), `jq empty` (json), `yq e .` (yaml/yml), `tofu fmt -check` (tf/tfvars/hcl), `hadolint` (Dockerfile/Containerfile, matched by basename). Response: `{"supported":bool,"tool"?,"unavailable"?,"diagnostics":[{"line","col"?,"severity","message"}]}`. `supported:false` (still HTTP 200, not an error) for a file type with no checker — the editor calls this automatically for whatever is open, so "nothing to check" is a normal answer, not a client error. `unavailable:true` when the checker binary itself is missing from the image. `409` if the project isn't running, `413` if content exceeds the same size cap as `/format`. |

## Credential broker (separate listener)

A second HTTP listener (`STYRMAN_BROKER_ADDR`, see Server environment below),
reachable only from a project's own bridge (ADR-030) — never published to the
host. The caller is identified by source IP → (user, project), re-resolved on
every request (no memoized mapping); it serves secrets ONLY, no auth token
required beyond network position. Three tiers (ADR-032), all returning the
CURRENT store contents so a Settings-side update propagates on the project's
next login shell:

| Method & path | Purpose |
| --- | --- |
| `GET /git?host=` | Git-credential-helper shape for the calling project: `{"username","token"}`. `host` defaults to `github.com`. `404` if nothing is onboarded for that host. |
| `GET /env` | `{KEY: value, ...}` of the user's env-tier credentials (`GH_TOKEN`, `NPM_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, …), merged with this project's own scoped env (ADR-043) — a same-named project variable wins. Always `200`, `{}` when nothing is onboarded. |
| `GET /files` | `[{"path","mode","data"}]` (base64) of the user's file-tier credentials (gcloud ADC, ssh key, agy's OAuth token file). Always `200`, `[]` when nothing is onboarded. |
| `GET /healthz` | Unauthenticated liveness probe — `"ok"`. Undocumented elsewhere; not a credential route. |

Prose overview (tiers, materialization, the file-vs-env-vs-git split): `guide.md` → Credential broker.
