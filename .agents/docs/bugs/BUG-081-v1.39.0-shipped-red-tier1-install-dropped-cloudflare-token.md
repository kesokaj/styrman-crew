# BUG-081: v1.39.0 shipped with two red Tier 1 tests; one a real defect, `styrman-ctl install` dropped a Cloudflare token the answers file carried

## Symptom
At HEAD `1fe28a0`, `go test ./internal/config/`:
- `--- FAIL: TestStyrmanCtlInstallPlan` `styrman_ctl_test.go:425: expected 6 planned .env writes, got 5`
- `--- FAIL: TestGCPLibEnvGetMatchesStyrmanCtl` `deploy/gcp/lib.sh: private_file lost its owner read; the two copies have drifted` (also "file mode read", "parent mode read").
Both pass at `v1.38.0`. Found 2026-10-02 by this work's Tier 1 run.

## Repro
`go test ./internal/config/ -run 'TestGCPLibEnvGetMatchesStyrmanCtl|TestStyrmanCtlInstallPlan'` in a worktree of `1fe28a0`.

## Root cause
Commit `167f605` (in v1.39.0) took `CLOUDFLARE_API_TOKEN` out of `MUST_FILL` to make it optional. `cmd_install` fills `.env` by iterating `MUST_FILL` only, so `styrman-ctl install --env-file F` silently dropped a token F carried and the host issued certificates over HTTP-01, while `deploy/gcp/install.sh`'s header documents the token as an optional key of that file.
The same commit made `deploy/gcp/lib.sh`'s three `stat` reads portable (GNU `stat -c`, then BSD `stat -f`) and left the drift test asserting the GNU text in both files.
v1.39.0 was tagged from macOS, where `deploy/verify-commit.sh` cannot run (2026-09-22 handoff: "`deploy/verify-commit.sh` fails on macOS (no Docker/GNU tools) - pre-existing"; the release's change entry: "pre-tag test suite runs not measured").

## Fix
Ships in the release after v1.39.0.
- `deploy/styrman-ctl`: `OPTIONAL_FILL="CLOUDFLARE_API_TOKEN"`; after the must-fill loop, an optional key the `--env-file` gives is validated and written, never prompted for, and an invalid value stops the install.
- `internal/config/gcp_scripts_test.go`: the three `stat` needles are per file (GNU-only in `styrman-ctl`, GNU then BSD in `lib.sh`), same fail-closed default asserted in both.
- `deploy/gcp/install.sh`: the two comments that said "six must-fill keys".
- Tests: `TestStyrmanCtlInstallPlan` (red at `1fe28a0`, green with the fix: six planned writes for an answers file that carries the token); new `TestStyrmanCtlInstallOptionalKeyAbsent` (five writes, the token not named) and `TestStyrmanCtlInstallOptionalKeyInvalidStops` (fails with the validation line removed, mutation run 2026-10-02); `TestGCPLibEnvGetMatchesStyrmanCtl` green.

## Prevention
A release tag is cut only from a machine where `deploy/verify-commit.sh` ran green on that commit; "the gate cannot run here" is a reason to tag from another machine, never to tag unmeasured. When a key leaves a required list, grep every loop that iterates that list, because what the list fed must still be fed.
